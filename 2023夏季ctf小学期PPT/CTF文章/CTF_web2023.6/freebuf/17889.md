运行时类型识别
2021-11-05 20:40:29

多态里面的东西比较多，学了一下RTTI机制，大概的讲解一下

类型识别

我们定义变量的时候都是这样定义的TypeName Var，按理来说我们应该已经知道了它的类型，同样编译器也知道它的类型。但是在多态里面这不一定，我愿称之为“薛定谔的数据类型”。来看一个代码

#include <iostream>
using namespace std;

class Student
{
public:
    virtual void func();
};
void Student::func()
{
    cout << "I am a Student" << endl;
}

class Boy:public Student
{
public:
    void func();
};
void Boy::func()
{
    cout << "I am a Boy" << endl;
}

class Girl:public Student
{
public:
    void func();
};
void Girl::func()
{
    cout << "I am a Girl" << endl;
}

int main()
{
    Student *stu;
    int sex;
    cout << "Please input your sex" << endl;
    cout << "1.Boy" << endl;
    cout << "2.Girl" << endl;
    cin >> sex;
    if(sex == 1)
    {
        stu = new Boy();
    }
    else if(sex == 2)
    {
        stu = new Girl();
    }
    else
    {
        cout << "Error" << endl;
    }
    stu->func();


    return 0;
}



我们创建了一个stu的指针，然后根据不同的输入给它对象。那么在这个时候编译器如何提前进行判断呢？答案是没有办法进行判断，只能在运行的过程中根据情况来判断它的类型。

在这里提前介绍一个类type_info，这个类型需要引入库<typeinfo>。这个类中保存了类型的信息。由于C++只对该类进行了一个大概的定义，所以具体的成员还是要看不同的编译器。并且该类的构造函数权限为private，因此程序员无法直接创建它的对象。但是它的对象可以由编译器创建

由此我们引出一个运算符叫做typeid()，该运算符里可以添加变量、表达式、基本类型和自定义类型(class和struct)，返回值为const type_info。

RTTI机制的实现

上面的例子证明了在某些情况下编译器无法提前知道一些变量的数据类型，那么就只有在运行时进行识别。

在用到多态的机制的时候(也就是存在虚函数的时候)，编译器会在紧邻虚函数表表头的低地址的位置放上一个指针，该指针指向了一个type_info类的对象，typeinfo对象中有一些成员，以上面的例子来画个图

也就是说不管我们的stu指向哪里，都可以通过访问typeinfo对象的成员来让编译器知道。其实也是一个公式的事情：假设指针为p，* (*(p->vptr-1)+x)。来解释一下，指向对象的指针为p，通过p->vptr获取到虚函数表的地址，减去1就是指针ptr的地址，这个地址指向typeinfo对象头部。加x是访问成员距离对象头部的偏移。再加一个 * 就相当于访问这个成员。
