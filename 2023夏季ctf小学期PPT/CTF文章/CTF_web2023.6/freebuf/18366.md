前言

本文产生的起因是在客户现场巡检时发现的几个特殊安全事件，从数据包为出发点慢慢挖掘出一个近年来行动猖獗的僵尸网络木马——Mozi，于是乎开展了对该Mozi样本的追溯和研究。本文主要记录了对该样静态逆向分析过程中的收获，若有描述不当或错误的地方，欢迎加以指正。

图文中涉及敏感信息皆已进行脱敏处理。

关于Mozi

Mozi是一个使用类BitTorrent网络感染网络设备的P2P僵尸网络。Mozi利用弱Telnet口令和近10个未修复的网络设备漏洞来执行DDoS攻击、数据窃取、命令和payload执行。

9.扩大传播目标

打开数据包就明晃晃地发现UserAgent字段内容为“Hello,World”，这个安全事件瞬间引起我的兴趣，从流量数据能看到一些下载Mozi.m、Mozi.a文件的命令，那应该就是最近几年在国内臭名昭著的Mozi僵尸网络无误了。攻击提供的下载地址还有效，趁热对样本分析一波。

静态分析

1.String

先用Strings查看恶意程序，打算筛选出有用的敏感字符串信息，但是除了知道是elf格式文件外，几乎没有可识别的明文内容，从里面发现这么两行内容：

$Info: This file is packed with the UPX executable packer http://upx.sf.net $

$Id: UPX 3.91 Copyright (C) 1996-2013 the UPX Team. All Rights Reserved. $

确定大概率是加了UPX壳，版本为3.91。除此之外没有获得其他有效的信息。

图5 发现UPX加壳特征

2.UPX脱壳

从http://upx.sourceforge.net下载对应版本的脱壳器进行脱壳。

但是脱壳失败了，报错信息显示p_info corrupted(p_info已损坏)，估计制作者对加壳后的文件进行了加工。

图6 首次自动脱壳失败

查看了一下UPX源码找到对该提示信息的介绍为：“p_info” is a 12-byte section in the UPX packed program header. Below, it can be observed filled with zeros。

于是定位文件中p_info的位置，可以看出作者将该结构体用0填充后，解压程序检测到异常，而导致解压缩失败。

图7 p_info被0填充导致自动脱壳失败

通过查询其他研究人员的文章发现，“p_info”是解包文件的大小。“p_info”和“p_filesize”包含相同的值。“p_filesize”位于文件末尾，如下图所示蓝色部分：十六进制：C03D0400

图8 p_filesize部分

再将 “p_info”的5-12字节的部分用 “p_filesize”进行替换:

图9 0字节替换

再次进行脱壳，成功！

图10 脱壳成功

脱完壳后文件的大小从121KB变大到272KB

图11 脱壳前文件大小

图12 脱壳后文件大小

IDA分析

1.检查被感染的设备上是否存在Watchdog，估计是为了防止系统重启。

图16 检测watchdog

2.攻击的设备类型，涉及GPON光纤设备、NetGear路由设备、华为、D-Link路由设备、使用Realtek SDK的设备、Vacron监控摄像机、斐讯路由器、 USR-G806 4G工业无线路由器等:

图17 涉及的设备类型

3.样本中发现口令爆破字典（用户名字典和口令字典），应该是用来对Telnet进行暴力破解攻击，以扩大感染和传播范围部分弱口令密码。部分字典数据如下图。

图18 部分爆破字典内容

其中样本的配置部分使用XOR进行了加密，密钥为：4E 66 5A 8F 80 C8 AC 23 8D AC 47 06 D5 4F 6F 7E，经过解密后可以获得主要的配置内容（默认配置）：

[ss]bot[/ss][hp]88888888[/hp][count]http://ia.51.la/go1？id = 19894027＆pu =http％3a％2f％2fbaidu.com/[idp][/count]

各个标签的解释：

[ss]标签：指定节点标记，只有相同节点的Mozi节点会使用该配置文件

[hp]设置Mozi节点hash的前缀

[count]在该url登记Mozi节点

小结

经过分析后，已立即通知客户采取相应的应对措施，所幸是对应资产没有成功下载到Mozi的相关恶意程序，没有对资产造成进一步的损害。

对于Mozi的动态分析部分还得花上一些时间去进行，随着网络环境的快速发展，网络攻击层出不穷，千变万化，经常感慨要做好安全防护和对抗任重而道远。

针对Mozi的几点防护建议

1、对网络设备应定期进行维护，防止攻击者利用漏洞入侵；

2、关闭不必要的端口，尽量减少端口在公网的开放，减小风险暴露面；

3、避免使用弱口令，降低攻击者口令爆破的成功率；

4、根据Payload阻断存在特征的通信。
