常见中间件漏洞总结
2022-04-21 22:56:30

IIS

6.0解析漏洞

 1. 文件解析漏洞
    1.asp后加;.jpg此种格式的文件名，当成asp来解析
 2. 目录解析漏洞
    会将扩展名为.asp 的文件夹下的文件解析为asp
 3. PUT任意文件写入
    IIS Server在web服务扩展中开启了WebDAV之后，支持多种请求，配合写入权限，可造成任意文件写入

防护

 1. 针对文件解析，文件上传后重命名（时间戳+随机数+.jpg等）。
 2. 针对目录解析，不允许新建目录。
 3. 针对PUT任意文件写入，关闭WebDAV和写权限。


7.0解析漏洞

在Fast-CGI运行模式下，在任意文件，加/.php，会将test.jpg解析为php文件

防护

关闭fast-cgi模式，并且将php.ini中cgi.fix_pathinfo设置为零并重启。

Apache

文件名解析漏洞（CVE-2017-15715）

Apache默认一个文件可以有多个以点分割的后缀，当最右边的后缀无法识别，则继续向左识别，直到识别到合法后缀才进行解析。

HTTPD换行解析漏洞（CVE-2017-15715）

1.php\x0a = 1.php上传后缀末尾包含换行符的文件，可以绕过FilesMatch。该漏洞是因为用户配置不当产生的漏洞。

修复

1.升级到最新版本
2.或将上传的文件重命名为时间戳+随机数+.jpg等的格式并禁用上传文件目录执行脚本权限

SSL远程命令执行漏洞

当目标服务器开起了SSL和CGI支持，我们就可以上传.shtml后缀名文件，利用<!--#exec cmd="id" -->语法执行命令。ssl可以在html中加入特定的指令

Nginx

文件解析漏洞

加/xxx.php后，可以将文件作为php解析

目录遍历

修改C:\phpStudy\nginx\conf\nginx.conf

CRLF注入

Nginx会将$uri进行解码，导致传入%0a%0d回车加换行 即可引入换行符，造成CRLF注入漏洞。


Tomcat

任意文件写入

漏洞的产生是由于配置不当（非默认配置），将配置文件（conf/web.xml）中的readonly设置为了false，导致可以使用PUT方法上传任意文件，但限制了jsp后缀。


远程代码执行

漏洞相关的代码在tomcat\java\org\apache\catalina\servlets\CGIServlet.java中，CGIServlet提供了一个cgi的调用接口，在启用enableCmdLineArguments参数时，会根据RFC 3875来从Url参数中生成命令行参数，并把参数传递至Java的 Runtime 执行。 这个漏洞是因为Runtime.getRuntime().exec在Windows中和Linux中底层实现不同导致的。

Jboss

反序列化漏洞（jb5.x6.x）

访问http://ip:port/invoker/readonly页面，回显500表示存在。漏洞出现在 Jboss 的 HttpInvoker 组件中的 ReadOnlyAccessFilter 过滤器中ReadOnlyAccessFilter.class文件中,其中doFilter函数，调用readobject方法对数据流进行反序列化操作。


jboss jmxinvokerservlet反序列化漏洞


访问页面http://192.168.112.148:8080/invoker/JMXInvokerServlet该漏洞的产生是由于JBoss在/invoker/JMXInvokerServlet请求中读取了用户传入的对象，利用Apache Commons Collections中的Gadget执行任意代码 processRequest中直接把我们POST的数据给readObject

jboss MQ JMS反序列化漏洞


jbossMQ实现过程的JMS over HTTP Invocation Layer的HTTPServerILServlet.java⽂件存在反序列化漏洞，远程攻击者可借助特制的序列化数据利⽤该漏洞执⾏任意代码。



JMX Console默认存在未授权访问


直接点击JBoss主页中的JMX Console链接进入JMX Console页面


Weblogic

它的反序列化分为两种，一种基于XML一种基于T3协议

XMLDecoder 反序列化漏洞（CVE-2017-10271 & CVE-2017-3506）


weblogic的wls security组件对外提供webservice服务，使用了xmlDecoder来解析用户传入的xml数据在解析的过程中出现反序列化漏洞。导致执行任意命令。只要是在wls-wsat包中的Uri皆受到影响。构造写入文件数据包发送，其中Content-Type需要等于text/xml，否则可能导致XMLDecoder不解析。readObject方法中WorkContextXmlInputAdapter类没有过滤，直接调用的xmldecoder方法



wls-wsat反序列化远程代码执行漏洞


绕过了CVE-2017-10271的补丁，其中CVE-2017-3506的补丁是过滤了object，CVE-2017-10271的补丁是过滤了new，method标签，且void后面只能跟index，array后面可以跟class，但是必须要是byte类型的。所以class标签没有被过滤导致了这个漏洞。



WLS Core Components 反序列化命令执行漏洞（CVE-2018-2628）


通过T3协议触发，可导致未授权的用户在远程服务器执行任意命令。coherence.jar存在着用于gadget构造的类（反序列化构造类），t3协议是特有的协议，传输rmi服务过程中产生的数据流。InboundMsgAbbrev#readObject方法处理T3协议传递过来的反序列化数据，ObjectInputStream#readObject方法处理反序列化数据



SSRF漏洞


可以发送任意http请求，攻击内网中的redis、fastcgi等组件Binding.send方法(存在于server/lib/webservices.jar中)
