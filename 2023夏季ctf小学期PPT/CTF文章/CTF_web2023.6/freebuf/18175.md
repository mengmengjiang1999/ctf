C++中对象的内存模型
2021-11-02 18:07:07

最近在看C++，各种各样的内存模型是在是有些繁琐，所以专门写一篇博客来总结一下C++面向对象相关的内存模型

我们已经知道在一个类中成员方法是共享的，我们只需要关注成员变量就可以；另外不考虑静态成员的情况

普通类的对象内存模型

首先看一下最普通的类，我们先写一段代码

#include <iostream>
using namespace std;

class A
{
public:
    int m_a;
    int m_b;
    int m_c;
};


int main()
{
    A a;
    cout << &a.m_a << "\n" << &a.m_b << "\n" << &a.m_c << endl;
    return 0;

}


然后来看一下结果

也就是说根据我们定义的顺序，成员变量的地址依次增加

封闭类的对象模型

当我们定义的一个类，需要使用到了别的类的对象，此时的成员变量又是如何排布的？还是先看一下代码

#include <iostream>
using namespace std;

class Body
{
public:
    Body(int high,int weight);

    int m_high;
    int m_weight;
};

Body::Body(int high,int weight):m_high(high),m_weight(weight){}

class People
{
public:
    People(int age,int high,int weight);

    int m_age;
    Body m_body;
};
People::People(int age,int high,int weight):m_age(age),m_body(high,weight){}

main()
{
    People p(12,160,180);
    cout << &p.m_age << "\n" << &p.m_body.m_high << "\n" << &p.m_body.m_weight << endl;
}


然后看一下最后运行的结果

和预料的一样，结构大概是这个样子

但是如果多想一下，是否与在类中定义的顺序有关呢？那么我们进行一下更改，将m_age和m_body的顺序反一下

Body m_body;
int m_age;


然后我们再来看结果

发现确实发生了变化，说明和定义的顺序有关

继承相关的内存模型

单继承

对于单继承来说，首先看一下只有一次继承的情况

#include <iostream>
using namespace std;

class GrandF
{
public:
    GrandF(int a,int b);

    int m_a;
    int m_b;
};
GrandF::GrandF(int a,int b):m_a(a),m_b(b){}


class Father:public GrandF
{
public:
    Father(int a,int b,int c);

    int m_c;
};

Father::Father(int a,int b,int c):GrandF(a,b),m_c(c){};

int main()
{
    Father f(10,20,30);
    cout << &f.m_a << "\n" << &f.m_b << "\n" << &f.m_c;
}


它们的内存情况大概是这样的
父类的成员在低地址，子类的成员在高地址，并且我们知道初始化参数的时候参数列表的顺序和内存位置没有关系(这个其实属于前置知识)

多继承

我们再来看一下多继承的情况

#include <iostream>
using namespace std;

class GrandF
{
public:
    GrandF(int a,int b);
    int m_a;
    int m_b;
};
GrandF::GrandF(int a,int b):m_a(a),m_b(b){}


class GrandM
{
public:
    GrandM(int c,int d);
    int m_c;
    int m_d;
};
GrandM::GrandM(int c,int d):m_c(c),m_d(d){}



class Father:public GrandF,public GrandM
{
public:

    Father(int a,int b,int c,int d,int e);
    int m_e;
};

Father::Father(int a,int b,int c,int d,int e):GrandF(a,b),GrandM(c,d),m_e(e){}



int main()
{
    Father f(1,2,3,4,5);
    cout << &f.m_a << "\n" << &f.m_b << "\n" << &f.m_c << "\n" << &f.m_d << "\n" << &f.m_e << endl;
    return 0;
}


最后我们看一下运行的结果

内存结构是这样的

那么如果改变一下继承的顺序呢？

class Father:public GrandM,public GrandF


我们再来看一下

确实发生了改变，并且我们会发现子类永远在最高地址

连续继承

连续继承就是Father继承GrandF，son继承Father，我们来看一下

#include <iostream>
using namespace std;

class GrandF
{

public:
    GrandF(int a,int b);
    int m_a;
    int m_b;
};

GrandF::GrandF(int a,int b):m_a(a),m_b(b){}


class Father:public GrandF
{
public:
    Father(int a,int b,int c);
    int m_c;
};
Father::Father(int a,int b,int c):GrandF(a,b),m_c(c){}


class Son:public Father
{
public:
    Son(int a,int b,int c,int d);
    int m_d;
};
Son::Son(int a,int b,int c,int d):Father(a,b,c),m_d(d){}

int main()
{
    Son s(1,2,3,4);
    cout << &s.m_a << "\n" << &s.m_b << "\n" << &s.m_c << "\n" << &s.m_d << endl;
}


我们再来看一下运行的结果

转换成内存模型是这样

总结：对象的内存模型根据定义的顺序，先定义的成员变量在低地址，后定义的成员变量在高地址。有继承的情况下，子类的成员变量一定在父类成员变量的高地址处，在多继承的情况下，根据继承的顺序，前面的父类在低地址，后面的父类在高地址，子类一定在最高地址

注：以上代码写的全都不规范，正常写代码不能这么写，我这样写是为了让读者可以更好的理解

虚继承

从虚继承开始，内存情况有些复杂。C++中只规定了一个大的框架，而具体的实现则根据不同的编译器略有不同，之前了解了一下Cfront和VC的，我们直接讲解VC的，毕竟用的人比较多

首先先粗略的讲解一下虚继承。在多继承中有这么一种情况

这种情况被称为菱形继承，由于B和C都继承了A的成员，当D去继承B和C的成员的时候就会出现命名冲突。当然我们可以通过定义命名空间的方法来对这种错误进行规避，还有一种方法就是虚继承。虚基类相当于做了一个承诺：子类都可以共享虚基类，所以当D继承B和C的时候其实只继承了一份A的成员

然后我们来看一下代码

#include <iostream>
using namespace std;

class A
{
public:
    A(int a);
    int m_a;
};
A::A(int a):m_a(a){}

class B:virtual public A
{
public:
    B(int a,int b);
    int m_b;
};
B::B(int a,int b):A(a),m_b(b){}


class C:virtual public A
{
public:
    C(int a,int c);
    int m_c;
};
C::C(int a,int c):A(a),m_c(c){}


class D:public B,public C
{
public:
    D(int a,int b,int c,int d);
    int m_d;
};
D::D(int a,int b,int c,int d):A(a),B(a,b),C(a,c),m_d(d){}



int main()
{
    D d(1,2,3,4);
    cout << &d.m_a << "\n" << &d.m_b << "\n" << &d.m_c << "\n" << &d.m_d << endl;
}


然后我们看一下输出结果

发现了吗？本来应该在最低地址的成员m_a到了最高地址，

我们先来粗略的画一下内存模型

连续的虚继承

首先是代码

#include <iostream>
using namespace std;

class A
{
public:
    A(int a,int b);
    int m_a;
    int m_b;
};
A::A(int a,int b):m_a(a),m_b(b){}

class B:virtual public A
{
public:
    B(int a,int b,int c);
    int m_c;
};
B::B(int a,int b,int c):A(a,b),m_c(c){}


class C:virtual public B
{
public:
    C(int a,int b,int c,int d);
    int m_d;
};
C::C(int a,int b,int c,int d):A(a,b),B(a,b,c),m_d(d){}

class D:public C
{
public :
    D(int a,int b,int c,int d,int e);
    int m_e;
};
D::D(int a,int b,int c,int d,int e):A(a,b),B(a,b,c),C(a,b,c,d),m_e(e){}

int main()
{
    D d(1,2,3,4,5);
    cout << &d.m_a << "\n" << &d.m_b << "\n" << &d.m_c << "\n" << &d.m_d << "\n" << &d.m_e << endl;
}



我们再来看一下运行的结果

内存结构大概是这样

由于D直接继承了C，所以C的成员变量在地址的最低处，而B和A都是虚基类，所以应该在下面，同样作为虚基类由于A要比B的层级高，地址也高于B。

举了这么多的例子，我们把上面的图一个颜色来看一下

图了颜色的部分就是虚基类的成员，我们会发现这些成员会随着继承的层数的改变，它们距离对象开头的偏移量也会发生改变，而普通的成员的偏移量不会随着继承的层数的改变而改变。我们称黄色的部分为共享部分，而白色的部分为固定部分。由于共享部分的偏移量会随着继承的层数进行改变，于是我们也需要想办法对它们进行一个定位。

虚基类表

前面说过，对于定位共享区域不同的编译器有不同的办法。而VC想的办法就是搞出了一个虚函数表。我们来画图看一下虚函数表。

首先假设有两个类A和B，A是B的虚基类。A有两个成员a和b，B有两个成员c和d
首先会往虚基类的直接派生类的成员的相邻低地址放一个指针，该指针指向虚函数表，虚函数表中记录了虚基类的偏移量

如果存在连续的虚继承也是同理，现在有三个类：A、B、C。A类的成员有a1、a2，B类的成员有b1、b2，C类的成员有C1、C2。现在A是B的虚基类，B是C的虚基类，我们再来画一下内存结构图

这个图比较复杂，需要认真的看一下。

最后总结：这些就是大部分情况下的内存模型。首先对于一个类来说，先定义的成员变量放在低地址，后定义的成员变量放在高地址。当出现继承的时候，父类的成员变量存放的地址一定比子类成员要低。在虚继承的情况下，虚基类的成员的地址一定比派生类要高。并且我们还说了，虚继承的派生类会在最低地址的成员变量的相邻低地址处放置一个指针指向虚基类表，该表存放了派生类到虚基类的偏移量。
