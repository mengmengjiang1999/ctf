针对ESXi服务器勒索来袭，新华三教你如何防范处置
2023-03-31 17:42:46

事件概述

近期一款针对VMware ESXi服务器的新型勒索软件”ESXiArgs”正在全球范围内实施攻击活动。攻击者利用2021年的远程代码执行漏洞CVE-2021-21974向VMware ESXi服务器进行攻击，从而投放勒索软件。目前美国网络安全和基础设施安全局（CISA）提供了恢复脚本，受影响用户可以尝试借此恢复数据。

样本分析

勒索程序分析

encrypt程序运行时，需要指定两个参数，RSA公钥、加密文件路径。有三个可选参数，加密数据块间隔、加密数据块大小、加密文件大小

  * 加密流程

加密文件使用了RSA+sosemanuk。sosemanuk为流密码算法，用来加密文件，随机生成32字节的数据作为sosemanuk算法的密钥。RSA为非对称算法，加密sosemanuk算法的密钥。

encrypt_simple调用了sosemanuk_encrypt分块加密，按脚本设定每次最多加密1MB，然后跳过部分内容。

sosemanuk算法的密钥被加密后放在文件结尾

由于encrypt程序使用了sosemanuk算法，而该算法目前只有Babuk勒索程序使用，所以ESX

iArgs可能由泄露的Babuk源代码修改而来。

  * 设计缺陷

encrypt处理参数时，数字的转换使用了atoi函数，导致file_size最大为0xFFFFFFFF(约4GB)，即文件最多只有前4GB内容被加密

勒索脚本分析

  * 加密文件类型

列举文件并加密

会加密的文件有：

*.vmdk

*.vmx

*.vmxf

*.vmsd

*.vmsn

*.vswp

*.vmss

*.nvram

*.vmem

  * 加密模式

脚本执行勒索程序时，参数enc_step的取值与文件大小有关。当文件大于128MB时，部分加密，文件越大，跳过的部分越大；否则全部加密

参数enc_size固定为1MB，参数file_size为所加密文件的实际大小。

  * 设置勒索提示信息

/usr/lib/vmware下的所有原index.html被备份为index1.html，index.html被勒索相关文件(HTML格式的勒索信息)替代

/etc/motd被备份为motd1，motd被勒索相关文件(文本形式的勒索信息)替代，登录时会显示相关信息

  * 清楚痕迹

使用/sbin/hostd-probe.bak覆盖/sbin/hostd-probe以恢复被修改的hostd-probe

清除root的cron计划任务(删除最后1行，删除前8行)

删除/bin/hostd-probe.sh的第1行(被删的行是该脚本启动时执行vmtools.py后门)

删除/store/packages/vmtools.py(后门文件)

删除/etc/vmware/rhttpproxy/endpoints.conf的最后1行

清空/etc/rc.local.d/local.sh(将执行vmtools.py后门的命令写入/bin/hostd-probe.sh)

删除/tmp目录下的encrypt、nohup.out、index.html、motd、public.pem、archieve.zip文件

执行/bin/auto-backup.sh，更新保存在 /bootbank/state.tgz 文件中的配置，然后删除自身




启动ssh服务




解决方案

防范建议

  * 升级补丁

排查当前ESXi版本是否是受影响版本

影响范围：

ESXi70U1c-17325551之前的ESXi 7.x版本
ESXi670-202102401-SG之前的ESXi 6.7.x版本
ESXi650-202102101-SG之前的ESXi 6.5.x版本

以上为官方公告受影响的漏洞版本情况，但据网络空间测绘平台的数据统计，6.0和5.5版本也遭受了勒索软件攻击。

漏洞排查：

方式1：登陆EXSi后台，点击帮助-关于，即可获取版本号

方式2：登陆EXSi终端，执行“vmware -vl”命令获取版本号





修复方式：

升级官方补丁，对存在漏洞的VMware ESXi进行升级。

漏洞通告：https://www.vmware.com/security/advisories/VMSA-2021-0002.html

补丁下载：https://customerconnect.vmware.com/patch

补丁信息及升级方式：https://docs.vmware.com/en/VMware-vSphere/6.7/rn/esxi670-202102001.html

  * 禁用OpenSLP服务

1. 登录ESXi，启用安全Shell

2.使用ESXi的账号密码登陆ESXi命令行

3. 查看SLP服务状态

/etc/init.d/slpd status，如果命令执行结果显示slpd is running，表示该服务正常运行中




4. 停止SLP服务

/etc/init.d/slpd stop




5. 禁止SLP服务

esxcli network firewall ruleset set -r CIMSLP -e 0

执行以下命令关闭自启动

chkconfig slpd off

6. 查看SLP是否自启动

chkconfig --list | grep slpd，输出“slpd on”为开启，输出“slpd off”则代表未开启。

及时备份重要数据

非必要不将ESXi的端口映射到公网

新华三入侵防御特征库支持该漏洞的检测，请及时升级特征库，并保持规则43383处于开启状态

处置措施

文件清除

检查是否存在后门文件/store/packages/vmtools.py，若有，建议立即删除

数据恢复

如果服务器已被加密，可尝试如下步骤恢复数据：

恢复原index.html：将/usr/lib/vmware下的所有index1.html重命名为index.html

mv /usr/lib/vmware/hostd/docroot/index1.html /usr/lib/vmware/hostd/docroot/index.html

mv /usr/lib/vmware/hostd/docroot/ui/index1.html /usr/lib/vmware/hostd/docroot/ui/index.html

恢复原登录显示信息：将/etc下的motd1重命名为motd

mv /etc/motd1 /etc/motd


恢复虚拟机磁盘文件方法：

ESXiArgs-Recover脚本

运行状态下的虚拟机会给原始配置文件“*.vmx”自动生成一个备份文件“*.vmx~”，由于该文件后缀“.vmx~”不在该勒索软件的加密文件后缀范围内，因此对于运行状态下的虚拟机被加密后可用“*.vmx~”文件恢复虚拟机配置。同时由于加密程序存在设计缺陷，最多只有前4GB，数据会被加密且虚拟机磁盘文件一般较大，占几十GB，大部分文件数据未被加密，美国网络安全和基础设施安全局（CISA）提供了恢复脚本（https://github.com/cisagov/ESXiArgs-Recover），可以尝试在具有.vmx~备份文件的情况下利用未完全加密的磁盘文件，重建磁盘描述文件，恢复虚拟机。

具体操作如下：

1. 下载 CISA 的恢复脚本并保存为 /tmp/recover.sh.

1.1 从https://github.com/cisagov/ESXiArgs-Recove/recover.sh下载后上传

1.2 在ESXi后台使用wget工具直接下载：wget -O /tmp/recover.sh https://raw.githubusercontent.com/cisagov/ESXiArgs-Recover/main/recover.sh

2. 给脚本添加执行权限：

chmod +x /tmp/recover.sh

3. 进入/vmfs/volumes/datastore1目录，使用“ls –l”命令查看虚拟机列表，选择要恢复的虚拟机（以test-1为例）：

4. 进入虚拟机目录下，运行恢复脚本/tmp/recover.sh [name]（[name]为虚拟机名称，此处为test-1），如果 VM 是精简格式，运行/tmp/recover.sh [name] thin

5. 数据恢复成功，虚拟机正常启动

数据恢复软件

如果恢复脚本无法恢复数据，可以尝试使用数据恢复软件恢复磁盘文件。取出被加密的磁盘镜像文件，以test-1-flat.vmdk为例：

步骤一：安装并打开ImDisk虚拟磁盘驱动程序（https://sourceforge.net/projects/imdisk-toolkit/），点击Mount new按钮，找到目标文件，注意查看驱动器号，点击OK。

步骤二：安装并打开数据恢复软件，如R-Studio(https://www.r-studio.com/)，点右击驱动器I，点击“扫描”；

扫描完成后会加载分区信息，本案例中只有一个分区Recognized0，同时，日志中提示系统扇区无法读取的错误。

步骤三：双击Recognized0分区，左边区域会显示磁盘完整的文件目录及路径，右边区域显示对应的被删除的文件。以bin文件夹为例，有X标记的文件即是被删除的文件。

步骤四：批量选择右键被标记的文件，选择“恢复”或者“恢复被标记”，输出到指定目录下，即可恢复被删除的文件。
