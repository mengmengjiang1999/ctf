0x00简介

SaltStack是使用Python开发的一个服务器基础架构集中化管理平台，底层采用动态的连接总线，使其可以用于编配，远程执行， 配置管理等等。Salt非常容易设置和维护，而不用考虑项目的大小。从数量可观的本地网络系统，到跨数据中心的互联网部署，Salt设计为在任意数量的server下都可工作。Salt的拓扑使用简单的server/client模式，需求的功能内建在一组daemon中。salt在几乎不改动配置的情况下就可以工作，也可以调整从而满足特定的需求。

0x01漏洞概述

在2020年5月初，国外某安全团队披露了SaltStack存在认证绕过漏洞（CVE-2020-11651）和目录遍历漏洞（CVE-2020-11652）。攻击者可以通过构造恶意请求绕过Salt Master的验证逻辑，调用相关未授权函数可以实现远程命令执行、目录遍历等。

0x02影响版本

SaltStack < 2019.2.4
SaltStack < 3000.2

0x03环境搭建

本次测试靶机使用kali20.4版本，靶机和攻击机我们使用同一个，当然我们也可以用不同的虚拟机做区分。

由于使用的脚本要求使用python3的环境，所以我们需要准备python3和pip3

pip3安装指令如下，安装好之后最好查看以下版本是否正确

wget https://bootstrap.pypa.io/pip/get-pip.py
python3 get-pip.py
pip3 --version

这里我们使用vulhub和docker搭建环境，没有搭建vulhub和docker的话就需要先配置好相关环境再进行漏洞环境的搭建。vulhub和docker的搭建百度上有很多，可以自行查询。

cd /root/vulhub/saltstack/CVE-2020-11651
docker-compose up -d
docker ps

由于本次测试使用的Poc要求安装salt，所以这里需要我们使用pip3进行salt的安装。这里我们另起一个终端进行salt的安装，速度还是比较快的。

pip3 install salt

我们先进行测试Poc，输入1然后回车，结果显示可以连接就证明漏洞存在。

下一步我们输入2进行读取文件，这里我们选择的读取路径为 /etc/passwd，回车就可以看到返回结果。

下一步我们输入3进行命令执行，回车之后会出现两个选择，这里我们选择master，输入1即可。回车输入cdm指令回车即可看到返回结果。

最后我们进行反弹shell的测试。

由于我们需要进行端口的监听，我们另起一个窗口对8888端口进行监听，输入指令回车之后我们再回到测试的终端进行反弹shell，按照提示填入靶机IP和反弹端口后回车即可。

nc -lvp 8888

反弹shell成功后我们可以在监听页面看到如下图结果，输入指令whoami回车即可实现远程命令执行。

0x05修复建议

将SaltStack升级至安全版本以上，升级前建议做好快照备份。安全版本SaltStack 2019.2.4、SaltStack 3000.2。

将Salt Master默认监听端口（默认4505 和 4506）设置为禁止对公网开放，或仅对可信对象开放。
