内网渗透学习--Windows认证
2022-07-29 21:25:05

前言

在平时的渗透测试中，当外网打点完成进入内网之后，便开始了内网渗透。其中Kerberos一直难以理解，在此记录一下学习Kerberos协议的过程。

Kerberos协议作为一个认证协议，在介绍Kerberos协议之前，本文重点内容是Kerberos协议的前置知识Windows认证。

总所周知，当我们每登录一次系统，系统就会完成一次认证，但是这个认证是怎么完成的呢？

0x01 本地认证

1.1 密码位置

在Windows系统中，我们用户的“密码”会存放到一个叫做SAM的文件里。

位于%SystemRoot%\system32\config\SAM，这个文件又是什么？

SAM（Security Account Manager）：安全账号管理器。SAM文件是Windows的用户账号数据库，计算机上每个用户的用户名和密码都会保存在这个文件，类似于Linux的/etc/shadow。值得一提的是，虽然这个文件在我们计算机上，但是我们也无法直接查看明文密码，因为明文密码会经过NTLM Hash（后文会详细讲解）生成的一串字符存放到SAM文件，所以Windows内部是不保存明文密码的。

当我们尝试打开这个文件时，发现无法打开。

因为在计算机开始运行之后，这个文件就会被锁定，用户无法打开。可见这个文件非常重要，如果这个文件被攻击者”拿走“，那么攻击者可以很轻松的破解密码。

PASS：当我们忘记密码时，可以利用这个文件来恢复密码。

1.2 LM Hash & NTLM Hash

当抓取计算机的Hash时。

可以发现格式为。

Administrator:500:AAD3B435B51404EEAAD3B435B51404EE:31D6CFE0D16AE931B73C59D7E0C089C0:::

这其中的AAD3B435B51404EEAAD3B435B51404EE就是LM Hash，31D6CFE0D16AE931B73C59D7E0C089C0则是NTLM Hash。

1.2.1 LM Hash

LM（LAN Manager）Hash是NTLM Hash的前身。

LM Hash计算过程：

1、将所有小写字母转换成大写字母
123acb -> 123ABC
​
2、转换为16进制，长度不够14字节使用0x00填充
123ABC -> 3132334142430000000000000000
​
3、分成两部分，每一部分7个字节
3132334142430000000000000000 -> 31323341424300  00000000000000
​
4、每一部分转换为二进制，不足56Bit在左边填充0
31323341424300 - > 110001001100100011001101000001010000100100001100000000
填充：00110001001100100011001101000001010000100100001100000000
​
5、将二进制比特流按7比特分一组，分成8组，末尾加0，再组成一组
0011000 0
1001100 0
1000110 0
0110100 0
0001010 0
0001001 0
0000110 0
0000000 0
组合：0011000010011000100011000110100000010100000100100000110000000000
因为第二部分为全0，所以得到的也是全0
​
6、得到的两组结果分别转换为16进制，分别和KEY为"KGS!@#$%"进行DES加密，的到结果转换为16进制。
0011000010011000100011000110100000010100000100100000110000000000
转换16进制：30988C6814120C00
DES加密：48-D7-EB-91-2F-5E-69-7C
因为第二部分是全0，所以结果为：AA-D3-B4-35-B5-14-04-EE
​
7、拼接得到LM Hash
48-D7-EB-91-2F-5E-69-7C-AA-D3-B4-35-B5-14-04-EE

LM Hash存在很多缺陷：

  * 密码最多14个字符

  * 密码不分大小写

  * 如果密码小于6位，LM Hash后半部分是固定的

  * ......

LM Hash目前已经被淘汰，但是 Windows Vista和Windows Server 2008以前的系统还在使用。

1.2.2 NTLM Hash

为了解决LM Hash的缺陷，Microsoft 于1993年在Windows NT 3.1中引入了NTLM协议，NTLM（NT LAN Manager）Hash支持Net NTLM认证协议，长度为32位，由数字和字母组成。

NTLM Hash的计算过程：

1、将密码转换成16进制。
password -> 70617373776f7264
2、进行Unicode编码
70617373776f7264 -> 700061007300730077006f0072006400
3、再进行MD4加密。
700061007300730077006f0072006400 -> 8846f7eaee8fb117ad06bdd830b7586c

计算NTLM Hash也可以使用python脚本：

import hashlib,binascii
hash = hashlib.new('md4', "password".encode('utf-16le')).digest()
print binascii.hexlify(hash)

其中涉及到了两个进程winlogon.exe和lsass.exe。

winlogon.exe：Windows Logon Process（winlogon.exe）是Windows NT用户登录程序，用于管理用户登录和退出。

0x02 网络认证

在内网环境中，如果两台主机同属于一个工作组，A主机想要访问B主机上的资源，就需要通过认证才能访问B主机上的资源。

由于没有信托机构所以二者之间无法建立一个完美的信任机制，只能点对点的认证。

信托机构：在网络中A向B转账，这个过程中需要通过银行来完成，银行需要核实A和B的身份是否合法、A的账户中有没有足够的金额等，同时A和B还需要完全信任银行，这里的银行就相当于信托机构。

2.1 NTLM

在进行网络认证的过程中，就需要有一个协议来规范整个过程。早期SMB协议在网络上传输明文口令。后来出现 LAN Manager Challenge/Response验证机制，简称LM，但是这个机制很容易被破解。再到后面出现了NTLM和Kerberos。

微软提出了WindowsNT挑战/响应认证机制，称之为NTLM。已经有了更新的NTLM v2以及Kerberos验证体系。NTLM是windows早期安全协议，因向后兼容性而保留下来。

NTLM是NT LAN Manager的缩写，这也说明了协议的来源。NTLM 是指telnet的一种验证身份方式，即问询/应答身份认证协议，NTLM有两个版本分别是v1和v2，与之相关的又有Net-NTLMv1/v2。

[NTLM协议] https://baike.baidu.com/item/NTLM/6371298

关于NTLM又有NTLM v1/ v2和Net-NTLMv1/v2，他们分别是什么，又有什么区别，这里也是我一直迷惑的地方。

NTLM Hash是用户的密码经过处理之后存储在SAM文件中，而Net-NTLM Hash用于网络认证中，也就是挑战/响应认证机制中使用的Hash。

根据对应关系可以发现NTLM v1对应的是Net-NTLMv1，NTLM v2对应的是Net-NTLMv2。NTLM v1/ v2只是挑战/响应认证机制中不同的协议版本，而Net-NTLMv1/v2便是不同版本NTLM Hash与Challenge进行加密运算得到的结果，二者的区别就在Challenge和加密算法。下面会抓包看一下整个认证过程。

2.2 挑战/响应

整个认证机制过程中大致分为三步：

  * 协商：协商主要是确认认证双方使用的版本（NTLM v1/ v2）

  * 质询：质询就是挑战/响应认证机制起作用的范畴。（下面所讨论的过程也是这一步）

  * 认证：认证是在完成质询后，验证结果，完成认证。

质询的大致流程：

1、客户端向服务器发起请求。
2、服务端收到请求后，验证用户名是否存在，不存在之间返回认证失败；如果用户名存在，则生成一个16位的随机数也就是Challenge，将Challenge发送给客户端；同时服务端根据用户名在SAM文件中查找对应的NTLM Hash，使用NTLM Hash加密Challenge得到Challenge1，这里的Challenge1就是Net-NTLM Hash。
3、客户端收到Challenge之后，使用用户名对应密码的NTLM Hash加密Challenge，得到Challenge2，这里的Challenge2就是Response，将Response发送给服务端。
4、服务端收到客服端发送的Response之后，将Challenge1和Response进行比较，一致则验证成功，反之失败。

如何使用密码生成Net-NTLM上文有提到。

抓包测试：

测试环境：

服务端：
IP:192.221.21.20
用户名：Administrator
密码：1234qwer....
客户端：
IP:192.221.21.10

在客服端连接服务端：

net use \\192.221.21.20 /u:Administrator 1234qwer....

利用Wireshark抓取数据包分析。

这四个数据包，就相当于质询过程中的四步，首先我们看其中第一个数据包。

客户端发送请求，这里的请求中看不到明文用户名和密码，再看第二个数据包。

在第二个数据包中，可以看到服务端发送给客户端的Challenge，再看第三个数据包。

第三个数据包包含了，LM Response，NTLMv2 Response，User name和Host name。（Windows Server2008默认禁用Net-NTLMv1，使用Net-NTLMv2）。

以上就是实际测试中NTLM v2的质询过程，至于NTLM v1，其过程如下：

1、客服端向服务端发起请求。
2、服务器收到请求，生成一个8位的Challenge，发送给客服端。
3、客服端收到Challenge，利用对应的NTLM Hash加密Challenge生成Response发送给服务端。
4、服务端验证Response。

其实NTLM v1和NTLM v2的过程完全相同，不同的就是生成的Challenge以及加密算法不同，NTLM v1的主要加密算法是DES，NTLM v2的主要加密算法是HMAC-MD5。

直到到这里才大致明白了NTLM、NTLM v1/ v2和Net-NTLMv1/v2是什么。

在平时进行渗透的时候得到hach之后还可以利用Hashcat进行破解，另外在内网渗透中经常使用的一种攻击方法Pass the hash（哈希传递）也与这里有关，具体后续再分享。
