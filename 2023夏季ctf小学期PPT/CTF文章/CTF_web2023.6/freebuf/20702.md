从零到一：浅谈区块链题目的模拟及落地
2021-08-25 11:26:00

概述

区块链和人工智能即将成为 CTF 的未来方向。如今的大型赛事中常常显现一些区块链的题目。没有一定实操经验的选手即使是简单的签到，也很容易爆零。

目前区块链题目的要求主要有如下几点

动态 flag

每位选手/每支队伍拥有自己的对应题目

在一些赛事中会出现使用 token 来区分不同队伍及选手。但是在赛后部署中，一旦有网上的 wp 没有对相关 token 打码，就会导致题目失去意义。所以必须分配单独容器。

其部署要求与 PWN 题大部分相同，也有所不同。不同主要在于：

不需要对于sh等系统命令的限制来避免搅屎。（这里需要确保 Python 编写正确）

有访问链网络的需求，PWN 容器禁用外网。

鉴于此，笔者采用CTFd+CTFd-Whale来进行底层部署，可以直接接入平台，同时也支持了动态 flag。

目前本项目分为两块，一层作为容器的镜像，另一层作为容器的上层。镜像中实现了大部分区块链的操作，包括账户的生成、合约的部署，以避免重复造轮子。上层中主要负责合约及校验。

custom.py

在custom.py中需要实现check、code、get_url方法。

check方法主要用于检查选手是否完成了 flag 的要求。调用时会传入acct,tx_hash,cont_if，分别代表选手的账户、选手完成的转账记录、合约编译结果。可以直接使用镜像util.py实现的方法。

def check(acct, tx_hash, cont_if):
    return check_if_has_topic(acct.address, tx_hash, cont_if, TOPIC)


code方法用于随机化合约和合约内容打印。调用是会传入一个布尔值，为真代表打印合约，为假代表部署合约。如果不需要给选手合约内容，可以直接修改注释。如果希望自定义随机化合约内容，可以修改其中的替换函数。

# public = False : Deploy
# public = True : Preview the source code
def code(public=True):
    if(public):
        # return ""
        # If you don't want user to see the source code, just return ""
        with open('./eth.sol', 'r') as f:
            SRC_TEXT = f.read()
            source = SRC_TEXT.replace(
                '$RAND_INT$', '0')
    else:
        with open('./eth.sol', 'r') as f:
            SRC_TEXT = f.read()
            source = SRC_TEXT.replace(
                '$RAND_INT$', str(int.from_bytes(os.urandom(16), 'little')))
    return source


get_url方法主要用于链网络的选择。返回值分别为连接模式、 JSON-RPC 地址、链 ID、PoA。连接模式为真，代表使用 HTTP/HTTPS，为假则代表 WebSocket。PoA 为真代表使用 PoA，否则使用 PoW。

def get_url():
    return True, "http://eth", 97, True


注：这里使用反向代理，具体原因及操作见下一节。

Dockerfile

Dockerfile里只需要修改solc的版本即可。版本基本在eth.sol文件的第一行注明。版本号参见 Release

ENV tag_name="v0.5.10"


注意：因为solc版本迭代有较大差异，版本错误会导致无法进行正常编译，请仔细确认！

eth.sol

尽量在文件中设置精确版本号和随机位，以便赛后复现。

pragma solidity ^0.5.10;

BSCT 的优势

水龙头无需验证每 24 小时就可获得 1 个 (t)BNB。其它测试网不是需要登录、转发就是获得的量比较少，大部分对国内不友好。

浏览器国内访问快，支持合约的反编译，有些小众链的浏览器支持不是很好。

浏览器支持一键添加节点至MetaMask，不用手输。

Gas 价格低，速度快。

BSCT 的劣势

相对于一些链的浏览器，虽然功能丰富，但是主题皮肤不是很得人心。KCC 链的浏览器虽然功能少得多，但是皮肤确实好看。

浏览器有时候对MetaMask支持不是很到位，有时转账成功完成会提示0 transaction complete

JSON-RPC 不支持 WebSocket

自定义区块链的 JSON-RPC 需要注意修改其链ID、协议类型。

容器部署

直接 Fork 上层，修改 GitHub Action 中的相关字段，Push 后可以自动编译上传，只要在CTFd中与 PWN 题一样指定容器名称即可。但是必须先安装CTFd-Whale。

网络部署

之前提到过一句，这里仔细阐述一下。目前有以下几种方式可以使得容器正常工作：

设置反向代理，横跨外网与容器内网，实现流量出口。

内部利用Geth实现私有链。

直接将容器内网连入互联网（不建议）。

因为容器属于内网，直接连接互联网有可能导致信息泄露。而且一旦开发连接，会导致 PWN 容器也一并接入互联网，可能会造成其它影响。所以笔者选择第一种方式。

反向代理这里直接使用nginx来实现，其它方式也可实现，各位师傅看情况决定。

直接使用proxy_pass模块

http {
    include mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;
    gzip on;
    server {
        listen 80;
        server_name localhost;
        location / {
            proxy_pass https://data-seed-prebsc-1-s1.binance.org:8545;
        }
    }
}


在docker-compose.yml中加入 nginx 容器，其网络与 Frp 容器网络相同。在容器中访问 http://name 成功访问。
