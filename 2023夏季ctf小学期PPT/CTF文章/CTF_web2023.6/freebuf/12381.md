PHP中SSRF漏洞相关函数及实验

file_get_contents()函数

函数作用：将整个文件内容读取到字符串中

实验漏洞源码：

<!DOCTYPE html>
<html>
<head>
	<title>ssrf</title>
</head>
<body>
	<form action="ssrf.php" method="GET">
	<input type="text" name="path">
	<input type="submit" value="提交">
	</form>
</body>
</html>
 
<?php
	$url = $_GET['path'];
	if ($url!=null) {
	$sss = file_get_contents($url);
	}
	echo $sss;
?>

观察上面的源代码，不难发现，传递参数时path，并且在传递参数面对用户输入的时候，并没有对path参数做任何过滤处理，而是直接将对应的参数值丢到了file_get_contents()函数里面，而后又将读取文件内容的字符串，做了输出

光说不练，假把式！那么，我们接下来就看看上面一串简单的代码会产生什么危害吧？

我们直接无节制的恶意访问任意服务器中的其他文件，会直接访问成功

curl_exec()函数

<?php
if(isset($_GET['url']) && $_GET['url'] != null){
    $URL = $_GET['url'];
    $CH = curl_init($URL);
    curl_setopt($CH, CURLOPT_HEADER, FALSE);
    curl_setopt($CH, CURLOPT_SSL_VERIFYPEER, FALSE);
    $RES = curl_exec($CH);
    curl_close($CH) ;
    echo $RES;
}
?>

上面的代码是pikachu-ssrf漏洞模块对应的部分源码，从上面的源码也很容易的发现，对于用户传参的url参数值，同样是没有做任何过滤的，唯一不同的是，这段代码是建立了一个curl会话，并且调用curl_exec()函数执行对应的url会话信息，并将其执行结果返回给浏览器。

fsockopen()函数：实现对用户指定url数据的获取，该函数使用socket（端口）跟服务器建立tcp连接，传输数据

<?php
$host=$_GET['url'];
$fp = fsockopen("$host", 80, $errno, $errstr, 30);
if (!$fp) {
    echo "$errstr ($errno)<br />\n";
} else {
    $out = "GET / HTTP/1.1\r\n";
    $out .= "Host: $host\r\n";
    $out .= "Connection: Close\r\n\r\n";
    fwrite($fp, $out);
    while (!feof($fp)) {
        echo fgets($fp, 128);
    }
    fclose($fp);
}?>

源码放在上面了，大家就自行实验一下好了。。
