0x2 格式化字符串漏洞

漏洞原理

格式化字符串代码

#include <stdio.h>
int main()
{
	char num = 1;
	printf("%s %d %d %d %d", "num", 1, 2, 3, 4);
	return 0;
}


main函数设置断点

F5->调试->窗口->反汇编

运行结果：

可见输出了5个参数值。使format参数>待输出的参数数量

#include <stdio.h>
int main()
{
	char num = 1;
	printf("%s %d %d %d %d %d %d", "num", 1, 2, 3, 4);
	return 0;
}


F5->调试->窗口->反汇编：

运行结果：

可见输出了7个参数值，但实际入栈参数只有5个，所以，输出两个本不应该输出的地址内容。由此泄露了栈中数据。

漏洞危害

格式化字符串漏洞由像printf(user_input)这样的代码引起，其中user_input是用户输入的数据，具有Set-UID root权限的这类程序在运行的时候，printf语句将会变得非常危险，因为它可能会导致下面的结果：
1.使得程序崩溃
2.任意一块内存读取数据
3.修改任意一块内存里的数据

0x3 栈溢出漏洞

漏洞原因

栈溢出是由于C语言系列没有内置检查机制来确保复制到缓冲区的数据不得大于缓冲区的大小，因此当这个数据足够大的时候，将会溢出缓冲区的范围。

解决方法：
1.增大栈空间
2.改用动态分配，使用堆（heap）而不是栈（stack）
3.函数参数中不要传递大型结构/联合/对象，应该使用引用或指针作为函数参数
4.减少函数调用层次，慎用递归函数，例如A->B->C->A环式调用

漏洞原理

漏洞代码

#include<stdio.h>
#include<string.h>
 
int main(){
	char buf[5];
	gets(buf);
	printf("Input:%s\n",buf);
	return 0;
}


gets 本身是一个危险函数。它从不检查输入字符串的长度，而是以回车来判断输入是否结束，所以很容易可以导致栈溢出，

使用gcc编译出a.out文件，以下会提示gets为危险函数

执行gdb a.out会自动加载pwndbg

list列出源代码内容

b 8在代码第7行设置断点

i b查看断点

r运行程序，并输入123456789，相当于给buf参数赋值

n逐步执行，因为buf为5，超出部分会溢出，覆盖rbp部分

若输出12345，则rbp部分未被覆盖

0x4 堆溢出漏洞

漏洞原因

堆溢出是指程序向某个堆块中写入的字节数超过了堆块本身可使用的字节数，因而导致数据溢出，并覆盖到物理相邻的高地址的下一个堆块。

堆溢出漏洞发生的基本前提是
1.程序向堆上写入数据。
2.写入的数据大小没有被良好地控制。

堆溢出利用
1.覆盖与其物理相邻的下一个 chunk 的元数据。
2.利用堆中的机制（如 unlink 等 ）来实现任意地址写入（ Write-Anything-Anywhere）或控制堆块中的内容等效果，从而来控制程序的执行流。

漏洞原理

漏洞代码

#include <stdio.h>
#include <stdlib.h>
int main(void){
	char *buff1;
	buff1 = malloc(5);
	gets(buff1);
	free(buff1);
	exit(0);
}


运行后，输入字符长度超出空间内存大小，超出部分覆盖掉其相邻的堆块

运行后，输入字符长度小于空间内存大小，其相邻的堆块正常
