需要的工具：volatility

Which volatility profile would be best for this machine?

哪种波动率曲线最适合这台机器？
我们通过如下命令去识别一下该内存文件的镜像信息。
volatility -f 111.raw imageinfo


我们查看Suggested Profile(s)即可得到答案
答案为：WinXPSP2x86

How many processes were running when the image was acquired?

获取镜像时有多少进程在运行？
我们可以通过如下命令查看运行的进程：
volatility.exe -f 111.raw --profile=WinXPSP2x86 pslist

我们可以看到有25个进程运行，其中有6个已经退出了。

所以答案就是25-6=19
答案为：19

What is the process ID of cmd.exe?

cmd.exe 的进程号是多少？
通过刚才查看进程，我们可以知道进程号为1960

答案为：1960

What is the name of the most suspicious process?

最可疑的进程名称是什么？
我们可以通过如下命令查看进程其中包括隐藏和终止的进程。
volatility -f 111.raw –-profile=WinXPSP2x86 psscan

其中 rootkit最为可疑，因为rootkit是一种特殊的恶意软件，它的功能是在安装目标上隐藏自身及指定的文件、进程和网络链接等信息，比较多见到的是Rootkit一般都和木马、后门等其他恶意程序结合使用。

答案为：rootkit.exe

Which process shows the highest likelihood of code injection?

哪个进程显示代码注入的可能性最高？
科普：
svchost.exe：svchost.exe进程是Windows服务主进程，这意味着svchost.exe是Windows系统的一部分，它是安全的核心文件。
Svchost.exe 是从动态链接库 (DLL) 中运行的服务的通用主机进程名称，个程序对系统的正常运行是非常重要，而且是不能被结束的。许多服务通过注入到该程序中启动。

至于为什么svchost.exe每次会被优先选择为代码注入原因如下：

 1. Svchost.exe是一个Windows操作系统中常见的进程，用于管理和运行许多系统服务。由于它是一个系统进程，因此在Windows操作系统中运行时具有较高的权限和信任级别，这使得攻击者可以更容易地运行恶意代码，并隐藏其行为。
 2. Svchost.exe进程通常会在后台运行，不会引起用户的注意，这使得攻击者可以更容易地隐藏恶意代码的存在，而不被用户察觉。
 3. Svchost.exe通常会访问网络或其他系统资源，这使得攻击者可以利用它来执行网络攻击或窃取敏感信息。
    所以，svchost.exe被代码注入的可能性很大。

    验证一下：
    我们使用如下指令查看被注入的进程：
    volatility -f 111.raw --profile=WinXPSP2x86 malfind

    标头包含MZ为PE文件。
    答案为：svchost.exe

There is an odd file referenced in the recent process. Provide the full path of that file.

最近的过程中引用了一个奇怪的文件。 提供该文件的完整路径。
我们使用如下命令查看文件：（一些参数我们可以从上个问题中 得知）
volatility -f 111.raw --profile=WinXPSP2x86 handles -p 880 -t file

其中，最突出的为str.sys文件。
答案为：C:\WINDOWS\system32\drivers\str.sys

What is the name of the injected dll file loaded from the recent process?

从最近的进程中加载的注入的dll文件的名称是什么？
我们使用如下命令检查dll注入以及进程镂空：
volatility -f 111.raw --profile=WinXPSP2x86 ldrmodules -p 880

小知识：如果inload，ininit，inmem属性的任何值是false，则dll注入可能已经发生，（具有ininit=false的pe文件除外）
所以dll文件名称为msxml3r.dll
答案为：msxml3r.dll

What is the base address of the injected dll?

注入的dll的基地址是什么？
我们可以通过malfind模块来查看：

它与注入进程共享一个基地址。
答案为：0x980000
