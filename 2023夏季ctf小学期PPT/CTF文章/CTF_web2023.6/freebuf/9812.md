极验滑块验证码研究
2022-06-28 16:59:24

非人为操作极验有两种：

 1. 利用python selenium这种，启动webdriver浏览器，然后模拟点击，滑动来完成极验验证。缺点是效率低，耗时严重，吃性能；不过优点也很明显：够简单，通过率也很高，与极验的版本耦合性很低。
 2. 根据极验的请求，伪造参数来完成极验校验。优点是避免了selenium启动一个浏览器，直接请求就行了，够快，还可以根据自己的需求增加多线程，缓存，重试等等来优化。缺点是，需要研究极验的js代码，调用链路，时间、学习成本很高，和版本的耦合性很高，几乎一段时间就会推出一个新的版本，那么旧的版本的逻辑可能就会不适用。

因此，这里开两篇文章分别介绍这两种方案。本文章介绍第一种。
【声明】：本文内容仅限于安全研究，维护网络安全，人人有责！

首先是要学会selenium,python语言的。如果不熟悉python，也可以搜搜其他语言，比如java。不用太详细，大概知道怎么回事就行。

 1. 打开官网demo链接，观察一下是一个常见的登录页面表单，其中用户名和密码有默认值value，我们利用selenium进行模拟键入。
# 引入selenium，并下载谷歌webdiver
# 启动的初始项，可以写入一些浏览器配置
# 比如userAgent,无头绕过检测等配置
options = webdriver.ChromeOptions()
options.add_argument('xxx')
# 获得driver
driver = webdriver.Chrome(options=options)
# 请求url
driver.get("demo链接")
# 等待渲染完成 再键入
wait = WebDriverWait(driver, 20)
username = wait.until(EC.presence_of_element_located((By.ID, 'username')))
driver.find_element(value="username", by=By.ID).clear()
ActionChains(driver).send_keys_to_element(username, 'username').perform()

driver.find_element(value="password", by=By.ID).clear()
password = wait.until(EC.presence_of_element_located((By.ID, 'password')))



这样username和password就填好了，因为demo上写死了value，所以改也没用。

 1. 接下来就模拟点击下面的按钮，打开F12找到class名称，然后点击。（普通大型的页面可能有重名class，需要找到有辨识度的比如id,class,placeholder或者相互组合比如：x_path: //div[@id="id1"]//input[@placeholder="手机号或邮箱"]'）
slider = wait.until(EC.presence_of_element_located((By.CLASS_NAME, 'geetest_radar_tip')))
ActionChains(driver).click(slider).perform()

 1. 点击之后就会弹出滑块的框，使用canvas画布画的，有两个画布，一个是xx_slice 这个是被扣掉一块的图片，一个是xx_bg是完整图片。

    需要模拟滑块滑动 => 需要知道滑块坐标 => 需要比较slice 和 bg的差异性 => 比较两个图片的像素点

那么怎么得到这两张图片呢？

我们在console 输入

document.getElementsByClassName("geetest_canvas_bg geetest_absolute")[0].toDataURL("image/png");


发现返回了扣掉的图片的base64

同理获得背景图片的base64

document.getElementsByClassName("geetest_canvas_fullbg geetest_fade geetest_absolute")[0].toDataURL("image/png");


webdirver提供跑js的功能：driver.execute_script("xxx"）

然后将他们转成bytes 打开

bg_b64 = im_bg_b64.split(',')[-1]
bg_bytes = base64.b64decode(bg_b64)
fullbg = im_fullbg_b64.split(',')[-1]
fullbg_bytes = base64.b64decode(fullbg)
 # 用Image 打开
im_bg = Image.open(BytesIO(bg_bytes))
im_fullbg = Image.open(BytesIO(fullbg_bytes)) 

 1. 开始比较两张图片的差异性，这里可以用cv去实现，也可以遍历像素点实现
cv版：
bg_gray = cv2_open(bg, flag=cv2.COLOR_BGR2GRAY)
tp_gray = cv2_open(tp, flag=cv2.COLOR_BGR2GRAY)
# 边缘检测
tp_gray = cv2.Canny(tp_gray, 255, 255)
bg_gray = cv2.Canny(bg_gray, 255, 255)
# 目标匹配
result = cv2.matchTemplate(bg_gray, tp_gray, cv2.TM_CCOEFF_NORMED)
# 解析匹配结果
min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(result)
# 得到坐标
distance = max_loc[0]

像素遍历：
pix_1 = im_fullbg.load()
pix_2 = im_bg.load()
threshold = 60

for x in range(im_fullbg.size[0]):
    # 垂直方向不同像素的计数
    vert_count = 0
    for y in range(im_fullbg.size[1]):
        p_1 = pix_1[x, y]
        p_2 = pix_2[x, y]
        # 找到像素不同的点
        if abs(p_1[0] - p_2[0]) > threshold and abs(p_1[1] - p_2[1]) > threshold and abs(
                        p_1[2] - p_2[2]) > threshold:
             vert_count += 1
             # 如果是一条直线返回横坐标距离，测试下来10个像素结果较好
             # print(vert_count, x)
             if vert_count > 10:
                 return x

 1. 得到坐标之后进行最后一步，模拟滑块！
action_chains = webdriver.ActionChains(driver)
# 点击，准备拖拽
action_chains.click_and_hold(button = self.driver.find_element_by_css_selector(".geetest_slider_button"))
action_chains.pause(0.3)
action_chains.move_by_offset(offset_x + 7, 0)
action_chains.pause(0.8)
action_chains.move_by_offset(-7, 0)
action_chains.pause(0.6)
action_chains.release()
action_chains.perform()


有可能会被识别出来，可以增加重试 点击geetest_refresh_1 class 进行刷新。也可以增加轨迹真实性：

  * 不断成功拖动，将轨迹记录到缓存池中，进行模拟时根据坐标来取响应的轨迹。(该方法不太适合模拟，适合请求)
  * 将轨迹设置成jquery.easing轨迹函数更柔和。
  * 结合人类滑块的特征模拟估计，比如先快后慢，拖动过了再往回拖，添加停顿等等，能显著提高成功率。
