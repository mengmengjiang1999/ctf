第一章、Serializable与Externalizable

public interface Serializable {
}
public interface Externalizable extends java.io.Serializable {

void writeExternal(ObjectOutput out) throws IOException;

void readExternal(ObjectInput in) throws IOException, ClassNotFoundException;
}

1、序列化方式

（1）Serializable

  * 采用默认序列化方式，将非transatient和非static的属性进行序列化

  * 自定义readObject和writeObject完成部分属性的序列化

（2）Externalizable

  * Externalizable需要重写writeExternal和readExternal方法，并且在方法中编写相关的逻辑完成序列化和反序列化。

2、序列号

（1）Serializable

  * 需要序列号

（2）Externalizable

  * 无需序列号

3、实现方式

（1）Serializable

  * 其采用反射机制完成内容恢复，没有一定要有无参构造函数的限制

（2）Externalizable

  * 实现Externalizable接口需要无参构造方法，否则反序列化会报错


第二章、POC分析

首先原生的readObject方法会对流中的类进行判断，根据判断结果进入不同的分支程序中。大部分的反序列化流会进入TC_OBJECT分支中，执行readOrdinaryObject方法。

readOrdinaryObject方法首先会调用readClassDesc读取反序列化流返回描述符desc。在获取desc的过程中，lookup方法起到主要作用，它会查找并返回给定类的类描述符entry，而在entry中就包含了构造的readObject方法（Method类型），同时根据entry和参数model初始化desc对象。

readOrdinaryObject得到desc后将其实例化为只有结构却无数据的obj对象，后续调用private void readSerialData(Object obj, ObjectStreamClass desc)恢复对象数据。在恢复对象数据时，会直接使用desc中记载的构造readObject方法读取反序列化流中数据，这样一来便触发了payload。

5.1、readClassDesc()

  * 该方法主要作用是读取流中反序列化数据，通过判断序列化流中高字节选择具体的处理方式，initNonProxy中也通过这个方法读取序列化流中的父类类描述符作为参数的。

private ObjectStreamClass readClassDesc(boolean unshared)
throws IOException
{
// 读取输入流中信息，判断流中class的类型
byte tc = bin.peekByte();
ObjectStreamClass descriptor;
switch (tc) {
  case TC_NULL:
      descriptor = (ObjectStreamClass) readNull();
      break;
  case TC_REFERENCE:
      descriptor = (ObjectStreamClass) readHandle(unshared);
      // Should only reference initialized class descriptors
      descriptor.checkInitialized();
      break;
  case TC_PROXYCLASSDESC:
      descriptor = readProxyDesc(unshared);
      break;
  case TC_CLASSDESC:
      // 程序进入这个分支
      descriptor = readNonProxyDesc(unshared);
      break;
  default:
      throw new StreamCorruptedException(
          String.format("invalid type code: %02X", tc));
}
return descriptor;
}
