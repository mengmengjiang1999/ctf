序列化&反序列化

简介

什么是序列化：序列化就是把对象转换为字符串的过程，序列化机制的核心作用就是对象状态的保存与重建

什么是反序列化：反序列化就是把字符串转换为对象的过程，从文件或网络上获取序列化后的对象字节流后，根据字节流中所保存的对象状态及描述信息，通过反序列化重建对象

本质上serialize()和unserialize()在PHP内部的实现上是本有漏洞的，漏洞的主要产生是由于应用程序在处理对象，魔术函数以及序列化相关问题时导致的

当传给unserialize()的参数可控时，那么用户就可以注入精心构造的payload，当进行反序列化的时候就有可能会触发对象中的一些魔法方法，造成意想不到的危害

魔术方法

__tostring: 当一个对象被当作字符串对待的时候，会触发这个方法

__get: 当调用一个未定义的属性时访问此方法

__set: 给一个未定义的属性赋值时调用

__isset: 当在一个未定义的属性上调用isset()函数时调用此方法

__unset: 当在一个未定义的属性上调用unset()函数时调用此方法

__call: 当调用一个未定义的方法时调用此方法

__autoload: 他会在视图使用尚未被定义的类时自动调用。通过调用此函数，脚本引擎在PHP出错失败前有了最后一个机会加载所需的类

__construce: 构造方法，当一个对象创建时调用此方法

__destruce: 析构方法，当一个对象被销毁时调用这个方法

__clone: 如果想赋值一个对象则需要使用clone方法

__sleep: 当类外使用序列化时调用此方法

__wakeup: 当类外使用反序列化时调用此方法

序列化

O:5:"index":1:{s:3:"foo";s:5:"hello";}

O表示对象，5表示对象名字的程度，index是对象名，1表示里面有一个变量，{}里面是key和value，s表示string对象，3表示内容的长度，foo为字符串定义的名字。;}反序列化过程中，遇到;}就会停止，反序列化时以;作为分隔，根据长度判断内容。

分析以下源代码，首先获取一个$a的传参，接着经过base64解密，进行反序列化操作。进行反序列化的时候首先会执行了__construce构造魔术方法进行变量的赋值，然后进行__wakeup这里，在这里存在了一个waf检测，不能有空格，再接着触发__destruce魔术方法，这个方法存在回调函数，通过判断之后会去调用ping方法，执行命令。

<?php
class home{

    private $method;  # 私有变量$method
    private $args;  # 私有变量$args
    function __construct($method, $args) {  #构造方法
        $this->method = $method;  #赋值给私有变量$method
        $this->args = $args;    #赋值给私有变量$args
    }

    function __destruct(){  #析构方法
        if (in_array($this->method, array("ping"))) { #检查$this-.method的内容是否有array("ping")值
            call_user_func_array(array($this, $this->method), $this->args); #调用回调函数
        }
    }

    function ping($host){
        system("ping -c 2 $host");
    }
    function waf($str){
        $str=str_replace(' ','',$str);
        return $str;
    }

    function __wakeup(){  #反序列化时调用
        foreach($this->args as $k => $v) {  #循环遍历数组
           $this->args[$k] = $this->waf(trim(addslashes($v)));  #进行过滤
 
        }
    }
}

漏洞成因

session序列化处理器，如果设置的session序列化选择器与默认设置不同的话会产生漏洞，在PHP大于5.54，默认的handler是php_serialize，这时如果我们传入一个NaMi|s:0:"";这样的一个数据(PHP)，在存储时就会加上键名进行序列化，但是进行读取的时候还是会按照php_serialize来处理，以竖线|作为键和值的分隔符，将前半部分作为键，后半部分当作值，然后进行反序列化。

分析phar反序列化示例

简介

phar时PHP里类似于Java中jar的一种打包文件，用于归档。当PHP >=5.3时，默认开启支持phar文件

phar文件默认是只读，使用phar文件不需要任何的配置

phar://伪协议及PHP归档，用来解析phar文件内容

Phar文件结构

1、stub

一个供phar扩展用于识别的标志，格式为xxx,前面内容不限，但必须以__HALT_COMPLER();?>来结尾，否则phar扩展将无法识别这个文件为phar文件

2、manifest

phar文件本质上是一种压缩文件，其中每个被压缩文件的权限、属性等信息都放在这部分

这部分还会以形式存储用户自定义的meta-data，这里即为反序列化漏洞点

3、contents

被压缩文件的内容

4、signature

签名，放在文件末尾

phar使用

生成phar文件需要修改php.ini中的配置

[Phar]
; http://php.net/phar.readonly
phar.readonly = Off

有序列化数据必然会有反序列化操作，php一大部分的文件系统函数在通过phar://伪协议解析phar文件时，都会将meta-data进行反序列化，测试后影响的函数如下：(借鉴前辈的，总结一下)

分析反序列化字符逃逸示例

简介

1、php在反序列化时，底层代码是以分号作为字段的分隔，以} 作为结尾(字符串除外)，并且根据长度判断内容

2、反序列化时，当长度和字符不对应的时候会出现报错

3、可以反序列化类中不存在的元素

反序列化字符串逃逸场景

1、过滤后字符串变多

2、过滤后字符串变少

场景1、过滤后字符串变多

代码如下

<?php
function filter($str){
    return str_replace('H','**',$str);  # 使用函数，将H替换为**
}

$name = $_GET['name'];
$text = 'Everyone';
$user = array($name,$text); # 新建一个数组
$ser = filter(serialize($user));  # 使用自定义fileter函数过滤输入
echo $ser."<br/>";
$unser = unserialize($ser); # 反序列化操作
echo $unser[0].'<br/>';
echo $unser[1].'<br/>';
print_r(unserialize($ser));


这是一个正常的输出，我们需要使用逃逸方法将Everyone给替换掉

当输入一个大H的时候，反序列化会报错，出现一个false

报错的原因是，在s:5这里，这里规定的是后面有5个字符，但是里面存在了6个字符: **ello，导致了不对等，所以产生了报错。这种情况下，如果s的长度为5，那么它读不完**ello，如果前面的长度大于后面他会往后继续读取

a:2:{i:0;s:5:"**ello";i:1;s:8:"Everyone";}

前面也说到了，分号作为字符串的分隔，而}作为结尾，那么此时可以构造一个字符串，插入到字符串当中，将逃逸字符串的长度填充成要反序列化的代码长度，就可以控制反序列化的结果以及类里面的变量值

HHHHHHHHHHHHHHHHHHello";i:1;s:4:"NaMi";}

这里的H的长度和构造序列化的内容是等长度的。为什么要等长度？

因为构造的序列化字符，插入到序列化中，需要将s:40满足，而s:40后面的字符刚好有40个，然后分号分隔再去反序列化构造的字符，到} 结尾，就构成了逃逸

场景2，过滤后字符串变少

代码如下，将str_replace简单修改一下

function filter($str){
    return str_replace('aa','*',$str);  # 使用函数，将H替换为**
}

$name = $_GET['name'];
$text = $_GET['text'];
$user = array($name,$text); # 新建一个数组
$ser = filter(serialize($user));  #使用自定义fileter函数过滤输入
echo $ser."<br/>";
$unser = unserialize($ser); # 反序列化操作
echo $unser[0].'<br/>';
echo $unser[1].'<br/>';
var_dump(unserialize($ser));


执行之后，s:2对应的是两个字符，但是里面由于过滤只存放了1个*，导致长度不对等

来看构造的字符，由于过滤将字符变短了，在反序列化的时候，它会根据长度继续往后读取内容，在下面细框内的内容是一个部分，26个字符，正好读取到***************";i:1;s:19:"1**这里，用分号;作为了分隔。接着就是第二个对象进行反序列化，从而达到逃逸的效果
