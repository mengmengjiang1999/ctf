QUIC 从 RFC 9000 毕业：网站运营方不能再“躺平”了！
2021-09-22 09:46:51

近日，据外媒报道，互联网工程任务组IETF已经发布了RFC 9000，且得到了RFC 9001/9002/8999支持，意味着QUIC已从草稿阶段转向了1.0正式版。与此同时，基于QUIC 的HTTP/3也有望紧随其后发表。作为传输控制协议TCP的继任者，快速UDP互联网连接QUIC拥有安全、可靠、低延迟等特性。

QUIC是什么？

QUIC的全称是 Quick UDP Internet Connections protocol，由 Google 设计提出，其设计的目标是替代 TCP 成为 HTTP/3 的数据传输层协议。这是一种全新的可靠且安全的协议，标志着网络标准设计的新方向。在 QUIC 之前，互联网上的安全通信涉及多个层，最常见的是 TCP 用于可靠传输，TLS 用于安全。这种分层方法（通过 OSI 模型）曾经很好地为大众服务，但是大众希望获得更好的性能，因此，必须开发专门的协议。QUIC 是一种多路复用和安全的通用传输协议，建立了客户端（client）和服务端（server）之间有状态的交互连接，它对所有数据包进行身份验证，并尽可能加密，增加了端到端传输的安全性。

图 via Orozco2018


QUIC背后的HTTP/3

随着公众广泛采用移动设备技术后，互联网流量的飞速增长，大众对实时应用的需求不断增加，HTTP/2 的缺点越来越明显。


早在互联网工程任务组 (IETF) 正式标准化 HTTP/2 的同时，Google 就已经在独立构建 gQUIC作为一种新的传输协议，后期更名为 QUIC。大多数 IETF 成员投票决定为 HTTP 建立一个新的规范以运行在 QUIC 上（实际上称之为“HTTP over QUIC”）。这项新举措后来被称为 HTTP/3。


多年来，HTTP 从 HTTP/1.0 发展到 HTTP/1.1，再到 HTTP/2，一直到现在的HTTP/3。在每次迭代中，协议都添加了新功能以处理当时的需求，例如应用层要求、安全考虑、会话处理和媒体类型。每个版本与上一个版本相比的比较表

HTTP/3 的目标是通过解决 HTTP/2 与传输相关的问题，在所有形式的设备上提供快速、可靠和安全的 Web 连接。为此，它使用 QUIC 的不同传输层网络协议，该协议运行在用户数据报协议 (UDP) 互联网协议上，而不是所有以前版本的 HTTP 都使用的 TCP。



互联网“新宠儿”到底强在哪？

HTTP/3 的目的是改善整体网络体验，特别是在高速无线互联网接入仍然不可用的地区。尽管 HTTP/2 非常适合其中一些应用程序，但HTTP/3 在物联网（IoT)、实时广告出价、微服务、网络虚拟现实（VR）等场景中具有更高的价值，更能满足大众的多重需求。小编留意到，最近很多从事证书管理者的朋友们在讨论：2018年的时候HTTP/2还是个新技术，转眼间很多国际大公司已经在使用HTTP/3了。互联网飞速发展的时代，真是应了那句话，时代抛弃你，并不会说再见！目前对于很多网站来说，直接跳过HTTP/2，升级HTTP/3或许是一个更加明智的选择。

部分国际大公司已经开始使用HTTP/3的报道



互联网变革下的新技术转型

HTTP作为互联网应用最为广泛的一种网络协议，可以在Web浏览器和网站服务器之间传递信息。但是HTTP明文协议是不安全的传输协议，通过HTTP协议传输的数据时刻处在被窃听、篡改、冒充的风险中，对隐私信息的保护有着巨大安全隐患。
互联网发展之初，网络安全协议——即安全套接字层（SSL，Secure Socket Layer）协议在1994年诞生了。截止目前，使用HTTPS访问业务，做好技术转型中的信息安全基建，是确保数据传输安全最有效的方法。
HTTPS（超文本加密传输协议）是由HTTP（超文本传输协议）+SSL（安全套接字层协议）构建而成，是一种可进行加密传输、身份认证的网络协议，为浏览器和服务器之间的通信进行加密，确保数据传输到正确的服务器端，防止中间人窃取传输数据。
HTTPS的安全基础是SSL协议，通过SSL证书来验证服务器的身份，为浏览器和服务器之间的通信加密以防止数据中途被窃取；维护数据的完整性，确保数据在传输过程中不被改变。因此，SSL证书已经成为了众多网站的安全标配。
企业网站管理者要想在互联网变革下把握机遇，小编建议，选择更高安全等级的SSL证书和更专业的数字证书厂商，才能在HTTP/3到来之际，保障网站信息安全的同时，后期维护的时候又能省心省力。
