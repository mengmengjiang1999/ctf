3. 安全维护

硬件和软件的版本长时间未更更新可能包含常见的漏洞，并为攻击者渗透网络提供了便利。定期将硬件和软件升级到供应商提供的最新版本，可以避免或者缓解漏洞带来的风险。此外，应在更新前和更新过程中验证下载软件的完整性。应该定期对设备和软件进行安全维护，以确保设备安全稳定运行。

3.1 验证软件和配置的完整性

攻击者可以通过修改操作系统文件、在内存中运行的可执行代码或加载网络设备操作系统的固件或引导加载程序等方式，将恶意软件加载到网络设备上。网络设备中被恶意篡改的软件可能会导致数据完整性破坏、敏感信息泄露甚至导致拒绝服务攻击 (DoS)。

NSA 建议：将文件的加密哈希值与供应商发布的哈希值对比，验证设备上安装和运行的操作系统文件的完整性。当升级操作系统文件时，请在安装前后对文件执行相同的完整性校验，以确保未进行任何修改。 可以使用以下 执行命令在操作系统映像文件上计算基础在线哈希值：

verify /md5 <PATH:filename>

计算出的哈希值可以与在的支持页上为该文件发布的信息进行比较https://www.cisco.com/[9]. 有关网络设备验证的更多信息，请参阅“网络设备完整性（NDI）方法”、“Cisco IOS设备上的网络设备完整性（NDI）”和“验证硬件和软件的完整性”文档[10]、[11]、[12]。

和这些复杂的软件修改相比，攻击者可能会选择用简单方式修改配置。配置被修改可能是设备受损的标志。

NSA还建议实施配置变更流程，通过检测恶意修改，安全地创建设备配置备份。当需要变更配置时，记录变更内容包括授权人、变更目的和变更原因。将当前设备配置与最近的备份配置进行比对来定期验证是否未应用修改。如果观察到可疑变更，请验证变更是否得到授权。

3.2 维护正确的文件系统和引导管理

升级操作系统到最新版本，由于修复了已出现的关键漏洞和安全问题，新版本往往更加可靠。 长期未更新的操作系统或易遭受攻击的设备更容易受到各种已发布漏洞的影响，利用这些设备是攻击者用来入侵网络的常用技术。

NSA 建议将所有设备上的操作系统和软件升级到供应商提供的最新稳定版本。 升级操作系统可能需要额外的硬件或添加内存，获得新的软件版本可能需要与供应商签订维护或支持合同。大多数网络基础设施的设备不支持自动更新功能，因此有必要向供应商提出申请安装最新版本。

有关最新 Cisco 操作系统文件的列表，请参阅支持页面，网址为

https://www.cisco.com/

3.3 维护软件和操作系统最新版本

把操作系统和软件升级到最新稳定版本，可以解决老版本中已经发现并修复的漏洞和安全问题。继续运行老版本的操作系统或有安全隐患软件容易遭受各种利用已发布漏洞的攻击，利用这些有脆弱性的设备攻击网络是一种常见的攻击手段。NSA建议将所有设备上的操作系统和软件升级到供应商提供的最新稳定版本。

升级操作系统可能会需要额外的硬件或内存升级，获得新的软件版本也可能需要与供应商签订维护或支持合同。大多数的网络基础设施设备不支持自动更新功能，因此软件的版本升级更新申请和安装流程都需要设备供应商支持配合。

有关最新的Cisco操作系统文件列表，请参见https://www.cisco.com/。

3.4 了解供应商支持的硬件的最新情况

供应商最终会停止支持特定的硬件平台，如果这些设备出现故障，将无法进行维修。除了设备不稳定和额外内存增加内存，还有个风险，攻击者会利用未及时更新软件导致存在未修复漏洞的设备。

最新版且在供应商维保支持的硬件平台具有改进的安全功能，常常修复了已知漏洞。一旦供应商发布终止使用通知或宣布不再支持设备，NSA 建议制定设备升级或更换计划 ，根据供应商的建议，立即升级或更换过时或不受支持的设备，以确保网络服务安全性和可用性。

有关受支持的 Cisco 设备的列表，请参阅 https://www.cisco.com/ 上的支持页面。

4. 认证、授权和计费 (AAA)

集中式 AAA 服务器提供了一种统一的机制来管理对设备的管理访问，并且攻击者在设备上创建的帐户也更具挑战性，因为凭据不直接存储在设备上。 正确配置AAA服务器为管理和监控设备提供了权威来源，提高了访问控制的一致性，减少了配置维护，并降低了管理成本。 应首先使用以下 Cisco IOS 设备配置示例命令将所有设备配置为使用现代 AAA 服务：

aaa new-model

应用以上配置命令可确保设备不会使用旧的认证和授权方法。

4.1 部署集中式服务器

所有设备都应配置为使用集中式 AAA 服务器。 NSA 建议在网络上至少部署两台 AAA服务器以确保可用性，并协助检测和预防对手活动。如果其中一台服务器因计划维护或其他原因不可用，其余服务器将继续提供集中式 AAA 服务。 服务器应该是：

  * 为设备配置唯一且复杂的预共享密钥进行身份验证，以确保只有授权设备才能使用 AAA 服务（请参阅 5.6 创建强密码）。
  * 配置相同的协议（例如，TACACS+、RADIUS 或 LDAP）以保持一致性，并在支持时使用加密传输（例如，RadSec、Diameter、LDAPS 或 IPsec 封装）。
  * 相互同步确保用户凭据和访问控制的一致性。

可以使用以下配置命令配置具有多个 AAA 服务器的服务器组：

aaa group server {tacacs+ | radius | ldap} <GROUP_NAME>

server-private <IP_ADDRESS_1> key <KEY_1>

server-private <IP_ADDRESS_2> key <KEY_2>

一些较旧的设备可能会在配置中使用关键字 “tacacs-server” 和 “radius-server”，这会阻止为每个服务器分配唯一的密钥。NSA 建议将这些行替换为上述配置格式，并为每个服务器分配一个唯一的预共享密钥。 如果攻击者获得了一个服务器的预共享密钥，则需要撤销该密钥，但设备可以继续使用具有不同密钥的其他服务器。

4.2 配置验证

认证机制验证个人或实体的身份信息。 所有设备都应首先配置为使用集中式服务器提供 AAA 服务，如果所有集中式服务器都不可用时，才使用本地管理员帐户作为备用。

这同样适用于特权级身份验证； 如果所有集中式服务器都不可用，设备应仅使用本地特权级密码。 这种优先顺序将阻止攻击者登录设备获得本地管理员帐户凭据，因为访问通常由 AAA 服务器集中控制。

NSA 建议将登录和启用（特权）访问配置为集中式身份验证作为主要方法，如以下配置命令所示：

aaa authentication login default group <GROUP_NAME> local

aaa authentication enable default group <GROUP_NAME> enable

使用在没有指定显式身份验证列表时，默认关键字可确保所有实例中全局应用配置。 如果改为使用自定义命名列表，则有必要将此列表显式应用于 AAA 所在的所有实例。如果使用自定义命名列表，则需要明确地将此列表应用于AAA所在的所有实例，可能会导致某些管理服务配置错误，并可能受到影响。

当自定义命名列表未明确应用，会始终应用默认列表。<GROUP_NAME> 应该是 AAA 服务器组（之前定义）的自定义名称，其中包括集中式 AAA 服务器的 IP 地址及其关联的密钥。不要使用Line关键字，因为这些密码没有安全地存储在配置中，不能提供责任担保。永远不要使用 none 关键字，因为它会禁用身份验证。

4.3 配置授权

授权会验证个人或实体是否有权访问特定资源或执行特定操作。 组织、场景和设备用途将决定授权的管理员命令。 至少授权应该是 应用于启动 命令行会话（shell）和执行其他 shell 命令，包括配置命令。

NSA建议适当的限制合法管理员被授权执行的操作，以防止对手对被泄露的帐户执行未经授权的操作。大多数管理员使用1级权限进行用户级访问，使用15级权限进行特权级访问。授权应该应用于这两个级别，以及管理员使用以下配置命令使用的任何其他特权级别:

aaa authorization exec default group <GROUP_NAME> local

aaa authorization commands 1 group <GROUP_NAME> local

aaa authorization commands 15 group <GROUP_NAME> local

aaa authorization config-commands

应该使用默认列表来确保在任何地方都应用配置。<GROUP_NAME> 应该是 AAA 服务器组（之前定义）的自定义名称，其中包括集中式 AAA 服务器的 IP 地址及其关联的密钥。

如果需要可以在 local 关键字之后应用 if-authenticated 关键字。 如果管理员成功登录并且所有集中式 AAA 服务器不可用，他们将不再被授权执行命令， if-authenticated 关键字确保经过身份验证的用户将继续被授权执行命令。但是要谨慎使用此关键字，因为它可能会为管理员提供超出集中式 AAA 服务器上配置的访问权限。还有一点，永远不要使用 none 关键字，因为它会禁用授权。

4.4 配置计费

计费记录所有访问的相关资源或执行的操作，让管理员承担责任。 等到事件结束来生成计费记录是不够的，因为在生成记录之前，特定操作可能需要特别长的时间才能完成。 计费记录可以采用多种事件类型来收集，但取决于组织需求和设备使用目的。

NSA 建议集中记录系统配置变更，并实施一个管理流程来定期审查这些记录以检测潜在的恶意活动。 在启动和停止 命令行会话 shell脚本 命令时收集计费记录。 与授权类似，计费命令必须使用以下配置命令应用于所有管理员权限级别：

aaa accounting exec default start-stop group <GROUP_NAME>

aaa accounting commands 1 default start-stop group <GROUP_NAME>

aaa accounting commands 15 default start-stop group <GROUP_NAME>

应该使用默认列表来确保在任何地方都应用配置。<GROUP_NAME> 应该是 AAA 服务器组（之前定义）的自定义名称，其中包括集中式 AAA 服务器的 IP 地址及其关联的密钥。

4.5 应用最小权限原则

最小权限是一个安全概念，当执行对个人或实体的访问任务时只授权所需的最低权限级别。许多常见任务不需要特权级别的访问，例如查看网络接口的状态或查看路由表。要实现最小权限，管理员一开始就应该使用所需的最低权限级别登录。这提供了一个额外的安全层，对手必须绕过它才能完全破坏设备，它还可以防止管理员无意中对设备进行配置更改。

NSA 建议将所有帐户配置为权限级别 1 或 0，当管理员要提升到更高的权限级别以执行所需的任务，需要输入额外的凭据。应定期审查特权级别使用情况，并删除不必要的访问，以防止在较低特权级别上疏忽大意而使用特权级别命令。

可以使用 privilege 关键字更改单个本地帐户的权限级别。 使用以下配置将本地帐户分配给权限级别 1。

命令如下：

username<USER_NAME> privilege 1

注意：这不会更改帐户密码。

管理员帐户以权限级别 1 登录的，都需要执行 enable命令并提供额外的凭据以提升到更高的权限级别。 查看所有本地管理员帐户并确保为其分配了最低权限级别，还需要查看在集中式 AAA 服务器上配置的所有帐户权限级别。

同样的理念也应用于控制台 (CON)、辅助 (AUX) 和虚拟电传 (VTY) 线路。 正确配置 AAA 授权时，不应该依赖于线路的配置。 使用以下配置命令将行配置为最低权限级别：

line con 0

privilege level 1

line aux 0

privilege level 1

line vty 0 4

privilege level 1

line vty 5 15

privilege level 1

根据设备的不同，可能还需要对其他线路应用类似的配置。 如果特定设备上不存在 VTY 行 5 到 15，则无需执行这些命令。

4.6 限制身份验证尝试

通过引入限制身份验证尝试的次数和登录延迟，可防止攻击者对设备实施暴力密码破解以尝试获取访问权限。

NSA 建议使用以下 Cisco IOS 设备的配置示例命令，将失败的远程管理登陆尝试限制在最多三个或更少：

aaa authentication attempts login 3

相同理念SSH会话登陆应使用以下配置命令，将限制失败尝试三次或更少：

ip ssh authentication-retries 3

NSA 还建议在每次登陆之间设置至少一秒的延迟，使用以下配置会显著限制暴力破解尝试。命令如下：

login delay 1
