渗透测试之我理解的信息收集和大佬的信息收集
2022-10-13 20:31:33

我所了解的信息收集内容：

  * 确定范围
      + 在我们拿到一个测试的目标后，首先能够确定的是测试范围。
  * 使用whois查询，对域名进行查询，这里能获得一些敏感信息，如：
      + 注册人信息

      + 可能会有管理者邮箱或者电话号码（只是可能）

  * 使用爱企查，天眼查，小蓝本等工具对域名所拥有者（一般是公司）进行查询，这里可以收集到
      + 法人
      + 公司电话信息（可能是网站管理者，也可能只是公司固定电话）
      + 邮箱信息（从邮箱后缀，可猜测到是否存在邮箱服务器等）
      + 地址
      + 官网和其他网站备案信息（有可能其他域名也在同一台服务器上）
      + 股东信息，主要成员（一搬主要人员都会具有公司中的系统很大一部分权限）
      + 具体的公司经营情况，和业务范围（可能对业务逻辑有用，至少要知道对方是做什么的，在你看来这个系统的逻辑是什么样）
      + 等等

  * 子域名查询,优先检测是否存在dns域传送漏洞，若存在，可以直接拿到所有子域名（但是一般都不存在，但还是需要测试下，万一呐）

      + 这里使用工具，可以得到很多的子域名url，需要进一步进行筛选，筛选出可用的url或者特殊状态码的url，比如403的url
      + 使用各种搜索引擎，进行搜索，比如google，fofa，钟馗之眼，shodan等等
      + 将各种工具和搜索引擎所拿到的各种URL进行整合（整合的时候最好将url对应的IP也一起整理）和分类（比如登录接口，403，或者特殊连接，比如某中间件的管理页面，或者phpinfo页面）
  * 域名url验证和简单识别cms
      + 子域名连接收集完之后，再一次验证URL是否有效，并使用工具，可以简单验证是否存在cms，可以使用的工具（EHOLE,Glass，两款工具都会进行指纹识别），若存在cms，优先测试cms，可能历史漏洞并没有修复
      + 不存在cms时，整理好链接，从头开始往下简单测试，期间可能遇到多个url对应的是一个网站，这样就需要再一次筛选。
      + 整理url对应的IP，一般工具像oneforall，灯塔系统，都会存在识别cdn和整合C段的功能（但一般不建议后面直接扫描C段）

  * 搜集敏感信息，这里先不要去管有没有存在CDN，后面再说

      + 使用谷歌语法，直接使用site:域名 +filetype:等方式进行敏感词汇搜索，鬼知道能搜到什么，反正搜一搜就是了
          o 同样使用谷歌语法搜索github上的东西，不要以为github搜索语法中的site:github.com smtp @xxx.com的搜索方式是github上的，这是谷歌语法来搜索邮箱的。很多网站说的github搜索方式，永远不会给你说，这个是在google里面进行搜索
      + 敏感邮箱的获取方式
          o 谷歌语法
          o hunter.io
          o 其他网站，网上存在
          o 0.zone(零零信安)
          o 工具teemo
          o 工具theHarvester

      + Github上搜索代码或者直接搜索域名相关

          o 可能存在用户名什么
          o 也可能存在公司使用者
          o 还可能存在公司业务代码
          o 鬼知道别人上传了什么
          o 也可能什么都没有

      + 电话号码，账号，密码

          o 可以在对方官网上查看（多看下对方官网上的公告什么的，有时候收集完，都不知道别人是做什么的，唉，还是要多了解下对象）
          o 有注册的地方直接注册，一般的系统都是存在注册点的，只不过可能对方隐藏了，或者说未开放，对于未开放的，鬼知道在什么地方，反正在登录地方，打一个register路径试下，万一出现了，能注册就注册，老师讲的，登录后的漏洞永远多于登录前的，可能运气好就有了

          o 一般不存在什么可以搜索到的账号，密码，除非你是天选之子，随便搜搜都能搜索到对方的账号密码表，且还暴露了，且在你之前都没有人搜索到过，想想都感觉（天*真无邪）

      + 云盘搜索

          o 谁知道有没有人，将公司资料，或者自己账号密码，保存到云盘上，且还公开（可能是离职人员），关键是公司还没有禁用离职账号，或者存在默认账号什么的，又那么巧合的默认账号没改的人又存在，唉，幻想可*真*美好

      + wiki百科

          o 想不到吧，还有百科都能上搜索。想想看到的新闻，一个人玩游戏都能创造els战争历史，鬼知道，有没有人将此公司的信息在上面公布，且数据还没被现在的管理人员更新，又那么巧合的是，发现了，然后登陆了。鬼知道得不得行哦，试试查询又不犯法
      + 近源渗透（最好不要想，除非你是此公司的），当然直接社工也不要想，鬼知道现在判定电信诈骗的会不会算在你头上。除非你有好朋友在那上班，又刚好他又不注意的泄露了信息，又刚好被你听见了，又刚好那个系统的链接你又知道，那么刚刚好你就进去了，当然是用你朋友的账号，然后你朋友因为泄露信息，被惩罚或者通报了，而你却完成了任务。唉，果然又是一个打翻友谊船的好方法。

  * CDN

      + 绕过CDN，有很多种方法，尤其是一大佬专版写了N种方式，但是看不懂，就很伤，粘贴上大佬链接，https://www.anquanke.com/post/id/227818，大佬对于cdn都总结了三板，可怕不可怕，弱小的我只能在边角看看，然后默默收藏，加关注。

  * 到了这里，基本上就可以打开浏览器，打开burp，开始测试

      + 但请注意，大型网络对于工具存在指纹识别，并且burp上有默认的被动扫描，在不知道，或者默认情况自己不能控制的时候，最好关闭，或者设置线程数。
      + 

      + 默认为10线程，基本上不会有人和你讲为什么有时候，我刚打开burp，然后点击了几个对方官网上的菜单，然后就被屏蔽了。你认为你自己没有对其怎么样，但是实际上，你点击一个菜单，被动扫描已经开始了每秒10次的发送请求包，然后你就被waf唧唧了。最后你发现你不知道的，还是那么多，甚至可能，你在偶然间登录别人后台后，用的不是你的账号，然后你点击了菜单，可能是创建什么模板或者账号，不好意思，垃圾信息或垃圾模板将会充满对方的账户中，甚至还可能对对方网站添加了很多模板。这个时候，你如果不清理干净，你想想后果（没有授权，就可能完蛋）。所以请在得到授权后再进行测试吧。

      + 如果是自己创建的账号，并且有授权，那么被动扫描开了也就开了，到时候对数据进行清理就完事了。

  * 回归正题，在我们了解官网的时候，可以开始对其IP进行端口扫描，使用在线的，或者使用nmap进行扫描（注意nmap也会发大量的请求包，并且也存在指纹）。授权的可以直接使用awvs，appscan进行扫描了。当完成扫描后，可以知道对方的系统，中间件，语言可以使用浏览器插件进行查看，或者对方网址路径会暴露，或者不存在的路径会暴露错误信息。反正各种方法，了解就行

  * 

  * 最后使用学到的各种乱七八糟的功能模块测试，业务逻辑测试（什么验证码绕过啊，重置密码，忘记密码，支付接口等）或者各种参数测试，输入输出点测试，各种测试，能找到漏洞的，就找到了，找不到的，只能望洋兴叹。“为什么这么难，难，难，难于上青天。”
