6. 远程日志记录和监控

日志是记录设备运行和溯源网络安全事件的一种重要机制，管理员查看日志分析可疑活动并调查事件。如果设备日志记录配置不完整会导致日志信息丢失或不准确，并且难以关联设备或网络上发生的事件进行正确分析。正确的日志记录包括将日志发送到多个远程日志服务器，将时钟同步到多个经过身份验证的时间源，以及实施日志管理策略和过程。安全信息和事件管理（SIEM）系统可用于归集和分析远程日志服务器接收的日志。

应按照管理和预算办公室（OMB）备忘录M-21-31[14]的建议保留日志。

6.1 启用日志记录

开启日志记录时，网络设备才会生成日志消息。应将设备配置为将日志消息发送到本地日志缓冲区和集中收集日志的服务器。NSA建议启用syslog日志记录，将本地日志缓冲区设置为16 MB或更大，并建立一个程序来验证定期接收和查看日志。大多数设备应该能够支持更大的缓冲区大小，但如果内存不足，则可以针对特定设备减小缓冲区大小。确保使用以下配置命令启用系统日志记录：

logging on

使用以下配置命令增加最大本地日志缓冲区：

logging buffered 16777216 informational

注意：这也会将日志记录级别更改为信息级别，因为这两个值必须同时设置。

6.2 建立集中式远程日志服务器

日志消息发送到远程日志服务器确保不容易被泄露或删除，在设备泄露、重新启动或本地日志缓冲区已满时，这些消息也不会受到影响。在防御拒绝服务攻击影响和减少单点故障时，多个日志服务器至关重要。

NSA建议至少建立两个远程集中日志服务器，以确保设备日志消息的监控、冗余备份和可用性。如果设置支持加密功能，在日志传输过程进行加密，防止未经授权泄露敏感信息。在Cisco IOS设备上出站系统日志消息要通过在设备和远程系统日志服务器之间创建IPsec隧道进行加密，如2.6限制和加密虚拟专用网络（VPN）中所述。使用以下配置命令配置至少两个远程日志服务器：

logging host <IP_ADDRESS_1>

logging host <IP_ADDRESS_2>

6.3 获取必需的日志信息

配置完善设备上产生的日志中可以为管理员提供了事件分析所需的信息，包括关联多个相关事件或与其他设备上发生的事件。

NSA建议将每个设备上的trap和缓冲区日志记录级别至少设置为系统日志级别“信息”（代码6），收集所有必要的信息。可以将设备配置为“调试”（代码7），这样生成的消息数量会增加很多可能会对日志检查过程造成影响。使用以下配置命令将陷阱和缓冲区日志记录级别设置为信息性：

logging trap informational

logging buffered 16777216 informational

请注意！这将设置本地日志缓冲区的最大容量，因为这两个值必须同时设置。

还可以分别使用console和monitor关键字在console和VTY行上启用日志记录。这些方法将立即通知已登录的管理员，但不会保留消息。除非管理员需要，否则没有必要为这些方法启用日志记录。可以使用以下配置命令禁用它们：

no logging console

no logging monitor

NSA还建议对时区使用世界标准时间（UTC），特别是当网络跨越多个时区时。所有日志消息都应该包含一个正确配置的时间戳，带有完整日期（包括年份）、时间（包括秒和毫秒）以及时区。确保时区设置正确，并使用以下配置命令启用上面列出的所有功能：

clock timezone UTC 0 0

service timestamps log datetime msec localtime show-timezone year

service timestamps debug datetime msec localtime show-timezone year

最后，NSA 还建议启用日志消息以提示用户何时成功或未成功登录系统。即使在正确配置计费功能情况下，这些事件会记录在集中式 AAA 服务器上，不会记录在本地缓冲区中。 确保使用以下配置命令记录这些事件：

login on-failure log

login on-success log

6.4 同步时钟

网络时间协议 (NTP) 用于在全球范围内同步设备时钟，并确保包含在日志消息中的时间戳的精准性。 为了保障可靠性，每个设备至少两个可信时间源同步。 确保日志消息时间戳可以在地理上分散的时区之间轻松关联，并用于不同设备之间的网络事件关联分析至关重要。

NSA 建议每台设备和远程日志服务器至少使用两个可信赖且可靠的时间服务器，确保日志信息的准确性和可用性。内部时间服务器应设置为所有设备时间的来源，要与权威的外部时间源同步。 这种设计可减少了外部请求的数量，并在无法访问外部时间服务器的情况下确保时间戳的一致性。 在网络上部署时间服务器时，管理员应确认设备能够访问时间服务器，并且在应用配置后时钟同步。 NSA 还建议在所有设备上启用 NTP 身份验证以防止时钟篡改，并在设备及其指定时间源之间配置健壮且唯一的 NTP 身份验证密钥。

使用以下配置命令建立可信 NTP 密钥并启用 NTP 身份验证：

ntp authentication-key <#1> md5 <KEY>

ntp trusted-key <#1>

ntp authentication-key <#2> md5 <KEY>

ntp trusted-key <#2>

ntp authenticate

可以建立任意数量的可信密钥。 请注意，NTP 身份验证密钥将作为类型 7 密码存储在配置中。 NTP 身份验证不支持类型 6 AES 加密的密码。

使用以下配置命令将设备与至少两个不同的 NTP 服务器同步：

ntp server <IP_ADDRESS_1> key <#1>

ntp server <IP_ADDRESS_2> key <#2>

注意：每个命令末尾的数字是用于验证该特定服务器的可信 NTP 密钥。

等待时钟同步后，使用以下 exec 命令验证 NTP 服务器的同步和状态：

show ntp status

show ntp associations

注意：每次 NTP 配置更改后都需要验证时钟同步，正确同步可能需要几个小时。

7. 远程管理和网络服务

管理员可以通过各种服务远程管理网络设备。 一些常见的网络服务包括 SSH、超文本传输协议 (HTTP)、SNMP 和文件传输协议 (FTP)等。 这些服务对管理员非常有用，但同时也是攻击者的目标，利用这些服务可获得对设备的特权级访问权限。 远程管理服务必须正确配置，降低被攻击的可能性。

7.1 禁用明文管理服务

明文协议以“明文”（即未加密）的方式通过网络传输，这是在之前未广泛使用加密措施之前设计的。使用这些明文协议远程管理关键设备可能会导致信息泄露，所以会对设备和网络安全产生不利影响。 攻击者通过常见的数据内容还原技术（例如，网络分析器或数据包捕获实用程序）收集用户名、密码、配置信息和其他敏感数据，可以破坏网络安全。

NSA 建议使用加密服务来保护网络通信，禁用所有明文管理服务（例如 Telnet、HTTP、FTP、SNMP 1/2c）。这确保了敏感信息不能被捕获网络流量的攻击者轻易获取。 关于如何启用加密服务的详细信息，请参见7.11 网络服务配置。

如果设备不支持加密协议，可将管理系统直接连接到控制台或管理端口，或建立专用的带外管理网络，有效降低攻击者捕获明文协议的能力。 使用以下配置命令禁用 Telnet 服务：

line vty 0 4

transport input none

line vty 5 15

transport input none

根据设备的不同，可能还需要对其他线路应用类似的配置。 如果特定设备上不存在 VTY 行 5 到 15，则无需执行这些命令。 请注意，这些命令还可能禁用默认情况下在线路上启用的其他服务，包括 SSH。 有关如何启用 SSH 的详细信息，请参阅 7.11.1 网络服务配置 SSH。 使用以下配置命令禁用 HTTP 服务：

no ip http server

有关如何启用安全 HTTP 服务的详细信息，请参阅7.11.2 网络服务配置 HTTP。

通过使用以下配置命令删除任何已配置的团体字符串来禁用 SNMP 和 SNMP 陷阱服务的版本 1 和 2c：

no snmp-server community <COMMUNITY_STRING>

no snmp-server host <HOSTNAME_OR_IP_ADDRESS> <COMMUNITY_STRING>

有关如何启用 SNMP 版本 3 的详细信息，请参阅 7.11.3 网络服务配置 SNMP。

通过使用以下配置命令来禁用简单文件传输协议 (TFTP)：

no tftp-server <FILENAME>

FTP服务一般不作为监听服务启用，但可以作为客户端使用。 使用以下配置命令删除 FTP 凭据：

no ip ftp username

no ip ftp password

7.2 确保足够的加密强度

一些加密服务要求生成一对公钥和私钥，这样客户端就可以连接到服务器并对其进行身份验证。 加密连接的客户端和服务器还可以为每个唯一连接共同建立一个私有会话密钥。 使用脆弱的算法或短比特位秘钥的加密连接，让攻击者更容易破解私有会话密钥，就可以解密在连接期间传输的所有数据。

有关NSA批准用于国家安全系统（NSS）的算法和密码的指南，请参阅CNSSP 15[4]。IETF关于互联网协议安全（IPsec）的商业国家安全算法（CNSA）套件加密、TLS和DTLS 1.2和1.3的商业国家安全算法（CNSA）套件配置文件，以及安全外壳（SSH）的商业国家安全算法（CNSA）套件加密的文件草案中解释了CNSSP 15要求[5]、[15]、[16]。

有关非NSS美国政府系统的相关要求和指南，请参考NIST SP 800-52第2版附录F[17]。

这些文档包含最新推荐的加密参数。NSA建议将3072位或更高的比特用于不对称（公共和私人）密钥生成，384位用于椭圆曲线加密（ECC）密钥，256位用于对称加密密钥。有些系统可能不支持3072位，所以可能是这样必须使用4096位。对于任何密钥长度较小的设备，要重新生成新密钥对，并将加密协议配置为仅使用已批准的密钥算法。较大的密钥长度可能会增加连接到服务的时间（由于额外的计算），但在大多数设备上可以忽略不计。有关配置加密服务，请参阅7.11网络服务配置。

7.3 使用安全协议

一些常见管理服务的协议实现在信息的使用和交换中存在缺陷，存在被攻击者利用的风险。一些协议（例如SSH）可以配置为向后兼容，并接受较旧的不安全协议和较新的协议。较旧的协议存在中间人利用风险，这种技术可能会强制客户机和服务器协商采用脆弱的算法，这点往往没有用户意识到。

NSA建议管理服务使用最新版本的协议，并充分启用合适的安全设置。SSH版本2是远程访问设备的首选方法。加密的HTTP服务器应配置为仅接受传输层安全性（TLS）1.2或更高版本。有关将服务限制在协议特定版本的更多信息，请参阅7.11网络服务配置。

7.4 限制对服务的访问

如果允许大量设备可连接到管理服务，它们就更容易受到攻击。 NSA 建议将 ACL 配置为仅允许管理员系统连接到设备以进行远程管理。 不支持 ACL 能力的设备应放置在单独的网络管理段（例如 VLAN）上。 应将 ACL 应用于该 VLAN 或入口路由器，以限制对该网段的访问。 可能需要在关键网段前面实施单独的防火墙，以限制哪些系统可以连接到该 VLAN。 考虑使用动态主机配置协议 (DHCP) 的替代方案； 为管理员系统分配静态 IP 地址或使用较小的地址池。 静态地址将使定义 ACL 和限制对管理服务的管理访问变得更加容易。

大多数管理服务只接受标准 ACL。 使用 permit 关键字可以在附加行中列出多个设备或网络。 即使每个 ACL 在最后都有一个隐含的拒绝语句，最好还是明确地包含它，以便记录拒绝的尝试。 使用以下配置命令创建标准 ACL 仅允许管理员使用的 IP 地址：

access-list <ACL#> permit <NETWORK> <WILDCARD_MASK> log

access-list <ACL#> deny any log

有关如何将 ACL 应用于特定管理服务的更多信息，请参阅7.11 网络服务配置。

NSA 还建议从配置中删除已经不使用的 ACL，因为它们会使管理员误以为它们被正确应用。 验证标准 ACL没有被应用后，使用以下配置命令将其删除：

no access-list <ACL#>

7.5 设置合适的超时时间

为空闲连接设置超时时间，允许会话在规定的不活动时间后自动关闭。 未设置超时期限或设置的时间过长，则空闲连接可能会无限期地等待，如果在设备上设置了并发连接限制，甚至会导致 DoS。 DoS 将一直持续到达到空闲超时期限，如果已禁用空闲超时，则该期限可能是无限的。 较长的超时时间为攻击者提供了更多的时间来劫持空闲的会话。

NSA 建议在所有远程设备上将管理连接的会话超时设置为五分钟或更短（例如，VTY 线路、SSH、控制台和辅助端口上的 exec-timeout）。 不要将超时时间设置为零，因为大多数设备会通过此设置禁用超时功能。 有关限制特定管理服务的会话超时的更多信息，请参阅7.11 网络服务配置。

7.6 启用传输控制协议 (TCP) 保活

从设备发送和接收的 TCP 保持活动消息，给定时间范围内未发生任何活动时进行评估连接状态。 这些消息可检测连接中的意外丢失并减轻潜在的网络危害。 在某些设备上，缺少 TCP 保持连接服务会导致已建立的 TCP 连接，在另外一端意外连接丢失后仍保持打开状态，从而使会话容易被劫持。 此外，保活报文可能不需要身份验证，特别是对于未加密的连接，攻击者可以简单地恢复会话，可获得特权级访问权限。 NSA 建议使用以下配置命令为所有 TCP 连接的入站和出站消息启用 TCP 保持活动设置：

service tcp-keepalives-in

service tcp-keepalives-out

请注意，某些设备不支持 TCP 保持活动消息的配置。

7.7 禁用出站连接

通过管理端口对设备进行身份验证后，用户通常可以通过支持的协议（例如 Telnet 和 SSH）远程连接到网络上的其他系统。 如果对手能够破坏设备或使用管理员帐户获得用户级别的访问权限，则此出站连接可能会被用于进一步的网络攻击。正确检查设备配置并利用 ACL 可以防止未经授权的系统访问网络资源。

NSA 建议使用以下配置命令禁用出站连接以限制攻击者在网络中活动：

line con 0

transport output none

line vty 0 4

transport output none

line vty 5 15

transport output none

根据设备的不同类型，可能还需要对其他线路应用类似的配置。 如果特定设备上不存在 VTY 行 5 到 15，则无需执行这些命令。 请注意，必须在控制台行上明确禁用此功能。

如果需要出站连接将文件复制到设备或从设备复制以进行维护或完整性验证，请将其限制为仅 SSH 并限制可以通过出站 ACL 访问的设备数量； 任务完成后恢复到上述配置。

7.8 删除 SNMP 读写团体字符串

SNMP V1或 V2c 读写团体字符串类似于密码，用于访问或修改设备配置和操作系统文件， 这些操作通常不能使用只读团体字符串来完成， 因为 SNMP 读写团体字符串以明文形式发送，它们可以被对手利用获得对网络设备的完全控制权。

NSA 建议删除所有 SNMP 读写团体字符串，并且升级到具有加密和身份验证功能的 SNMP V3版。 如果远程管理需要版本 1 或 2c SNMP 读写团体字符串且无法删除，则建议设置读写团体字符串与其他团体字符串要明显不同，以防止被攻击者猜解。如果要获得只读团体字符串，可以使用以下运行命令列出所有版本 1 和 2c SNMP 团体字符串：

show running-config | include snmp-server community

注意：读写团体字符串将包含 RW 关键字，而只读团体字符串将包含 RO 关键字。

使用以下配置命令禁用 SNMP 读写团体字符串：

no snmp-server community <COMMUNITY_STRING>

7.9 禁用不需要的网络服务

在设备的初始安装过程中，默认启用了一些 TCP 和 UDP 服务，但是这些往往对于正常操作来说是不必要的。 这些服务启用会降低网络的安全级别，为攻击者提供额外的访问点来利用设备，使其容易受到未经授权的监控、信息收集和破坏。

例如，思科智能安装服务（ Cisco Smart Install）通常是用不上的，但启用该服务后，远程攻击者未经身份验证就可以使用此服务获取设备的配置文件、上传新的配置或操作系统映像文件和强制重启。 这已在 Cisco 的安全公告 cisco-sa-20170214-smi 中记录为滥用协议，但安全社区已发现并承认此问题是攻击者利用该漏洞通过 Internet 获取配置文件的严重漏洞 [18]， [19]。

NSA 建议在每台设备上禁用所有不需要的服务。 如果服务是必需的并且可以支持密码和 ACL，请根据 NSA 的强密码指南创建密码（请参阅 5.6 创建强密码），并且应用 ACL 只允许所需系统连接到服务。 如果设备不支持 ACL，可以将其移至单独的 VLAN，然后将 ACL 应用到 VLAN。NSA 还建议立即使用以下配置命令在所有设备上禁用 Cisco Smart Install 服务：

no vstack

尽管该服务是为交换机设计的，但路由器也可以配置为 Cisco Smart Install director； 因此，应该在所有设备上明确禁用它，最好初始化安装配置就设置禁用。

使用以下配置命令禁用其他不需要的 TCP 和 UDP 服务：

no service tcp-small-servers

no service udp-small-servers

no service finger

7.10 在特定接口上禁用发现协议

Cisco 发现协议 (CDP) 和链路层发现协议 (LLDP) 是广播协议，它们定期向支持该协议并正在侦听数据包的相邻设备通告网络拓扑和设备信息。 此功能默认启用，对于管理员获取有关网络的信息很有用，但对于想被动收集网络配置信息的攻击者也非常有用。 能够在网络中部署嗅探器的攻击者可以收集设备型号、操作系统版本、VLAN 信息以及物理和逻辑地址等，获得有价值的信息来渗透利用网络上的设备。

NSA 建议禁用 CDP 和 LLDP。 如果网络通信需要服务（例如，某些 Cisco IP 语音 (VoIP) 电话），请仅在需要该协议的设备之间的点对点链路或启用语音的端口上启用它。 可以使用以下配置命令全局禁用 CDP 和 LLDP：

no cdp run

no lldp run

如果特定接口需要 CDP，则必须全局启用但在所有其他接口上禁用，如以下单个接口的配置命令所示：

interface <INTERFACE>

no cdp enable

7.11 网络服务配置

本节介绍如何正确启用常用的远程网络管理服务。

7.11.1 SSH

使用以下配置命令允许入站 SSH 连接：

line vty 0 4

transport input ssh

line vty 5 15

transport input ssh

注意：这可能会禁用线路上默认启用的其他服务，例如 Telnet。 如果特定设备上不存在 VTY 行 5 到 15，则无需执行这些命令。 根据设备的不同，可能还需要对其他线路应用类似的配置。

可以使用以下命令确认允许的输入传输：

show line <LINE> <LINE_NUMBER>

使用以下配置命令禁用 SSH 版本 1 连接，仅允许版本 2 的协议：

ip ssh version 2

使用以下配置命令为 SSH 生成新的非对称 (RSA) 密钥对：

crypto key generate rsa modulus 3072

注意：此命令将覆盖现有的 RSA 密钥对。

使用以下配置命令为 SSH 生成新的非对称 ECC（椭圆加密算法） 密钥对：

crypto key generate ec keysize 384

注意：此命令将覆盖现有的 ECC 密钥对。

使用以下配置命令将 Diffie-Hellman 长度最小值设置为 4096 位：

ip ssh dh min 4096

注意：某些系统不支持 3072 位的 Diffie-Hellman 密钥长度，因此建议使用 4096 位。

可以使用以下配置命令指定 SSH 协议接受的加密、密钥交换 (KEX) 和消息验证码算法（包括首选顺序）：

ip ssh server algorithm encryption <ALGORITHM> [<ALGORITHM> ...]

ip ssh server algorithm kex <ALGORITHM> [<ALGORITHM> ...]

ip ssh server algorithm mac <ALGORITHM> [<ALGORITHM> ...]

有关可接受算法的更多信息，请参阅 CNSSP 15 [4]。 CNSSP 15 的要求在 IETF 文件草案中关于用于SSH 的商业国家安全算法 (CNSA) 套件密码学 [16]中进行了解释。

可以使用以下运行命令确认 SSH 服务的配置：

show ip ssh

应用标准 ACL 只允许管理员使用以下配置命令使用的 IP 地址：

line vty 0 4

access-class <ACL#> in

line vty 5 15

access-class <ACL#> in

如果特定设备上不存在 VTY 行 5 到 15，则无需执行这些命令。 请注意，如果在线路上启用了此 ACL，它也将适用于 Telnet。 根据设备的不同，可能还需要对其他线路应用类似的配置。 有关创建标准 ACL 的更多信息，请参阅 7.4 限制对服务的访问。

使用以下配置命令将会话到期时间设置为 5 分钟或更短：

line con 0

exec-timeout 5 0

line vty 0 4

exec-timeout 5 0

line vty 5 15

exec-timeout 5 0

如果特定设备上不存在 VTY 行 5 到 15，则无需执行这些命令。 请注意，如果在线路上启用了 Telnet，这也适用于 Telnet。 根据设备的不同，可能还需要对其他线路应用类似的配置。

7.11.2 HTTP

如果 HTTP 用于管理目的，请使用以下配置命令启用 HTTP over TLS：

ip http secure-server

只接受 TLS 1.2 版用以下配置命令的：

ip http tls-version TLSv1.2

可以使用以下配置命令指定加密 HTTP 服务接受的密码套件（包括首选顺序）：

ip http secure-ciphersuite <CIPHERSUITE> [<CIPHERSUITE> ...]

有关可接受算法的更多信息，请参阅 CNSSP 15 [4]。 CNSSP 15 的要求在 IETF 文件草案中对 TLS 和 DTLS 1.2 和 1.3 [15] 的商业国家安全算法 (CNSA) 套件配置文件进行了解释。

应用标准 ACL 只允许管理员使用以下配置命令使用的 IP 地址：

ip http access-class <ACL#>

注意：如果启用此 ACL，它也将适用于明文 HTTP 服务。 有关创建标准 ACL 的更多信息，请参阅7.4 限制对服务的访问。

HTTP 服务器连接的默认空闲超时时间为 180 秒（三分钟），因此无需更改此值。

7.11.3 SNMP

如果使用 SNMP 进行网络管理，请使用以下配置命令启用具有身份验证和隐私（加密）的 SNMP 版本 3：

snmp-server group <SNMPv3_GROUP> v3 priv access <ACL#>

snmp-server user <USER> <SNMPv3_GROUP> v3 auth sha <AUTH_PASSWORD> priv aes

256 <PRIV_PASSWORD> access <ACL#>

首先必须定义一个组，其中 priv 关键字等同于 authPriv（身份验证和隐私）。 必须定义一个或多个用户并将其分配给一个组。 除了身份验证和加密参数之外，还必须为每个用户提供两个不同的密码，一个用于身份验证，一个用于隐私。

已发现到 AES-192 和 AES-256 的互操作性问题，因此可能需要使用 AES-128 进行加密，而不是使用带有 aes 128 关键字的 AES-256。 如上所示，通过在每个命令末尾使用 access 关键字将 ACL 指定为单独的选项，可以将 ACL 应用于组和每个单独的用户。

可以使用以下 shell 命令从 Linux 系统测试上述 SNMP 配置：

snmpget -v 3 -u <USER> -a sha -l authPriv -A '<AUTH_PASSWORD>' -x AES \

-X '<PRIV_PASSWORD>' <IP_ADDRESS> 1.3.6.1.2.1.1.5.0
