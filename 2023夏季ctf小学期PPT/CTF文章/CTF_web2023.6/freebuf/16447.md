1.前言

xxe漏洞之前只是粗略的学习过，并没有单独整理资料好好的总结下这个漏洞，于是想专门写个文章总结下关于xxe的知识

2.xml文档

xxe本质上来说就是xml实体注入，XML用于标记电子文件使其具有结构性的标记语言，可以用来标记数据、定义数据类型，是一种允许用户对自己的标记语言进行定义的源语言。XML文档结构包括XML声明、DTD文档类型定义（可选）、文档元素

所有的xml文档均由元素、属性、实体、PCDATA、CDATA构成

其中PCDATA代表此元素会被xml进行解析，而CDATA元素只会作为普通字符串数据

2.1DTD文档声明

DTD可以分为内部声明或者外部声明，内部声明即<!DOCTYPE 根元素 [元素声明]>

外部声明：<!DOCTYPE 根元素 SYSTEM "文件名">

2.2 DTD实体

DTD实体指的是定义字符或者解析字符的变量，可以内部声明和外部引用

实体分为一般实体和参数实体。

一般实体：<!ENTITY 实体名 "实体内容">，引用：&实体名;

参数实体：<!ENTITY % 实体名 "实体内容">,引用：%实体名; 参数实体只能在DTD中用

外部实体调用同上外部元素声明<!ENTITY 实体名称 SYSTEM "文件名">

如<!ENTITY abc SYSTEM "http://127.0.0.1/test.dtd"> &abc;


3. xml实体注入

3.1知道了xml的基本知识，来看看xml实体注入是怎么攻击的。

xml实体攻击其实是外部实体攻击，即通过引用外部的dtd实体来访问相应的敏感文件或执行其他操作

方式一：如访问/etc/passwd文件

方式二：或者先引入外部文档，再引入外部实体声明

方式三：先引入外部文档，然后定义外部实体，最后在本xml文档里面引用定义的外部实体

test.dtd文件内容

<!ENTITY b SYSTEM "file:///etc/passwd">

3.3可利用类型

（1）file:///etc/passwd读取文件内容，若不回显

(2) http://127.0.0.1:80探测端口是否开放

（3）引入公网服务器的poc攻击内网，如s2， http://127.0.0.1/s2-poc

(4)execpt://whoami 执行系统命令 except是php中执行命令的协议

(5)gopher协议配合ssrf反弹shell

4. 无回显的xxe

4.1 读取文件

首先要创建一个1.xml文档将数据传给公网的php文件

然后再2.php文件中将获取到的数据写入3.txt文件中保存

最后是在有xml注入点的地方引入xml外部实体文档，可以用php协议的base64加密文件数据，防止编码出错

这时候可以在3.txt文件中接收到base64编码的文件内容了

4.2 端口探测

<!DOCTYPE test [<!ENTITY xxe SYSTEM "http://127.0.0.1:80">]> 通过判断响应时间的长短判断是否端口开放


5.防御

防御xxe可以禁用DOCTYPE等敏感字符，或者禁用外部实体注入可以达到防止xxe漏洞的效果。
