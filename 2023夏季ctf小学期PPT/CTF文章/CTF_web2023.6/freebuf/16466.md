easypwn

glibc 2.31 堆下标溢出题目，与 2.31 关系不大，主要是 mmap 妙用

show 功能溢出：

delete 功能溢出：

泄露堆地址和 libc 地址属于是常规操作，malloc 不会清空残留指针

维持堆指针的列表 chunk_list 是存放在 mmap 分配的一个地址上。因为申请 size 没有上限，所以以 mmap 方式再申请一个堆块，将地址信息写到上面，这样就有一个确定的下标（两个 mmap 分配的堆块相对位置固定不变）。

利用思路两个：

 1. 伪造堆块造成堆重叠，攻击 tcache 覆盖 free_hook

 2. 直接攻击 tcache 管理堆块

题目名字忘记了

比赛原题是基于 glibc 2.27 旧版本，重点要利用 tcache double free 。启动脚本如下：

cd /home/ctf/Desktop/
#timeout --foreground -s 9 120s ./rachell
LD_PRELOAD=/home/ctf/Desktop/libc.so.6 timeout --foreground -s 9 30s ./chall

文件夹内容如下：

tree .
.
├── chall
├── libc.so.6
└── start.sh

调用的是当前目录下的 libc.so.6 ，这个文件是有权限覆盖的。现场过 1/4 队伍直接将 libc.so.6 替换成新版本的 glibc 2.27 就是带 tcache double free 检查的，直接好家伙，关键是还能过 check ，大大的回显报错退出free(): double free detected in tcache 2。

程序分析

程序是一个仿的终端，看上去是个终端，实际上是用堆和链表仿造的效果

程序有文件夹和文件两个概念，两者都是用 0xb1 和 0x31 大小的堆块表示，文件还有个存放内容的堆

UAF 在 rm 删除非当前目录下的文件时：

void __fastcall sub_rm(__int64 a1)
{
if ( (int *)a1 == &root )                     // 删除根目录
{
write(1, "not allowed\n", 0xCuLL);
return;
}
if ( *(int **)(a1 + 8) == cwd )               // 在当前目录
{
if ( *(_DWORD *)a1 )                        // 节点存在
{
if ( *(_DWORD *)a1 != 1 )                 // 类型是文件
panic();
if ( *(_QWORD *)(a1 + 0x98) )             // 文件内容堆存在
free(*(void **)(a1 + 0x98));            // 释放内容堆块
unlink_child(a1);
return;
}
LABEL_9:
unlink_child(a1);
free((void *)a1);
return;
}
if ( !*(_DWORD *)a1 )
goto LABEL_9;
if ( *(_DWORD *)a1 != 1 )                     // 节点不存在
panic();
if ( *(_QWORD *)(a1 + 0x98) )
free(*(void **)(a1 + 0x98));                // UAF
// 当删除不是当前文件夹下的文件是会触发
}

洞就是这么一个洞，然后麻烦的就是泄露地址输出上限制很烦人。程序能输出的有两个地方 ls 和 pwd 。

ls 输出限制必须要可见字符串，pwd 输出有两个分支，当父目录不是 root 时，进入 else 输出直接调用 write 没有限制可见字符串。
