Shiro权限绕过漏洞

环境

  * Shiro 1.5.1

  * Spring Boot 2.2.2.RELEASE

使用高版本Spring boot进行复现时复现失败，猜测是由于修改了Spring MVC的路径匹配策略导致导致的，希望有大佬解惑

MyRealm.java

public class MyRealm extends AuthorizingRealm {
    @Override
    protected AuthorizationInfo doGetAuthorizationInfo(PrincipalCollection principals) {
        return null;
    }
    @Override
    protected AuthenticationInfo doGetAuthenticationInfo(AuthenticationToken token) throws AuthenticationException {
        String username = (String) token.getPrincipal();
        if (!"admin".equals(username)) {
            throw new UnknownAccountException("账户不存在!");
        }
        return new SimpleAuthenticationInfo(username, "123456", getName());
    }
}


ShiroConfig.java

@Configuration
public class ShiroConfig {
    @Bean
    MyRealm myRealm() {
        return new MyRealm();
    }
    @Bean
    SecurityManager securityManager() {
        DefaultWebSecurityManager manager = new DefaultWebSecurityManager();
        manager.setRealm(myRealm());
        return manager;
    }
    @Bean
    ShiroFilterFactoryBean shiroFilterFactoryBean() {
        ShiroFilterFactoryBean bean = new ShiroFilterFactoryBean();
        bean.setSecurityManager(securityManager());
        bean.setLoginUrl("/login");
        bean.setSuccessUrl("/index");
        bean.setUnauthorizedUrl("/unauthorizedurl");
        Map<String, String> map = new LinkedHashMap();
        map.put("/login", "anon");
        map.put("/index", "anon");
        map.put("/admin", "authc");
        bean.setFilterChainDefinitionMap(map);
        return bean;
    }
}


Controller.java

@RestController
public class Controller {
    @RequestMapping("/login")
    public String login(String username, String password) {
        Subject subject = SecurityUtils.getSubject();
        try {
            subject.login(new UsernamePasswordToken(username, password));
            return "登录成功";
        } catch (AuthenticationException e) {
            e.printStackTrace();
            return "登录失败";
        }
    }
    @RequestMapping("/admin")
    public String admin() {
        return "admin";
    }
    @RequestMapping("/index")
    public String index() {
        return "index";
    }
}


复现

  * 访问anon权限页面

    可以正常访问

  * 访问authc权限页面

    重定向到登录页面

  * 构造url绕过身份验证

    未授权访问成功

分析

Shiro验证

详细的调用流程网上很多，这里只看关键的几个地方

首先是经过decodeAndCleanUriString处理，将uri以;截断，uri变为/xxx/..

接着是在getChain中以Shiro的路由过滤规则，对uri的权限做验证

由于/xxx/..不会匹配上/admin，所以在Shiro的权限验证中通过

Spring boot验证

经过Shiro的验证后，请求进入到Spring boot中进行验证，但由于传入Spring boot的uri是初始的uri(/xxx/..;/admin)，而不是经过Shiro过滤的uri(/xxx/..)，使得请求被解析为对/admin的访问，从而绕过了Shiro的权限验证

Tomcat URL解析漏洞

Shiro权限绕过漏洞的原理就是Shiro和Spring boot对url解析的差异，在Shiro中/xxx/..;/admin被解析为/xxx/..绕过了权限验证，而在Spring boot中/xxx/..;/admin又被解析成了对/admin的访问，造成了未授权访问

与之类似的还有Tomcat URL解析漏洞

URL解析

Servlet中有以下几种url解析函数

  * request.getRequestURL()

  * request.getRequestURI()

  * request.getContextPath()

  * request.getServletPath()

  * request.getPathInfo()

解析效果如图：

  * getRequestURL() 返回完整的路径

  * getRequestURI() 返回host地址之后的路径

  * getContextPath() 返回项目名

  * getServletPath() 返回项目名之后的路径
    如：

  * getPathInfo() 返回servlet后的路径
    如：servlet配置信息为@WebServlet(name = "helloServlet", value = "/hello-servlet/*")

解析测试

  * demo_war_exploded/./././index.jsp

  * demo_war_exploded/asdfas/../index.jsp

  * ;asdfas/index.jsp

可以看出，在使用这几种url地址访问时，最终访问的都是index.jsp，因此可以利用这种方法绕过权限检测

如：http://localhost:8080/demo_war_exploded/admin/index.jsp为敏感信息时，可以尝试这样绕过

http://localhost:8080/demo_war_exploded/admin/./index.jsp
http://localhost:8080/demo_war_exploded/;asd/admin/index.jsp
http://localhost:8080/demo_war_exploded/admin/asd/../index.jsp
