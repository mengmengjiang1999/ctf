1-1SQL注入简介
2021-12-06 20:04:34

以上两个参数是程序设计者希望我们传入的正常参数，这个时候我们看到的网站是正常的

sql注入一旦被发现了注入点，SQL注入的目标就是把注入点进行充分的利用，以便得到网站背后的数据库，进而控制数据库系统和操作系统

1.什么是SQL注入？

1.正常的web端口访问

正常访问是web传入程序设计者所希望的参数值，由程序查询数据库完成处理后，呈现结果页面给用户。

2.SQL注入是如何访问？

（1）SQL注入实际上也是正常的web端口访问

（2）只是传入的参数值并非是程序设计者所希望的参数值，而是传入了嵌套SQL代码的参数值

我们传入嵌套SQL代码的参数值是希望程序帮我们查询数据库

（3）参数值利用程序处理注入者的逻辑，这个叫sql注入漏洞，按注入者的期望执行数据库查询

（4）甚至页面呈现按SQL注入者期望显示

SQL注入：是通过应用程序把带有SQL代码的参数传递给数据库引擎。

2.为什么要深入了解SQL注入？

1.SQL注入危害大

黑客最终的目标是数据，SQL注入提供了这种通道，是直达数据库引擎的。SQL注入的过程可以扩大到数据库，甚至与系统层进行交互，进而控制了操作系统，这种可能，后果更加严重，敏感数据可能有被泄露、破坏的风险。

2.SQL注入隐秘性强

SQL注入也是正常的web端口访问，因此SQL注入的隐秘性很强，高明的SQL注入者，系统或者数据库管理员不一定能够发现，所以它有可能被攻击者长期的潜伏，以便控制系统或者数据库。

3.SQL注入具有普遍性

SQL语言是关系数据库行业的通用标准，SQL注入不仅是MySQL本身的问题，实际上，也是其它使用SQL关系数据库存在的同样问题，有证据表明，60%以上的网站具有SQL注入漏洞。

4.知己知彼，目标为防

实际上不是我们不想提高，一方面是我们的意识不够，另一方面是对SQL注入技术了解不够，因此我们要深入了解SQL注入的终极目标是做好防范。

提高数据安全意识，把数据安全提高到一定的战略高度。

3.程序端SQL注入工作原理

在PHP语言中，正常访问的时候我们定义一个变量，这个是最常见的，比如登录的时候，要对账号和密码进行校验

1.正常的访问

$sql="SELECT * FROM users WHERE login ='$uname' AND password ='$pwd'"

PHP程序传入结果参数：$uname='huangxifeng'

$pwd='hxf123’

这个是正常的，没有什么问题

结果：SELECT * FROM users WHERE login = 'huangxifeng' AND password = 'hxf123'

2.SQL注入访问

这只是其中的一个例子，我们看到的黑色是注入者传进来的参数

PHP程序传入结果参数：$uname= ' ' or 1=1 --

$pwd='hxf123’

使用单引号的含义，把前面单引号闭合

or的目标，是希望1=1，永远为真，把它的结果变为真，改变了整个查询的逻辑，

后面--是sql的当行注释

结果：SELECT * FROM users WHERE login = ' ' or 1=1 --AND password = ' hxf123 '

用户名是空的，但是1=1永远为真，并且把后面的sql给注释掉了，它的结构最终永远为真，也就是说，当我们登录的时候，不需要用户名，也不需要密码，这样子应用程序就可以直接登录，这并非是我们程序设计者，所希望的那样

4.SQL注入漏洞的根本原因

（1）SQL注入漏洞是应用程序的问题，实际上不是系统或者数据库的问题。

虽然mysql本身就有注入漏洞，但是这种平台的漏洞出现的可能性是非常非常少的，因此我们讨论的sql漏洞，实际上本质就是应用程序，应用程序都是人为的，实际上归根揭底就是人的问题

SQL注入本质的原因是人对数据安全的意识薄弱。或者即使有安全的意识，而程序员对如何防范无从下手。因此导致程序对用户输入数据的合法性进行检查的时候，甚至没有检查，对传入参数的安全性也没有过滤，这就是本质的原因。
