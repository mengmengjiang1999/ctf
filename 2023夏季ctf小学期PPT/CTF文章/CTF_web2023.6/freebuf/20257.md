堆管理的细节：arena和chunk
2021-09-10 18:53:27

arena

arena的介绍

之前我们已经提到过arena，调用malloc的时候，我们明明只申请了1000Byte，但是heap segment却有0x21000Byte的大小，这0x21000Byte的空间就是arena。我们申请的空间优先从arena中取出，free后也将放回到arena

arena数量限制

之前我们写过一个代码，一共有两个线程，一个主线程，一个线程1.它们都有自己的arena。但其实并不是每一个线程都会有自己的arena。这里有一个arena个数的限制：
对于32位操作系统：arena的个数=2 * 处理器核心数+1
对于64位操作系统：arena的个数=8 * 处理器核心数+1

arena的管理

如果有一台主机它的处理器核心数为1个，32位操作系统，上面运行了一个程序，该程序含有一个主线程和三个用户线程。根据arena的数量限制，只可能会有三个arena，那么多出来的线程将会与其他线程共用一个arena。

当主线程首次调用malloc时，glibc malloc会直接给它分配一个main arena。

同样的，线程1和线程2首次调用malloc也会给它们都创建一个新的arena。此时三个arena和三个线程一一对应。

然后第三个线程来了，由于arena个数的限制，已经无法为线程3分配新的arena，于是glibc malloc会遍历所有的可用arenas，遍历的时候它会尝试lock当前arena。如果改arena当前对应的线程并没有使用堆内存，那么该arena将会被lock。然后就会将该arena返回给用户。然后该arena就被与其对应的线程和线程3共享

如果在这过程中没有找到可用arena，那么线程3被阻塞，直到有可用的arena为止

如果线程3再次调用malloc，glibc malloc就会先尝试最近访问的arena，如果此时该arena可用，那么就直接使用，否则将线程3阻塞，直到该arena再次可用未知

更多线程的情况以此类推

堆管理

三个数据结构

heap_info

也被称为heap header，由于除主线程之外的线程的arena(我们称为thread arena)可以包含多个heaps，所以会给每一个heap分配一个heap header。当某一个线程当前的heap不够用的时候，malloc会通过系统调用mmap申请新的堆空间，新的堆空间也会被添加到当前thread arena中

typedef struct _heap_info
{
  mstate ar_ptr; /* Arena for this heap. */
  struct _heap_info *prev; /* Previous heap. */
  size_t size;   /* Current size in bytes. */
  size_t mprotect_size; /* Size in bytes that has been mprotected
                           PROT_READ|PROT_WRITE.  */
  /* Make sure the following data is properly aligned, particularly
     that sizeof (heap_info) + 2 * SIZE_SZ is a multiple of
     MALLOC_ALIGNMENT. */
  char pad[-6 * SIZE_SZ & MALLOC_ALIGN_MASK];
} heap_info;


malloc_state

也叫做arena header，每个线程最多有一个arena header。arena header包含bins的信息、top chunk以及最后一个remainder chunk

struct malloc_state
{
  /* Serialize access.  */
  mutex_t mutex;
  /* Flags (formerly in max_fast).  */
  int flags;
  /* Fastbins */
  mfastbinptr fastbinsY[NFASTBINS];
  /* Base of the topmost chunk -- not otherwise kept in a bin */
  mchunkptr top;
  /* The remainder from the most recent split of a small request */
  mchunkptr last_remainder;
  /* Normal bins packed as described above */
  mchunkptr bins[NBINS * 2 - 2];
  /* Bitmap of bins */
  unsigned int binmap[BINMAPSIZE];
  /* Linked list */
  struct malloc_state *next;
  /* Linked list for free arenas.  */
  struct malloc_state *next_free;
  /* Memory allocated from the system in this arena.  */
  INTERNAL_SIZE_T system_mem;
  INTERNAL_SIZE_T max_system_mem;
};


malloc_chunk

也叫做chunk header，一个heap会被分为多个chunk。用户申请的也就是chunk。

struct malloc_chunk {
  /* #define INTERNAL_SIZE_T size_t */
  INTERNAL_SIZE_T      prev_size;  /* Size of previous chunk (if free).  */
  INTERNAL_SIZE_T      size;       /* Size in bytes, including overhead. */
  struct malloc_chunk* fd;         /* double links -- used only if free. 这两个指针只在free chunk中存在*/
  struct malloc_chunk* bk;
  /* Only used for large blocks: pointer to next larger size.  */
  struct malloc_chunk* fd_nextsize; /* double links -- used only if free. */
  struct malloc_chunk* bk_nextsize;
};


大家可能会有疑问，为什么主线程只能有一个heap。这里给大家解释一下。这里的heap并不是广义上虚拟内存空间中的堆，而是子线程使用系统调用mmap从操作系统申请的一块内存。而主线程的堆只有一个可以自增的heap。

1. 由于main thread不含有多个heaps所以没有heap_info结构体。当需要更多堆空间的时候就通过扩展brk
2.main arena的arena header并不是sbrk heap segment的一部分，而是一个全局变量。因此它属于libc.so的data segment。

malloc_chunk

这里重点介绍一下chunk。由malloc申请的内存就会被称为chunk。当chunk被free以后，就会加入到空闲列表中去。chunk不管是处于分配状态还是释放状态，它们都是用同一个数据结构

再来回顾一下chunk的数据结构

struct malloc_chunk {

  INTERNAL_SIZE_T      prev_size;  /* Size of previous chunk (if free).  */
  INTERNAL_SIZE_T      size;       /* Size in bytes, including overhead. */

  struct malloc_chunk* fd;         /* double links -- used only if free. */
  struct malloc_chunk* bk;

  /* Only used for large blocks: pointer to next larger size.  */
  struct malloc_chunk* fd_nextsize; /* double links -- used only if free. */
  struct malloc_chunk* bk_nextsize;
};


另外关于一些数据类型还有一些宏定义

#ifndef INTERNAL_SIZE_T
# define INTERNAL_SIZE_T size_t  4字节或8字节
#endif

/* The corresponding word size.  */
#define SIZE_SZ (sizeof (INTERNAL_SIZE_T))

/* The corresponding bit mask value.  */
#define MALLOC_ALIGN_MASK (MALLOC_ALIGNMENT - 1)


每个字段的介绍

prev_size

该字段在前一地址处于空闲状态时启用，用来记录物理相邻前一个chunk的大小。如果前一个chunk处于使用状态，那么这个字段可以用来存储物理相邻的前一个chunk的数据(前一个是指地址比较低的chunk)

size

size字段记录该chunk的大小。大小必须是2 * SIZE_SZ的证书被。如果申请的内存大小不是2 * SIZE_SZ的整数倍，会转换为满足大小的最小的2*SIZE_SZ的倍数。由于无论申请多少，都不会用到最后三位，于是最后三位就被记载其他信息

 1. NON_MAIN_ARENA,记录当前chunk是否不属于主线程，1表示不属于，0表示属于

 2. IS_MAPPED,记录当前chunk是否由mmap分配

 3. PREV_INUSE,记录前一个chunk是否被分配，0未被分配，1被分配。堆中第一个被分配的内存块的size字段的P位都会置为1，防止非法访问。而且也方便空闲chunk的合并

fd,bk

chunk处于分配状态时，从fd字段开始就是用户数据。chunk空闲时fd和bk指针才会被启用，分别指向下一个和上一个空闲chunk。chunk空闲时会以链表的形式存放(后面的文章会讲到bins)

fd_nextsize， bk_nextsize

只有chunk空闲的时候会启用，用于较大的chunk。fd_nextsize指向前一个与当前chunk大小不同的第一个空闲块，不包含bin的头指针

bk_nextsize指向后一个与当前 chunk 大小不同的第一个空闲块，不包含 bin 的头指针。

一般空闲的large chunk在fd的遍历顺序中，按照由大到小的顺序排列

这些大概就是chunk每个字段代表的含义，再到后面会讲解chunk在具体环境中的使用
