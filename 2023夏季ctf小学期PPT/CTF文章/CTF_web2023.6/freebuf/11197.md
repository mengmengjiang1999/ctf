XSS漏洞

XSS(cross site script)或者说跨站脚本是一种Web应用程序的漏洞，恶意攻击者往Web页面里插入恶意Script代码，当用户浏览该页之时，嵌入其中Web里面的Script代码会被执行，从而达到恶意攻击用户的目的。

XSS本质：一种钓鱼攻击


主要风险：

1、盗取用户cookie，然后伪造用户身份登录，泄漏用户个人身份及用户订单信息。
 2、结合浏览器及其插件漏洞，下载病毒木马到浏览者的计算机上执行。
 3、修改页面内容，产生钓鱼攻击效果，例如伪造登录框获取用户明文帐号密码。


XSS分类

1、反射性XSS

反射式XSS一般是提交信息的一部分内容通过服务器解析后反馈到浏览器，而不存储到服务器。

反射型XSS案例场景：DVWA靶场

1）随便输入hell 567 后提交

2）查看源码，输入在服务器端处理后，已经成为HTML页面中的一部分。


3）当输入的内容为脚本时， 输入的内容会被当作脚本执行




4）此处我们可以利用XSS实现跳转

<script>alert("点击跳转");location.href="https://www.baidu.com"</script>



5）跳转到百度首页

2、存储型XSS

存储型xss是指应用程序通过web请求向服务端提交了恶意数据，在未检验数据是否存在xss代码的情况下将其存入数据库。当下一次从数据库中获取该数据时，程序也未对其进行过滤，页面再次执行xss代码。

注：

1）存储型XSS的核心是存入到某个地方然后调用，不一定就要存在数据库里，还可以是文件里
2）存储型xss出现的位置：留言板、评论区、用户头像、个性签名、博客等


存储型XSS案例场景：

1）当留言板块被插入恶意xss代码时，内容会被存储到数据库中。



2)切换到其他页面后再次访问此页面就会受到影响



反射式 XSS 漏洞与存储式 XSS 漏洞的区别

与存储式XSS不同的是，反射型XSS不能存储在服务器中


3、DOM式XSS

DOM型XSS其实时一种特殊类型的反射型XSS，通过JS操作DOM数动态地输出数据到页面，而不依赖于将数据提交给服务器端，它是基于DOM文档对象模型的一种漏洞。DOM型XSS数据不经过服务器，所以不受WAF影响。

DOM型XSS案例场景：DVWA靶场

1）构造XSS代码，脚本执行成功

2）查看源代码，可以看到，我们的脚本插入到代码中，所以执行了

与之前两类XSS漏洞不同的是

DOM式XSS漏洞发生原因跟服务器解析无关，存粹是JS代码读取了URL内容

1）最常见的方法

就是在论坛或留言本中发帖时将html代码写入到被攻击页面中，此外在用户资料修改、签名、联系方式等地方也是攻击者写入html代码常用的地方，如果被攻击页面对用户输入过滤不严的话，就可以被攻击者写入类似如下的一段代码。

<script>alert('1')</script>

<textarea onfocus=alert(1); autofocus>

3、篡改网页链接

在存在xss漏洞的地方插入如下代码：

<script>
window.onload = function() {
var link=document.getElementsByTagName("a");
for(j = 0; j < link.length; j++) {
   link[j].href="http://www.baidu.com/";}
}
</script>


当窗口加载时，使用for循环遍历所有的a标签，将a标签中的url替换指定的url。

利用带有XSS漏洞的页面，将所有a标签的url替换成指向流量的url，使得所有用户在这个网页点击的任何链接都跳转到该流量站点，使得站点的流量增多

XSS 绕过

1、基于规则的绕过

大小写绕过：

HTML对标签大小写不敏感，可以利用大小写混用绕过， 例如：

<script>改为<ScRiPt>


双写绕过：

有些情况的规则会将黑名单标签替换为空，可以利用这一点构造标签，例如：

<script>改为<scr<script>ipt>


同理某些注释符在规则中也会替换为空，这时候可以利用它构造payload，例如：

<script>改为<scr<!---test--->ipt>


开口标签：

在某些特殊环境，由于html代码补全机制，可以故意不闭合标签绕过黑名单检测，例如：

<script>改为<script

XSS 防护方法

1、过滤和转义

1）对用户的输入进行合理验证
对特殊字符如（<、>、’、”等）以及script、javascript等进行过滤。

2）设置HttpOnly
设置HttpOnly属性，避免攻击者利用XSS漏洞进行Cookie劫持攻击。

java：cookie.setHttpOnly(true);

  python：tools.session.httponly = true

  php：session.cookie_httponly=1
