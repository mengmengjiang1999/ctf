Spring 中一个零日 RCE 漏洞 Spring4Shell 的神秘披露
2022-03-31 17:30:15

根据外媒报道，研究人员在名为“Spring4Shell”的 Spring Core Java 框架中披露了一个名为 Spring4Shell 的零日漏洞。未经身份验证的远程攻击者可以触发该漏洞在目标系统上执行任意代码。该框架目前由 VMware 的子公司 Spring.io 维护。

Spring Framework 是Java 平台的应用程序框架和控制容器反转。该框架的核心功能可以被任何 Java 应用程序使用，但也有一些扩展可用于在 Java EE（企业版）平台之上构建 Web 应用程序。

该漏洞是在一名我国安全研究人员在删除其帐户(helloexp)之前发布概念验证 (PoC) 漏洞后披露的。

Java Springcore RCE 0day 漏洞已被泄露。它是由一位中国的安全研究人员泄露的，该研究人员在分享和/或泄露它后，已经删除了他们的 Twitter 帐户。我们尚未验证该漏洞。


— vx-underground (@vxunderground) 2022 年 3 月 30 日

Rapid7 发表的分析指出，利用代码针对 Spring Framework 的 Spring Core 模块中的零日漏洞。Spring 由 Spring.io （VMWare 的子公司）维护，并被许多基于 Java 的企业软件框架使用。泄露的概念证明中的漏洞似乎允许未经身份验证的攻击者在目标系统上执行代码，但很快就 被删除了。

该漏洞尚未修补，并会影响 Java 开发工具包 ( JDK ) 版本 9 及更高版本上的 Spring Core。该漏洞是对另一个被跟踪为 CVE-2010-1622的漏洞的绕过。

Rapid7 研究人员指出，只有在使用特定功能时才能触发漏洞（和概念证明）。 中国研究人员发布的漏洞利用代码与2022 年 3 月 29 日针对 Spring Cloud发布的“完全不同”的未经身份验证的 RCE 漏洞无关 。

Rapid7研究人员还指出，存在概念验证漏洞，但目前尚不清楚哪些实际应用程序使用了易受攻击的功能。配置和 JRE 版本也可能是影响可利用性和广泛利用可能性的重要因素。

对该漏洞的分析表明，它的影响可能不像其他问题（如 Log4J）那样严重。在网络安全公司Praetorian 发布的分析中写到，利用需要启用 DataBinder 的端点（例如，自动解码来自请求正文的数据的 POST 请求），并且严重依赖于应用程序的 servlet 容器。

测试 Spring4Shell 漏洞的安全研究人员证实它有效。CERT/CC 漏洞分析师 Will Dormann 证实，PoC 漏洞利用代码与 spring.io 中的“处理表单提交”示例代码有效。

信息来源：https://securityaffairs.co/wordpress/129644/hacking/spring-java-framework-rce-zero-day.html
