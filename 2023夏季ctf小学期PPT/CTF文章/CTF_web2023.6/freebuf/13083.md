NSA网络基础设施安全指南（翻译）（一）
2022-04-09 16:31:04

1. 简介

网络安全是动态发展的，随着新的安全漏洞不断被利用，网络安全基础设施指南也在不断更新，增加了一些新的安全防护措施和安全加固设备的新方法。不合理的配置、不正确的配置处理和脆弱的安全密码会导致整个网络的脆弱性被暴露在外。所有网络都存在被破坏和攻击风险，当设备得到没有正确配置和维护，这种风险会大大增加。俗话说“三分技术，七分管理”，网络管理员的岗位是至关重要的，可以保护网络抵御各种黑客攻击，日常安全管理中，一般都要求有专职安全管理员来保护网络上的设备、业务软件和重要信息。

本报告介绍了总体网络安全防护和网络设备保护的最佳实践，从而可以帮助管理员防止对手利用其网络进行攻击。这份指南提供的指导是通用，可以用于多种类型的网络设备。提供思科设备命令作为示例，实现指南内提供的相关建议措施。

1.1 关于零信任

零信任是一种安全模型、一套网络基础架构设计原则，一种网络安全和业务系统的协同的策略，中心思想是不应自动信任内部或外部的任何人/事/物，打破了传统“内部等于可信任”、‘外部等于不可信任’的传统旧的安全观念。NSA完全支持零信任模型，在报告中很多地方防护措施也推荐零信任。然而课时，这份报告主要关注如何缓解在现有网络上常见的漏洞和脆弱性，如果系统所有者要采用新的网络设计，实现更成熟的零信任原则，该指南可能需要修改。

2. 网络架构和设计

实现“纵深防御”的安全网络设计对于抵御威胁和保护网络内的资源至关重要。对于DMZ区域和内部设备，设计应遵循安全最佳实践和模型零信任原则。

2.1 部署DMZ和内部防护设备

网络通过部署一系列防护策略去保护网络组件和信息， DMZ区域按照纵深防御理念部署多重防护措施去抵御外部威胁，并且限制出站和入站的通信流量。

  * NSA建议按照以下最佳实践在DMZ区域安装和配置安全设备；
  * 安装便捷路由器去连接外部网络，例如ISP；
  * 部署七层下一代防火墙在网络中去限制入站流量和出站流量，检查不同网络区域之间的所有内部活动。每一层都应当利用不同厂商的措施去防止对手利用同一的未修复补丁的漏洞访问内部网络；
  * 在一个或多个非军事区(DMZ)子网的防火墙层之间放置公开可访问的系统和出站代理，可以在外部设备、DMZ设备和内部系统之间适当地控制访问；
  * 部署一个网络监控解决方案来记录和跟踪入站和出站流量，例如网络入侵检测系统(NIDS)、流量检查器或全数据包捕获设备；
  * 部署多个专用的远程日志服务器，以分析设备之间的活动关联和检测横向移动；
  * 在关键区域实现设备冗余确保网络可用性，通过负载平衡设备可以增加网络吞吐量和减少延迟；

2.2 将类似的网络系统分组

网络中的类似系统应该在逻辑上分成同一组，以防止来自其他类型系统的对抗性横向移动。攻击者会以更容易被利用的系统为目标，例如打印机，使用初始的访问权限进一步渗透到网络上其他系统中。适当的网络分组可以显著减少对手访问和渗透系统的能力。此外，如果网络被逻辑上分组，不同类型的系统之间的访问控制会更容易管理、控制和监控。

NSA建议将类似的系统隔离到不同的子网或vlan中，也可以通过防火墙或过滤路由器将不同的子网进行物理分离。工作站、服务器、打印机、通信系统和其他网络外设也应当被相互隔离。OT运营技术相关的，如工业控制系统，通常也需要与其他信息技术和高风险网络（例如互联网）需要隔离。物理隔离提供了更强的保护，对攻击者而言，首先要攻陷子网之间的中间设备才能绕过访问限制。在内部路由器、交换机或防火墙上设置访问限制策略，只允许那些为网络日常操作和业务访问所需的端口和协议通过。访问控制列表(acl)可能需要复制并直接应用到交换机上，限制vlan之间的访问，也可以应用于在内部子网之间的核心路由器上。

2.3 删除后门连接

后门网络连接是位于不同网络区域的两个或多个设备之间，通常具有不同类型的数据和安全要求。如果一个设备被攻陷了，攻击者可以使用这个连接来绕过访问限制，并获得访问网络的其他区域的权限。一个后门网络连接的例子，连接到ISP的外部边界路由器，也直接连接到内部或管理网络。一个攻击者会攻陷这个路由器，绕过所有防火墙直接访问到内部网络。NSA建议删除所有后门网络连接，谨慎使用连接具有多个网络接口的设备。检查设备的所有网络接口是否处于相同的安全级别，中间设备是否提供了不同网络区域之间的逻辑和物理隔离措施。

2.4 使用严格的边界访问控制

网络周边设备是安全模型中的基本组成部分，应该通过设置访问控制列表（acl）来控制网络进出流量，访问控制规则应该被配置遵守最小化原则，只允许所需的服务端口和应用系统通过。如果防火墙和边界路由器没有配置合适安全策略，将可以对内部网络进行不必要的访问，从而增加网络泄露和信息收集的风险。

NSA建议仔细考虑为允许通过的连接建立允许的访问控制规则，其他连接默认拒绝。这个方法可以利用单个规则拒绝多种类型的连接，而不必为每个拒绝通过的连接使用单独的规则。如果认为有必要使用动态访问控制规则，以防止攻击利用尝试被顺利完成或持续， NSA 建议使用入侵防御系统 (IPS)。

2.5 部署网络准入方案

攻击者如果想要访问内部网络，必须找一条从外部网络边界通往内部网络的通道。准入解决方案可以阻止未授权的物理连接，也可以监控已授权的网络物理连接。

NSA 建议实施 NAC 解决方案，以识别和验证连接到网络的唯一设备。端口安全是一种可以在交换机上实施的机制，用于检测未经授权的设备何时通过设备的MAC地址连接到网络。但是端口安全措施难以管理， 例如，由于有效的阻塞网络端口，它会增加技术支持工作量（例如，经常人员变化的会议室）。攻击者可以使用MAC地址欺骗技术绕过。更强大的解决方案使用 802.1X，可以根据设备上安装的CA证书对设备进行身份验证。由于证书的生成和安装过程繁琐，虽然实施起来比较困难，但是比端口安全更容易管理，并提供更高级别的防护强度。

2.6 限制和加密虚拟网络

VPN 网关往往可以从 Internet 访问，容易遭受网络扫描、暴力破解和零日漏洞等攻击的影响。为了应对许多此类漏洞，管理员应禁用所有不需要的功能，并对 VPN 网关的流量实施严格的流量过滤规则。

所有 IPsec VPN 配置都需要 IPsec 策略和 Internet 密钥交换 (IKE) 策略，这些策略决定了它在建立 IPsec 隧道时如何协商每个阶段。 如果任一阶段配置为允许弱加密，整个 VPN 可能存在风险，数据机密性将丢失。

每个 IKE 策略至少包括三个关键组件：

 1. 密钥交换算法
 2. 加密算法
 3. 哈希算法

以下是国家安全系统政策委员会（CNSSP）推荐的最低设置：

  * Diffie-Hellman 组：16 ，密钥长度：4096 位MODP
  * Diffie-Hellman 组：20， ECP384
  * 加密：高级加密标准 (AES)-256
  * 哈希：安全哈希算法 (SHA)-384

根据 CNSSP 15 的最低要求，其实Diffie-Hellman 组15 安全性也是可以接受的，但由于已经发现有互操作性问题，不推荐使用 组 15。

可以在不受信任的网络（例如 Internet）的两个端点之间建立 VPN 隧道，提供加密的通信通道。 在建立 VPN 建议、策略或转换集时，请确保它遵循 CNSSP 15 建议 [4]。 互联网工程任务组 (IETF) 文件草案解释了 CNSSP 15 的要求。“用于 Internet 协议安全 (IPsec) 的商业国家安全算法 (CNSA) 套件加密”。为确保它们不会被无意使用，请使用以下配置命令禁用 Internet安全关联密钥管理协议 (ISAKMP) 和 IKEv2 的默认策略和建议：

no crypto isakmp default policy

no crypto ikev2 policy default

no crypto ikev2 proposal default

no crypto ipsec transform-set default

注意：如果禁用默认策略，则仅使用配置的策略。

使用以下示例配置命令建立 IKEv2 提案、策略和配置文件：

crypto ikev2 proposal <IKEV2_PROPOSAL_NAME>

encryption aes-gcm-256

group [16|20]

crypto ikev2 policy <IKEV2_POLICY_NAME>

proposal <IKEV2_PROPOSAL_NAME>

crypto ikev2 profile <IKEV2_PROFILE_NAME>

match identity remote ...

authentication remote ...

authentication local ...

配置文件的设置将根据网络实际环境，并且必须具有本地和远程身份验证方法以及匹配声明。也可以为多个预共享密钥建立单独的密钥环并将其应用于配置文件。使用以下示例配置命令建立 IPsec 转换集：

crypto ipsec transform-set <IPSEC_TRANSFORM_NAME> esp-gcm 256

mode tunnel

利用上面定义的 IKEv2 配置文件和 IPsec 转换集，使用以下示例配置命令建立 IPsec 配置文件：

crypto ipsec profile <IPSEC_PROFILE_NAME>

set transform-set <IPSEC_TRANSFORM_NAME>

set pfs group16

set ikev2-profile <IKEV2_PROFILE_NAME>

应使用以下配置命令将 IPsec 配置文件应用于隧道接口：

interface <TUNNEL_INTERFACE_NAME>

tunnel protection ipsec profile <IPSEC_PROFILE_NAME>

no shutdown

有关详细信息，请参阅“配置 IPsec 虚拟专用网络”、“缓解最新的 VPN 漏洞”和“消除陈旧的传输层安全性 (TLS)协议配置”[6]、[7]、[8]
