当今社会物联网设备已经逐步渗透到人们生产生活的方方面面，为人们及时了解自己周围环境以及辅助日常工作带来便利。但随着互联紧密度的增高，物联网设备的安全性问题也逐渐影响到人们的正常生活，甚至生命安全，物联网设备安全不容小觑。

以下为近日的物联网安全新闻内容。

思科填补了小型企业路由器的关键漏洞

“思科 PSIRT 知道概念验证漏洞利用代码可用于本公告中描述的几个漏洞，”该公司在随附的安全公告中表示。幸运的是，PoC 并不公开——思科（主要）指的是安全研究人员在 2021 年 11 月在德克萨斯州奥斯汀举行的 Pwn2Own 黑客竞赛中用来“破解”思科 RV340 路由器的漏洞。

关于漏洞

这些漏洞影响 Cisco Small Business RV160、RV260、RV340 和 RV345 系列路由器。

他们收到了连续的 CVE 编号，从 CVE-2022-20699 开始，到 CVE-2022-20712 结束。最后一个被标记为 CVE-2022-20749。

它们可能允许攻击者：

  * 实现RCE
  * 将他们的权限提升为 root 并执行命令
  * 在受影响的设备上安装和启动恶意软件映像或执行未签名的二进制文件
  * 查看或更改受影响设备与特定思科服务器之间共享的信息
  * 击败身份验证保护并访问设备的 Web UI
  * 在底层操作系统上注入和执行任意命令
  * 将任意文件上传到受影响的设备
  * 在基于 Web 的管理界面的登录功能中导致拒绝服务 (DoS) 条件
  * 覆盖受影响设备上的某些文件

“一些漏洞相互依赖。可能需要利用其中一个漏洞来利用另一个漏洞，”思科补充说。

由于没有可用的解决方法，建议尽快应用提供的安全更新。

该计划中唯一的临时故障是，虽然 RV340 和 RV345 系列路由器的安全更新已经可用，但 RV160 和 RV260 系列的安全更新仍在进行中，并将在本月的某个时候发布。

跨越多代：三星修复影响上亿 Android 设备的硬件密钥安全漏洞

SamMobile 报道称，尽管三星总能在 Google 正式发布修复之前，就为自家规模庞大的 Android 移动设备提供安全更新。然而过去多年销售的三星智能机，还是被发现存在一个出厂即有的安全漏洞，使得黑客能够轻易提取包括密码在内的敏感信息。以色列特拉维夫大学的研究人员指出，问题在于 Galaxy S8 / S9 / S10 / S20 / S21 等系列机型未能妥善存储其加密密钥。

InsydeH2O UEFI BIOS 被曝存在 23 个安全漏洞 波及大批电脑厂家

专业处理固件威胁的安全研究公司 Binarly，刚刚在周二的一篇博客文章中披露了 InsydeH2O“Hardware-2-Operating System”UEFI BIOS 中存在的问题。作为微软、英特尔、惠普、戴尔、联想、西门子、富士通等多家科技巨头的固件供应商，这意味着它们都易受将近两打安全漏洞的影响。

由于这是固件级别的缺陷，因而成功利用可能导致几乎无法摆脱的持久性恶意软件。，其中大多数漏洞（CVSS 评分 7.5 – 8.2 / 高危）可利用 SMM 权限执行代码，在借此绕过安全功能之后，这些漏洞还可在长期持久性的第二阶段继续发挥作用。

Trickbot 使用受感染的 MikroTik 路由器作为 C2 通信代理

微软研究人员发现，MikroTik 路由器正被用作 Trickbot 恶意软件的通信代理，以使受 Trickbot 影响的设备能够以标准网络防御系统无法检测到的方式与其 C2 服务器进行通信。

Trickbot 是一种模块化木马，自 2016 年以来一直存在，经常被网络犯罪分子用来传播勒索软件或其他恶意软件。

以前削弱 Trickbot 僵尸网络的尝试只是部分成功，因此僵尸网络继续存在。它的控制器也在不断尝试新的技巧，让恶意软件在受感染的系统上持续存在，并保持与 C2 服务器的通信不中断。

他们最新的技巧是控制 MikroTik 路由器——通过尝试默认密码、发起暴力攻击（使用可能从其他 MikroTik 设备获取的唯一密码）或利用CVE-2018-14847——并通过更改来保持它受影响设备的密码。

然后，受感染的路由器用于在受 Trickbot 感染的设备和 Trickbot C2 服务器之间创建一条通信线路：路由器通过端口 449 接收来自受 Trickbot 感染的设备的流量，将其重定向到端口 80，然后从该端口发送到命令和控制服务器。

详文阅读：https://www.helpnetsecurity.com/2022/03/17/trickbot-uses-compromised-mikrotik-routers-as-c2-communication-proxies/

Veeam 修复了备份解决方案中的关键 RCE（CVE-2022-26500、CVE-2022-26501）

Veeam Software 修复了两个影响其流行的 Veeam Backup & Replication 解决方案的严重漏洞（CVE-2022-26500、CVE-2022-26501），未经身份验证的攻击者可利用该漏洞远程执行恶意代码。

Veeam Backup & Replication 是一种企业数据保护解决方案，允许管理员创建虚拟、物理、云计算机的映像级备份并从中恢复。

根据公司最新共享信息，自 2021 年第一季度推出以来，已有超过 450,000 名用户下载了 Veeam Backup & Replication v11。

关于漏洞（CVE-2022-26500、CVE-2022-26501）

这两个漏洞都可能允许攻击者实现 RCE 并控制易受攻击的系统。

该公司或发现并报告这些漏洞的 Positive Technologies 研究员 Nikita Petrov 都没有分享这些漏洞的细节。

Veeam 简单地指出，“Veeam 分发服务（默认为 TCP 9380）允许未经身份验证的用户访问内部 API 功能。远程攻击者可能会向内部 API 发送输入，这可能导致恶意代码的上传和执行。”

Veeam Backup & Replication v9.5、10 和 11 受到影响，并为后两者提供了补丁。该公司正在敦促前者的用户升级到受支持的版本。

如果补丁无法快速实施，管理员可以暂时停止和禁用 Veeam 分发服务。

除了修复这些缺陷之外，相同的补丁还关闭了 CVE-2022-26504，这是另一个影响用于 Microsoft System Center Virtual Machine Manager 集成的组件的 RCE 漏洞。

“易受攻击的进程 Veeam.Backup.PSManager.exe（默认为 TCP 8732）允许使用非管理域凭据进行身份验证。远程攻击者可能会使用易受攻击的组件执行任意代码，”该公司分享道，但补充说，默认的 Veeam Backup & Replication 安装不受此问题的影响。

对于管理员来说幸运的是，任何这些漏洞的利用尚未公开。
