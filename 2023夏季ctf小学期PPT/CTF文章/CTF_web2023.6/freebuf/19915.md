水印溯源——基于业务语义不变的数据水印生成算法
2021-09-13 17:17:07

数据水印

数字水印是永久镶嵌在其它数据中具有可鉴别性的数字信号或模式，且不影响宿主数据的可用性。一般用于数据共享分发的溯源场景，也用于数据版权宣示。比如在数据渠道分发的过程中，会将渠道商信息转为水印信息，镶嵌到分发数据中。当发生数据泄露后，只需要收集部分泄露的数据，通过水印溯源系统提取出水印信息。数字水印生成算法有很多，比如在正常文本中插入零宽字符、空格字符以及非其他可读性较差的字符。以下两段文字，分别是加密和未加密，人肉眼是看不出来的：

问题背景

零宽字符并不是适用于所有场景。因为插入了新的字符，在应用程序处理中，会多出一些字节，可能导致内存溢出，或者存储空间溢出。程序逻辑处理也可能导致异常，比如一个整数，因为插入了字符，导致做字符串转整型的时候异常。对于有防备能力的泄露者，可能会通过技术手段绕过，比如对一封涉密邮件拍照，然后OCR转文字，零宽字符就自动被过滤。

实现思路

我们提出一种算法水印。利用业务上文本的等价性，做业务语义不变的文字转换。先看下面的一个例子：

物流系统里，有一个收件人地址信息，如：苏州市工业园区腾飞创新园塔楼A-1205室，如果我们将这个地址改为“江苏省苏州市工业园区腾飞创新园塔楼A-1205室”，其文本语义不变。其中“江苏省”是一种水印位，是我们实施水印的时候作为水印位添加上去。再比如：交易金额，如：￥123.3，如果我们将其改写为￥123.30，其文本语义也不变。其中末位的0是一种水印位，是我们实施水印的时候作为水印位添加上去。这种在业务语义上等价，字符属性上发生变化的水印方式，我们称为语义水印。现在我们以金额为例子，说明算法的可用性。金额末位是否添加0，构建一种水印函数wp族，根据我们要实施的水印信息id动态生成函数，

func gen_func(id){
  return func
}

其输入参数：账号id。这里面的渠道账号id，可以是我们面向的用户id，也可以是我们的第三方调用者，总之是后面我们希望能溯源出来的信息。

接下来我们拿到这个函数，对具体的数据进行打水印

text waterPrint(text,func){
  return func(text);
}

text就是我们要分发出去的原始数据，比如金额就是￥123.3。func就是我们刚才根据id生产的函数。对于金额来说，输出后的信息可能是：￥123.3或者￥123.30，这要依赖于我们的算法实现。

有人可能会疑问，我们输入100条交易金额，类似￥123.3， 结果输出还是￥123.3，什么也没改变，那水印信息藏在哪里？

这就是该算法的精妙之处。文本状态没有任何改变，本身就是一种算法的体现。就像0和1,本身包含了2种状态。他的状态改变或者不改变，都是该函数的效果。也即是说，我们添加了“算法”信息到了一批文本中。我们的目的，不是溯源出账号id，而是从水印文本中溯源出“函数”。我们希望从一批样本中逆向还原出当时施加的函数。

下面我们以金额为例子，来看不同函数生成的效果。

当我们重新导入一批水印后的数据的时候，重新用上面生成的函数族算法，生成与id匹配的函数，然后该函数实施到水印样本，其结果是输出是否与水印位匹配。如果多条样本都是匹配，我们判断属于这个函数产生的水印。

设计一个函数rwp,其输入是参数：添加水印的文本列表,输出是id。rwp(text1,text2,..textn)=id。

对于单条的输出文本，我们无法判断是基于哪个函数生成的结果，毕竟只有有限位，容易产生碰撞。但是随着样本量的增加，多条数据的水印位形成的轨迹，碰撞概率会急速下降。以总共有2个id（2个函数），数据水印位为1位，随机分布生产水印位来推算，那么当只有1条数据的时候，这个数据各有50%的概率分属于两个id，当有10条数据的时候，产生了2^10的水印位的随机组合，这种情况下，99.9%的概率会匹配具体函数。

我们应该注意到，每条数据的水印位可以不止1位，也可以多位，而每增加1位，其溯源能力就成倍提升。而衡量溯源精准度主要就是要看数据的水印总信息量。所以这个算法非常灵活，可以适用于不同的业务场景中。

这种语义水印，通过将算法而非水印信息实施到数据本身，达到了“可用不可见”的目的，完美地避免了零宽字符、不可见字符等导致文本处理异常的问题。

后语

数据水印算法的可用性是非常重要的评价指标，本方案创造性地通过牺牲单条数据水印的水印信息，将每个水印信息映射成函数来对数据做转义，并结合业务特性，在不改变业务信息属性的情况下，利用有限的扩展位，达到了数据可用性不降低，水印信息溯源程度高的目的。
