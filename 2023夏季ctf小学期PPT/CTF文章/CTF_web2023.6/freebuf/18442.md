hash的区别跟缓解的方式

1 lmhash ntmlhash netlmhash

lm hash

lm hash是一种比较古老的hash，一般都存在xp跟2000的系统中还在使用。存储的hash值非常容易被暴力破解，在之后的版本就禁用这个lm，但是也是有使用选择的情况。

ntlm hash

vista之后的版本使用的就是ntlm hash ，使用16进制，加上uncode编码之后再进行md4的对密码的加密的ntlm hash，这样的加密之后要做到与密码之后的同等的效果。hash传递的攻击的pth等都是使用的ntlm hash进行传递的攻击。并且都会存在到lsass的进程中，提供个ssp服务的使用。

ssp（内网中的一些认证的协议，比如msv，tspkg，wdigest，kerberos ）

net - ntlm hash

net -ntml hash 是一种基于网络认证的hash协议 ，用于网络认证的协议，目前有两个版本：

net-ntml hashv1

net-ntml hashv2

net-ntml hash v1 默认使用的是2003跟xp这些机器

通常我们使用的responder的一个网络请求认证的一个工具一个类似与dns欺骗的工具主要涉及的协议有（llmnr，NBNS，mdns）这三种协议。这几种协议都是默认启动的，类似与arp欺骗协议，都是没有认证的协议那responder就是利用的这种情况进行欺骗。

windows基于NTLM协议的有smb,httpm,ldap,mssql而这个工具就是responder就是模拟正常的smb协议的数据包读受害者进行的获取NTLMv2 hash的值，NTLMV2 hash的值是不能直接作为pth攻击的协议，当是可以使用john进行散列值的破解到明文，而如果是NTLMv1的话是可以直接还原真实的htLM hash的值，直接用于pass the hash（pth攻击),相对于NTLMv2 hash来比较的话会更加的危险跟应用漏洞

网络认证与非网络认证

网络登入

网络认证在登入的过程中不使用凭证输入对话框来收集数据，而会使用预先生成的票据

非网络登入

分为网络明文登入和交互的类型进行登入，在登入的时候会把明文密码进行验证，服务器会把明文密码放进lsass运行内存里面。并使用这个值进行访问资源。

NTML登入

NTML认证出现网络认证中，而远程服务器不会去保存NTLM值。

缓解pth的方式

1 禁止NTLM认证

2 防止NTLM hash被获取

第一种方式一劳永逸组织了pth，但是NTLM被微软使用是很久了，如果直接禁止一些破坏一些已经部署的一些环境，但实际中的阻力会比较大，

由于NTLM认证的天然缺陷，微软似乎改变其改变，所以要吧重心要做防御这块，简单来讲就是打补丁。

kb2871997

删除lsass的明文凭证

我们前面提到过，lsass进程会缓存用户凭据，有明文有Hash，这取决于使用的ssp类型以及补丁情况。

在上面中(msv tspkg wdigest kerberos)这几个ssp都获取到了凭据，分别用于Terminak server认证(RDSH),NTLM认证，摘要认证，以及kerberos认证，我们能看只有msv一个ssp是没有明文密码的。

这说明msv服务只需要输入一次明文密码之后就会进行在hash的运算之后直接用处理之后的NTLM hash进行传递，这也是说，ssp只需要把NTLM hash并存放在内存中。

而摘要认证wdigest在windows机器中缓存了明文密码。摘要认证类似与NTlm认证，也使用了挑战响应机制，但是他与NTLM认证较大的区别在于客户端计算机响应的时候需要使用到明文密码，为实现oss，因此客服端再进行计算的时候会把明文密码放到内存中计算，这也是我们能直接抓到内存中的密码的原因，与这个想比较NTLM ssp使用的单向函数如NTOWFv2只需要计算一次并放值内存中，之后计算响应只需要这个hash值就可以以了

KB2871998会删除除了widgest ssp的以外其他ssp的明文凭据，但对于wdigest只能选择再注册表中禁用，用户可以使用注册表

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest\UseLogonCredential 改成0来禁用

在本地的组策略中禁止本地用户网络认证的登入的设置，理论上uac无法限制rid为500的用户，但是打补丁并且配置好之后就会让administrator无法登入。

局限性 ： 太过于粗暴，可能会影响到用户的正常需求

添加受限制模式

正常模式

在使用mstsc的远程桌面连接中会直接把明文密码加载到对方服务器中内存中使用，委托的过程中就会直接调用这个内存中的明文密码去使用

使用受限制模式

客户端使用mstsc /restrictedadmin，也即受限管理员模式启动，服务端支持受限管理员模式：

远程桌面会话是没缓存用户凭据的，这也是受限制的特性restrictedadmin

1 远程桌面默认无约束委派用户的，以达到完全在远程服务器上代表用户的目的，当我们连接到远程服务器上的时候，使用dir命令可以连接到其他的smb服务器使用我们的凭证，这是因为客户端进行远程桌面连接的时候发送用户的明文密码，这个密码用于计算HTLM HASH并缓存到远程服务器上面。

2 受管理者模式下，远程桌面客户端会使用客户端机器上已经皇城的NTLM HASH进行认证，不需要用户去输入账号密码，也不会把明文委派给远程连接的服务器，即便缓存的hash认证失败用户必须使用明文密码，也不会把直接的发送密码，而是经过计算把密码经过计算之后再进行使用，这种模式使用smb的服务器认证基本都是会失败的。

局限性

受管理员模式的初衷是为了保护远程服务器桌面服务端，当服务器被攻陷的时候，明文密码不会被获取到，但是这个保护不是针对PTH，效果也非常的有限。

实际上受限管理员模式的本身就会增加新的攻击路径，即以PTH的方式向远程管理服务其发其认证，也就是说再实际运用中我们可以使用mimikatz来启动mstsc，使用受限制管理员模式来无明文登入，也可以使用其他的hash来认证。

安全用户组

Protected Users

受保护用户是一个新的域全局安全组，对于该组的成员，Windows 8.1设备或Windows Server 2012 R2主机不会缓存受保护用户不支持的凭据。如果这些组的成员登录到运行早于Windows 8.1的Windows版本的设备，则该组的成员没有其他保护。

登录到Windows 8.1设备和Windows Server 2012 R2主机的受保护用户组的成员不能再使用：

  * 默认凭据委派（CredSSP） - 即使启用了“ 允许委派默认凭据”策略，也不会缓存纯文本凭据
  * Windows摘要 - 即使启用明文凭据也不会进行缓存
  * NTLM - NTOWF未缓存
  * Kerberos长期密钥 - Kerberos票证授予票证（TGT）在登录时获取，无法自动重新获取
  * 离线登录 - 未创建缓存的登录验证程序

如果域功能级别是Windows Server 2012 R2，则该组的成员不能再：

  * 使用NTLM身份验证进行身份验证
  * 在Kerberos预身份验证中使用数据加密标准（DES）或RC4密码套件
  * 通过使用无约束或约束委派来委派
  * 更新用户票证（TGT）超过最初的4小时生命周期
