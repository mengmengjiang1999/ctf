跟进transformValue(value)

protected Object transformValue(Object object) {
    if (valueTransformer == null) {
        return object;
    }
    return valueTransformer.transform(object);

在return valueTransformer.transform(object);中调用了transform方法，

valueTransformer是之前定义的transformerChain，valueTransformer.transform因而这个方法可以调用transformerChain的transform方法，transform方法如下

public Object transform(Object object) {
    for (int i = 0; i < iTransformers.length; i++) {
        object = iTransformers[i].transform(object); // 链式调用transform方法
    }
    return object;
}


我们传入的第一个参数是ConstantTransformer，对应的transform方法为

public Object transform(Object input) {

关于poc的细节：

为什么要有fakeTransformers？

因为在本地生成poc链的时候，会在expMap.put(tme, "valuevalue");处执行rce，所以先随便传一个无害的Transformsformers，然后在利用反射修改iTransformers的值为有害的transformers

为什么要remove掉keykey


具体是什么影响，跟进一下就可以了

public Object get(Object key) {
        // create value for key if key is not currently in the map
        if (map.containsKey(key) == false) {

2013年，由于老版的CommonsCollections有架构上的问题，apache推出了全新的jar包CommonsCollections4，两个jar包互不干扰，pom中可以同时添加

PriorityQueue是一个队列排序函数，最后会通过compare比较元素大小

private void siftDownUsingComparator(int k, E x) {
    int half = size >>> 1;
    while (k < half) {
    int child = (k << 1) + 1;
    Object c = queue[child];
    int right = child + 1;
    if (right < size &&
    comparator.compare((E) c, (E) queue[right]) > 0)// compare比较
    c = queue[child = right];
    if (comparator.compare(x, (E) c) <= 0)
    break;
    queue[k] = c;
    k = child;


如果comparator为TransformingComparator ，那么就会执行rce，因为TransformingComparator.compare()内执行了transform方法
