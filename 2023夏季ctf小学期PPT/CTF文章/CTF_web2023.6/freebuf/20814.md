意识与认知

您不必纠结靶机是假的，实际不是这种情况。您需要观察，具体知识点。

重要的事情：【知识点】【知识点】【知识点】与【测试方法】【测试方法】【测试方法】。说三遍。

靶机的构造通常基于单机部署。它不是假，而是没有引入后续阶段性的练习对象。比如XSS漏洞场景，您将不会遇到CDN，集群，waf，过滤器，EDR，蜜罐，威胁狩猎平台，HIDS/NIDS等。

后续场景也不用担心，您可以寻找具体实验室，针对性练习。步子不要跨得那么大，扯到什么就不好了。。

您肯定会思考，现在的渗透测试那都是打点很难的，学这些基础有什么用？有用，因为您忘记思考SDLC安全开发生命周期了，在开发初步提交源码与部署场景进行动静态扫描之后，您需要依赖这些基础性的安全测试方法来检查扫描器报告的真伪性，以及各种逻辑缺陷的验证保障。运用基础性安全测试方法在公司内部让SDLC更具有价值性。

Crypto Basics 加密学基础场景

base64编码

总而言之，它旨在解决网络设备以及缺陷应用的数据交换问题。一些网络设备或者E-mail无法发送Unicode编码，只能发送ASCII码，base64编码应此需求而生。将所有类型的字节转换为ASCII码范围的字节技术。这能更轻松的传二进制数据，比如密钥，图片等。编码是可逆的，相当于明文传输。

对称与非对称加密

HTTPS 同时使用对称和非对称密钥

1.浏览器访问网站，获取网站证书。

2.在操作系统与浏览器中匹配证书是否认证。得到证书公钥。

3.浏览器使用公钥做对称加密。服务器自己也有此公钥，来解密。

4.浏览器与服务器使用对称加密的公钥来交换非对称加密中的公钥。

您可以将其翻译成密钥库与信任库，它们讲得是同一个事情：里面通常放着证书，因此仅有公钥和证书颁发者信息。

基于文件的密钥库

这个很好理解，存储在文件系统中。

基于数据库的密钥库

存于数据库中。

基于硬件的密钥库

通常用于存储私钥的高端设备安全环境，从它里面弄出副本什么的来利用就不要想了。

基于网站证书的证书颁发机构也会为您创建私钥，但是存于哪得求证于不同的此类组织。

也有人将这种创建私钥情况，定义为非私钥。但无论他们如何定义，您都应该将私钥至于密钥库中秘密保存，使用公钥或者证书来向密钥库发起请求。

基于操作系统、浏览器和其他应用程序中的托管密钥库

访问网站，浏览器显示证书正常时，是因为它将网站的证书和本地的密钥库做了匹配。 我们知道，凡是证书就会存在撤销或删除或过期。那么在更新与安装浏览器时，这些密钥库的变化也默认跟着一起同步更新。

不仅是浏览器维护受信任的证书颁发机构的列表，操作系统也这样做。

就连 Java runtime（这里不深究是解释器还是编译器，同等理解为解析器）也有自己的列表，保存在 cacerts 文件中。操作系统和 Java JRE 的更新也会使得此列表（CA证书列表）保持最新。

使用 DNS CAA 记录，检查网站证书

DNS记录CAA，被视为一个扩展功能性来检测网站证书

基于公司的流量劫持

一些公司检查所有或大部分互联网流量。您认为您有一个端到端的安全连接。打开浏览器并使用谷歌搜索， 浏览器将使用 https 并转到 google 站点。但是，如果您检查证书，会注意到它是您公司的根 CA 颁发的！

加密的免费证书颁发组织 【Let’s encrypt】

https://letsencrypt.org/

Let's encrypt 是一个免费、自动化和开放的证书颁发机构。 它允许您为您的网站创建有效的证书。 通过遵循并实施某种协议，您的身份将被检查并颁发证书。证书是免费的，这样做是为了促进授权证书的使用并减少互联网上自签名证书的使用。有效期为 90 天，需要自动续订。

与购买证书的对比情况自己测试。

例如路由器中的默认用户名/密码、密钥库的默认密码、默认未加密模式等
