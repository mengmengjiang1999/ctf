祥云杯2021之just_guess解题Writeup
2021-09-07 02:29:38

在祥云杯线上赛中，有幸成为唯一解出Misc题目just_guess的队伍。想着写篇wp分享一下，拖着拖着半个月过去了，希望它还留有余温:)

题目概况

题目描述：

猜就完事了

function pow(bytes memory calcStr) public onlyPlayer returns(bool);

附件 https://pan.baidu.com/s/106s6j1U1xxFKakQ6OUDI0Q 提取码（GAME）

以及一个已经下线了的端口。

题目描述中给了一个明显是solidity的函数。本以为这是一道区块链的题目，可谁能想到附件竟然是一个so呢？实际上，本题考查的范围及其广(tao)泛(wa)，除了区块链还涉及了re、crypto、pwn。作为一个会做区块链web手表示非常尴尬，全程抱紧队友大腿。

如果你想要复现本题，只需要在ubuntu 1804的python3.6上运行以下两行即可。（题目实际部署还有一些try except，区别不大.jpg）

import guess
guess.main()


黑盒捣鼓

nc连上做proof of work，然后问我们要了infura的id和一个私钥。随便生成私钥提交，告知Address must end in FFF。再生成符合要求的地址，又告知余额不足。这里一开始在ropsten上面转了不少eth都没用，后来grep了一下guess.so才发现是rinkeby。那么提交一个有余额的私钥之后进入了菜单：

1. Info
2. Training
3. Buy Ticket
4. Capture Flag


直接选4发现因为没有ticket不让进，选3需要输入购买数量，但是又会代币余额不足。

去etherscan看了一下，发现服务器使用我给的FFF的账户调用了0xb80DbF48415E8f194fc072648e0b78CD9D77998E的register()。

因为pow太慢，每个私钥又只给用一次，我选择切换到本地进行测试。

本地测试

IDA打开发现一堆_Py开头的函数，毫无疑问这是一个python的模块。（一开始我以为这是一个手撸的玩意儿，后来才意识到其实是Cython。）在ubuntu下面import guess，还得到了温馨提醒compiletime version 3.6。缺少web3依赖，装就完事儿。

看一下guess里有什么东西

再试一试调用函数，其实能得到很多信息：

  * 调用guess.main()就是远程的环境

  * 菜单4个选项对应guess.Info、guess.Training、guess.Buy、guess.Capture

  * 使用CDLL加载了libc

  * guess.Training是一个猜数游戏，猜8个emoji，猜错了会告知正确答案

  * 赋值guess.ticket_time = 1之后可以调用guess.Capture了，也是猜8个emoji，但是现在猜不对

  * guess.getRandNums的返回值就是8个emoji，可以料想上面两个函数都使用了它。

  * 鉴于合约abi里只有register()与buyTicket(uint256)，刚好对应guess.Buy的行为。

来看看合约

etherscan自带的反编译就够了，看buyTicket确实需要代币。有空投函数，但是允许的空投次数为0，所以合约的历史交易中能看到所有airdrop都fail了。

还记得题目描述里的function pow(bytes memory calcStr) public onlyPlayer returns(bool);吗？这个函数比较复杂，但是除了空投函数也只有它可能会增加余额了。静下来看看，结合反编译、动态调试、以及函数名的提示，甚至是参考其他队伍的交易，可以发现这个函数的功能是：如果sha3(msg.sender+calcStr)最高8位是0，就增加30000代币，可以买3张ticket。calcStr不能重复使用。

快乐猜数

现在我们能够合法进入guess.Capture了，不管怎么说需要想办法把数字猜对。因为题目加载了libc，本能想到是不是用了srand和rand，然而在guess.so里却并没有这两个函数的字符串。

从这里开始，我想到了魔改python library。如果用了libc的函数，会调用CDLL.__getattr__，我加了句print，但是在生成emoji时并没有任何打印，说明emoji应该还是用的random。guess里面使用了randint、choice、getrandbits三个随机函数，我逐一尝试魔改，最终发现随机数依赖getrandbits：

于是我再打印出getrandbits的参数，发现每次调用guess.getRandNums()会调用24次getrandbits(1)。因为一共有8种emoji，刚好3bit可以决定一个emoji，24bit可以决定8个。上图中所有bit均为1，0b111=7，刚好是对应guess.emoji[7]的猫猫。再多次尝试，可以确认顺序都是对应的。

getrandbit(1)

现在问题转化为了怎么在可以无限次getrandbit(1)的情况下预测/还原得到mersenne twister状态的密码学题目。如果是getrandbit(32)倒还有工具，getrandbit(1)可真把我难住了。经过队里密码学师傅的指点，这里和pwnhub的一道CoinFlip2如出一辙，抄抄代码：https://badmonkey.site/archives/mt19937.html 。顺带一提，文中保存/读取矩阵的方式过于粗暴，直接将一个19968*19968的01矩阵用字符串形式保存，数据量高达700M，换用pickle的话，又快又小。

最后一步

事实上，在想到hook random的时候，我就已经能够正确答对guess.Capture的问题，但是意料之外，答对后并没有flag，取而代之的是要输入我们名字。这时hook的CDLL.__getattr__起了反应，显示加载了libc.printf，很快确认本题的最后是一个格式化字符串的利用。但是堆上的字符串又把我整不会了，最多就是leak一下栈确认是1604，然后只能求助队里的pwn爷爷。为了方便他专注利用和调试，我把hook后的脚本作为server给了他，另外告诉他不用装web3，只要新建web3.py写Web3=1就行了，加载起来还快很多。

import guess
guess.getrandbits = lambda x:1
guess.ticket_time = 9999
for i in range(3):
    guess.Capture()


这里应该对于pwn选手都是常规操作，一次leak加上一次指针改指针覆盖one gadget，我也就不班门弄斧了。

流程总结

到这里每一步都做好了，还需要再串一下：

 1. 生成FFF结尾的地址，转一点钱，提交给题目

 2. 题目会先调用register，我们调用pow得到代币，回到题目买3个ticket

 3. Train 832次，拿到832*24=19968个bit，还原state

 4. 预测接下来的两组随机数，利用两次格式化字符串

 5. getshell

心得体会

首先这道题真的非常套娃，尤其是Cython根本不是给人看的。事实上我也硬着头皮翻了很久ida，最后才想到直接hook library去猜测题目行为的操作。另外我估计应该不太会有人能独立解出本题（至少在比赛期间没有），这就需要和其他方向的队友相互配合。如果能啥都懂一些，就可以比较准确精炼地提取出题目想要考察的点，比如密码学考只有MSB的MT还原，pwn考堆fmtstr，把这些信息交给队友就很高效。
