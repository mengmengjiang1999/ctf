当今社会物联网设备已经逐步渗透到人们生产生活的方方面面，为人们及时了解自己周围环境以及辅助日常工作带来便利。但随着互联紧密度的增高，物联网设备的安全性问题也逐渐影响到人们的正常生活，甚至生命安全，物联网设备安全不容小觑。

以下为近日的物联网安全新闻内容。

研究人员将披露两个影响 AMD 处理器的 SEV 漏洞

与竞争对手 Intel 相比，AMD 处理器在安全性方面表现得相对出色。但在偶尔的情况下，研究人员还是会发现一些容易被利用的新攻击。TechPowerUp 指出，在即将于 5 月 27 日举办的第 15 届 IEEE WOOT’21 技术研讨会上，将有两篇专门针对 AMD 安全加密虚拟化（SEV）漏洞的新文章等待发表。

来自德国慕尼黑工业大学和吕贝克大学的研究人员，将分别披露有关 CVE-2020-12967 和 CVE-2021-26311 安全漏洞的论文。

虽然尚不清楚 AMD SEV 新漏洞的详情，但我们不难猜测有哪些处理器受到了影响。由于 SEV 是一项企业级的安全特性，因此 AMD 的霄龙（EPYC）服务器处理器将首当其冲。

AMD 表示，相关漏洞影响所有 EPYC 嵌入式 CPU，以及 1、2、3 代霄龙处理器。对于后者，该公司已经提供了专门的 SEV-SNP 缓解功能。

至于其它产品线，官方还是建议客户尽量在各个方面都遵从最佳的安全实践，以避免受到潜在的 SEV-SNP 攻击的影响。

严重漏洞可能允许攻击者破坏医院的气动管道系统

Armis 研究人员在 Swisslog Healthcare 的 Translogic 气动管系统中发现了关键漏洞，该系统在全球 3,000 多家医院（包括北美 80% 的医院）的患者护理中发挥着至关重要的作用。

Swisslog PTS 漏洞

Swisslog PTS 系统通过气动管网络在整个医院内自动传输实验室标本、血液制品、实验室测试和药物。该系统还与其他医院系统（例如，访问控制系统）集成。

“现代 PTS 系统是 IP 连接的，并提供先进的功能，但是，尽管这些系统很流行，并且医院依赖其提供护理的可用性，但从未彻底分析或研究过这些系统的安全性，”Armis研究人员指出。

他们自己的研究发现了九个影响 Translogic Nexus 控制面板的漏洞（他们统称为 PwnedPiper），该控制面板为 Translogic 气动管系统站的所有当前型号提供动力。

其中包括用户和 root 帐户的硬编码密码、可用于获得 root 访问权限的提权漏洞、可用于实现 RCE 和挂载 DoS 攻击的内存损坏漏洞、单独的 DoS 漏洞以及允许未加密的设计缺陷， Nexus 控制面板上未经身份验证和未签名的固件更新。

研究人员表示：“发现的漏洞中最严重的漏洞 (CVE-2021-37160) 可以让攻击者通过不安全的固件升级程序在受感染的 PTS 站上保持持久性，从而使他能够将站扣为人质，直到支付赎金为止，”研究人员注意到。

虽然这种攻击最终可以通过对所有受感染站点进行手动固件升级来修复，但这样的过程将需要相当多的时间和精力。医院不一定有任何应急措施来处理 PTS 系统的长期关闭，这最终可能会转化为对患者护理的伤害。”

其他漏洞可能允许攻击者操纵系统来损坏通过它运输的敏感物品，将它们重定向到错误的站点，访问员工记录和他们的 RFID 凭证，向系统的维护人员触发错误警报等等。

据研究人员称，所有漏洞都可以通过发送未经身份验证的网络数据包来触发。此外，攻击成功不需要用户交互。

大流行期间物联网恶意软件攻击增加了 700%

Zscaler 发布了一项研究，调查了企业被迫迁移到远程工作环境期间留在企业网络上的物联网设备的状态。

该报告分析了在 2020 年 12 月的两周内阻止的超过 5.75 亿次设备交易和 300,000 次特定于物联网的恶意软件攻击——与大流行前的调查结果相比增加了 700%。这些攻击针对 553 种不同类型的设备，包括打印机、数字标牌和智能电视，所有这些设备都连接到企业 IT 网络并与之通信，而许多员工在 COVID-19 大流行期间远程工作。

研究团队确定了最脆弱的物联网设备、最常见的攻击来源和目的地，以及负责大部分恶意流量的恶意软件家族，以更好地帮助企业保护其宝贵数据。

“一年多来，由于员工在COVID-19大流行期间继续远程工作，大多数公司办公室大多被废弃。然而，我们的服务团队注意到，尽管缺乏员工，企业网络仍然因物联网活动而嗡嗡作响，” Zscaler 的CISO Deepen Desai说。

“连接到企业网络的物联网设备的数量和种类非常庞大，包括从音乐灯到 IP 摄像机的所有内容。我们的团队发现，这些设备中有 76% 仍在未加密的纯文本通道上进行通信，这意味着大多数物联网交易对业务构成了巨大风险。”在超过 50 亿的物联网设备交易中，确定了来自 212 家制造商的 553 种不同设备，其中 65% 分为三类：机顶盒（29%）、智能电视（20%）和智能手表（15%） ）。

以 CVE-2020-3580 PoC 漏洞为目标的思科安全设备

攻击者和漏洞猎人正在利用 CVE-2020-3580 漏洞来破坏运行 Cisco ASA 或 FTD 软件的易受攻击的安全设备。

主动攻击显然是在Positive Technologies研究人员上周四通过 Twitter 共享概念验证 (PoC) 漏洞代码之后开始的。

关于 CVE-2020-3580

思科于 2020 年 10 月修补了 CVE-2020-3580，以及三个额外的预身份验证跨站点脚本 (XSS) 缺陷：CVE-2020-3581、CVE-2020-3582 和 CVE-2020-3583。

2021 年 4 月，思科发布了新的软件更新，因为 CVE-2020-3581 的修复不完整。

所有四个漏洞的来源都是受影响设备的 Web 服务界面对用户提供的输入的验证不足，并且可能被设法欺骗或说服界面用户单击精心制作的链接的攻击者利用。

这些漏洞被认为是中等严重性，即使它们可以在没有身份验证的情况下远程利用。这种中等严重性评级的原因有几个：利用需要用户交互，并且最终可能“仅”导致在界面上下文中执行任意脚本代码，或者为攻击者提供对敏感的、基于浏览器的信息的访问。

使用 CVE-2020-3580 PoC 漏洞的主动攻击

自 CVE-2020-3580 修复以来已经过去了九个月，Positive Technologies 的研究人员显然相信有足够多的组织已经实施了安全更新，并且发布 PoC 漏洞利用代码不会造成广泛的破坏。

安全研究人员曝光多款电动汽车充电器与充电网络存在的隐患

英国网络安全公司 Pen Test Partners，刚刚曝光了在六个家用电动汽车充电品牌、以及一个大型公共 EV 充电网络 API 中的几个安全漏洞。随着 IoT 即将在人们的家庭与车辆中无处不在，本次调查给出了物联网设备监管不力的最新实例，且涉及 Project EV、Wallbox、EVBox、EO Charging 的 EO Hub / EO mini pro 2、Rolec、以及 Hypervolt 这个六个不同的 EV 充电品牌。

问题还涉及 Chargepoint 公共充电网络的 API（资料图 via Mitsubishi）

安全研究人员 Vangelis Stykas 指出，这些漏洞或允许黑客劫持用户账户、阻碍充电、甚至将其中一款充电器编程入侵用户家庭网络的“后门”。

若公共充电网络遭到黑客攻击，还可能导致电费窃取、以及通过开启 / 关闭充电器而造成电网波动。
